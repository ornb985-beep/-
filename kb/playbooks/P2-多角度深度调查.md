# P2 · 多角度深度调查

> 决定准确率的不是查了几次，是**查了几个角度**、**几个真独立的源**、
> 以及**知不知道什么时候该停**。

## 停止条件

| 信号 | 动作 |
|---|---|
| 连续 3 次查询边际产出 <5% | 饱和，可以停 [K-ANA-023] |
| 某角度多次零产出 | 该字段不在公开渠道，**换渠道或接受盲区**，别再查 [K-ANA-024] |
| 有效独立源 <2 | 标「待核实」，不得作为结论 [K-EVD-004] |

---

## 步骤

### 1 · 生成八角度矩阵

```
demand_size    市场规模与增速      supply_entry   企业新增注册
supply_exit    注销吊销闭店退出    concentration  CR5 / 市占率
capital        融资数量与金额      profitability  毛利率/价格战/亏损
channel        门店数、渠道结构    regulation     政策、监管事件
```

**刻意穷举而非精选** [K-ANA-021]。缺哪个角度，对应字段就永远是空的，
而多查一次的成本远低于一个永久性的数据缺口。

已有的字段不重复查 [K-ANA-025]。

### 2 · 并行执行

八个角度互不依赖，**属于可并行任务**（实测 +80.8%），
不受铁律 2 的多智能体限制 [K-ORC-002]。
挡的是「五个 agent 轮流推理同一条结论」，那是 −39~70% 那一类。

### 3 · 折算信源独立性

```
名义来源 3 个 → 有效独立源 2 个（转引放大 1.5×）
  ⚠️ 2 个来源同溯至「iimedia」：新浪财经、网易新闻
```

**十篇引用同一家的报道，独立性是 1 不是 10** [K-ANA-022]。
没有这个折算，多方查询只会**放大同一个错误**并让它看起来被多方确认了。

### 4 · 判定饱和度

```
#1 [demand_size ] +2 条（边际 100%）
#2 [supply_entry] +4 条（边际 67%）
#3 [capital     ] +0 条（边际 0%）
⬜ 尚未饱和，继续查还能拿到新事实
🔴 零产出角度：capital
```

零产出角度那条判定**是整套方法里最省钱的一条** [K-ANA-024]：
它把「再查查看」和「这数据根本不存在」区分开。

### 5 · 交叉求证

验证 agent **不能看到原答案** [K-ORC-003]。
同上下文自查等于让犯错者当裁判。

冲突**由确定性代码裁决，不由模型裁决** [K-MET-007] [K-MET-010]。

---

## 实测效果

同一品类（盲盒/潮玩）：**1 次查询 → 2 条事实；7 次多角度 → 17 条事实**
[K-ANA-021]。供给侧和集中度数据一直在互联网上，缺的是查询角度。

即时零售 7 次查询产出 2、4、3、0、2、3、3 —— **未饱和**，
说明边际价值仍为正 [K-ANA-023]。
