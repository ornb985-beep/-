# MoneyLoop · 工程交接包

**这一份是给接手工程化的那个 AI 看的。** 把整份甩给它，它应该能直接开工。

---

# 一、这是什么（一句话，其余都是它的展开）

> **任何一个想法输入，都能快速得到一个诚实的答案——
> 要么变成赚钱闭环，要么在你花大钱之前告诉你它不行。**

**功能会变，这句话不会。** 判断一个新功能该不该做，回来问这句话。

## 给谁用

**生意人，不是程序员。** 判断力强、审美好、知道什么能赚钱，
但不懂技术名词、不会看代码。

> **他的全部工作量 ＝ 回答一个问题，或者做一道选择题。**

界面上不许出现任何商业术语或技术术语。
**唯一的判断标准：他看完能不能立刻做一个决定。**

---

# 二、凭什么是它（这三条不许动）

任何工程决定违反这三条，就是做错了，不管技术上多优雅。

### 1. 它会拦住自己

六条「不许」**是在代码里硬查的**，不是写在提示词里就完了：

| | 不许什么 | 挡的是哪种自欺 |
|---|---|---|
| 1 | 不许编 | 「业内普遍认为」——凭印象说出来、听着很专业的话 |
| 2 | 不许把猜测当事实 | 一份读起来完美流畅、看不出哪句是猜的文档 |
| 3 | 不许问他答不上来的问题 | 「你的标准是什么」——把该它干的活推给他 |
| 4 | 不许只算一侧的钱 | 算了半天成本，从没问过谁掏钱 |
| 5 | 不许拿「我们更好」当护城河 | 功能更好／效率更高／更有品味 |
| 6 | **不许说通过了但其实没验** | 屏幕上全是 ✓，底下什么都没发生 |

**第 6 条的落地方式**：每一步跑完，代码检查该产出的文件在不在，
不在就记「没做成」，**不往下走**。

### 2. 标准是产出，不是输入

「什么算好」不是一开始定完就锁死的输入，**是随证据不断修订的产出**。

每转一圈要同时更新两样：**做出来的那个东西**，和**「什么算好」的定义**。

> **只更新前者的系统，会非常高效地跑向一个错的地方。**

落地方式：`docs/03-什么算好.md` 末尾有一张「标准修订记录」表，
**代码会数它有几行**——一轮下来没新增，就判定这一轮不算跑完整。

### 3. 每个角色是独立智能体

一个角色有三样自己的东西，**换任何一样都不影响别人**：

| | 在哪 |
|---|---|
| 会话 | `.loop/roles/<名字>.session` |
| 工作目录 | `work/<名字>/` |
| **AI 接口** | `.loop/roles/<名字>.env`（用谁家的 AI、哪个模型、花谁的钱） |

调用某个角色时，他的 `.env` 在**子 shell** 里生效，跑完就没了。

>

```

    │
    ├─ 1 听懂    拆他的话、分轻重、挖真痛点 → 一次只问一个问题

    │            ./loop.sh 照镜子       （可选：只用他自己的话当镜子）
    │
    ├─ 2 目标    给谁/谁掏钱/要赚多少/倒推算账
    │            ./loop.sh 论证         （十个专家：4个联网查 → 6个看数据判）
    │
    ├─ 蓝图循环  ./loop.sh 蓝图 → 改 "A" → …→ 定了
    │            ./loop.sh 启蒙         （四位大师，细到按钮）
    │            ./loop.sh 审美         （给他看真东西，反推他的审美标准）
    │
    ├─ 3~9 步    巨人 → 独特★ → 标准★ → 需求★ → 补课 → 选型★ → 计划
    │            ./loop.sh go           （★ 是要他拍板的）
    │
    ├─ 10 开做   ./loop.sh go           做→检查→修，循环到过关
    │            ./loop.sh 手册         （一步一步 + 所有要花钱的点）
    │
    └─ 上线运营  ./loop.sh 上线         三道闸，一道不过不许上
                 ./loop.sh 止损 "…"     他只需定这个 + 投入多少
                 ./loop.sh 记账 收 500  真金白银

                 ./loop.sh 看板         仪表盘
```

**横向随时能用**：`hire` `ask` `会诊` `派活` `验收` `台账` `接口` `cost`
`budget` `judge` `correct` `explain` `today` `back` `close` `reset`

## 组织结构

```
你 → CEO（唯一拍板）
      ├─ 左：参谋层（只出意见，不指挥执行）
      │    常驻10 · 大师7 · 镜子1 · 审美1 · 蒸馏N
```

**参谋层和执行层之间没有线**，中间必须过 CEO——
防止「一群 AI 互相附和，产出最低公约数」。

# 四、已知的坑（这个项目栽过的，别再踩）

**这一节是这份交接包里最值钱的部分。**

| 坑 | 后果 | 现在怎么防的 |
|---|---|---|
| `grep` 没匹配到返回 1，配 `set -euo pipefail` 直接杀死脚本 | **整条命令静默死掉**，栽过 5 次 | 所有 `x="$(grep ...)"` 都加 `\|\| true` |
| `strip_frontmatter` 用 `sed q`，对没有 frontmatter 的文件只输出第一行 | **每个角色只收到自己定义的第一行**，身份和问题全丢，而它照样会输出东西 | 改成先判断首行 |
| `[:：]` 方括号拆多字节全角冒号 | 匹配静默失效 | 一律写成 `(:\|：)` |
| `case` 分支别名重复（`board`、`ledger`） | 后面那条永远走不到 | 每加一条 dispatch 先 grep 一遍 |
| 九步编号手写在 20 个文件里 | `框架库.md` 里「第4步要做什么」错了很久没人发现 | 编号改成从数组位置**算出来** |
| 同一份清单抄在三处（lib.sh/状态.py/看板.py） | 加第0步时看板漏了，进度条少一格且看不出来 | 加了逐项比对的漂移测试 |

**共同点**：**全部是"看起来正常但其实没做"**，而不是报错。
所以这个项目的测试**不测"命令有没有报错"，测"它到底做了什么"**——
比如接口测试用一个假的 `claude` 二进制，检查它**真正收到的环境变量**。

## 核心一：真人级团队，自动分析判断

### 现在的实情（我量过，不是估的）

29 个角色，**只有 2 个指定了不同模型**。也就是说：

> **29 个"专家"跑在同一个脑子上，是一个模型分饰 29 角。**

后果非常具体：**十个专家会比真正独立的十个更一致**——
因为他们本来就是同一个模型，看同一份材料，用同一套先验。

**而一致是可疑的。** 十个人看同一件事全都同意，
通常说明他们在顺着同一个假设说话，**而那个假设可能就是错的。**

还有第二个缺口：**现在专家要人敲命令才来**（`./loop.sh 论证`）。
人不敲，它就不分析。**那不叫团队，叫一堆待命的模板。**

### 要做成什么样

**三层，缺一层都不算做到。**

**（1）真的独立——不同角色接不同的模型**

地基已经有了：每个角色有自己的 `.loop/roles/<名字>.env`，
支持独立的 `ANTHROPIC_BASE_URL` / 模型 / key，
调用时在子 shell 里生效，**互不污染**（这条有测试守着）。

**缺的是把它用起来。** 最低要求：

| 角色 | 必须跟别人不同模型 | 为什么 |
|---|---|---|
| **风控**（反方辩护人） | **必须** | 同一个模型很难真的反驳自己刚说过的话 |
| 行研／增长／竞品（查证方） | 至少跟判断方不同 | 查的人和判的人不该是同一个脑子 |
| CEO（裁决） | 用最强的 | 判断力省不得 |

**（2）自动召集——不用人敲命令**

系统每一步跑完，**自己判断要不要开会**。触发条件必须是**可数的**，
不许靠感觉：

```
承重条件里 ≥2 条还是 [猜测]        → 自动召集查证方
可行性 < 90%                       → 自动召集相关专家补查
风控提了反对，但没人回应            → 自动召集裁决
连续 3 轮「标准修订记录」没新增      → 自动召集复盘（标准可能已经僵死）
```

**（3）分歧要被量出来，不是靠感觉**

系统必须统计并报出：

```
本轮 10 个专家，在 8 条承重条件上：
  完全一致：6 条   ← 【这个数字太高的时候要报警】
  有分歧：  2 条   ← 分歧在哪、谁跟谁、CEO 判了谁
  无人回应：0 条
```

> **"全票通过"应该触发警报，不是让人放心。**

### 怎么验收（一条都不许少）

- [ ] 至少 3 个角色跑在**不同的模型/接口**上，`./loop.sh 接口` 能看出来
- [ ] **拿同一个议题跑两次**：一次全用同一个模型，一次用混合模型，
      **分歧数必须明显不同**——不同就证明"独立"是真的
- [ ] 不敲任何命令，跑完一步之后系统**自己**报出
      「这几条是承重的猜测，我已经召集了 X/Y/Z 去验」
- [ ] 分歧率被统计出来并显示在看板上；**全票通过时有明显警告**

## 核心二：自动操作运营

### 现在的实情

**这套东西没有手。**

| 要什么 | 现在有没有 |
|---|---|
| 会自己醒（定时器/触发器） | **零** |
| 能对外动作（发内容、回消息、读平台后台） | **零** |
| 能看见真实结果（自动拉数据回来） | **零**，账本是人一笔一笔敲的 |

它现在做的全部事情是：**写文档说该做什么。然后等你去做。**

**那不是运营，那是给你布置作业。**

### 要做成什么样：「备好，等你点头」

**红线不许破**（花你的钱／对外发东西／不可逆操作，永远不许自动），
所以自动运营唯一诚实的做法是：

```
系统自己跑到最后一步 → 把动作整个备好 → 打包成一个「待批」
        ↓
   你看一眼（手机上就能看）
        ↓
   一键放行 / 改一下再放行 / 否掉
        ↓
   放行之后自动执行 → 结果自动回流到账本和看板
```

**关键在"备好"两个字**：不是问你"要不要发个内容？"，
而是**内容已经写好、平台选好、时间定好、配图配好，你只需要看一眼说"发"。**

**这就是「他的全部工作量 ＝ 回答一个问题或做一道选择题」在运营期的样子。**

### 授权分三档（复用 CEO 已有的绿黄红，不新造）

`.claude/commands/ceo.md` 里已经写好了这套，直接接过来用：

| | 什么事 | 怎么办 |
|---|---|---|
| 🟢 **绿灯** | 小额、可逆、有预设话术的 | **直接做**，事后记一笔 |
| 🟡 **黄灯** | 影响面中等 | **做了报备**，24 小时内他可以撤 |
| 🔴 **红灯** | 花钱／对外发布／删除／不可逆 | **必须事前批准，永不下放** |

**黄灯额度靠记录涨，不靠嘴**——绿灯连续做对 N 次，
某类动作才能从红升黄、从黄升绿。ceo.md 里有具体规则。

### 最少要接哪些手（按性价比排）

| 顺序 | 接什么 | 为什么先做这个 |
|---|---|---|
| 1 | **定时器**（能自己醒） | **没有这个，别的都白搭**——人不敲命令它就不动 |
| 2 | **把真实数据拉回来**（平台后台/表格/邮件） | 没有真数据，日报和止损线全是编的 |
| 3 | **内容准备 ＋ 待批队列** | 最高频、最耗人、而且可逆 |
| 4 | 客服回复（先只做"备好草稿"） | 有话术模板，风险低 |
| 5 | 投放/付费（**永远红灯**） | 只备方案，永不自动执行 |

### 怎么验收

- [ ] 设一个定时任务，**人离开 24 小时**，回来时系统自己完成了一轮
      「拉数据 → 分析 → 备好动作 → 排进待批」
- [ ] 待批队列里每一条都**具体到能直接执行**（内容全文、发哪儿、几点），
      不是"建议发一条内容"
- [ ] 一键放行之后**动作真的执行了**，结果**自动回流**到账本和看板——
      不用人再敲一次 `记账`
- [ ] 红灯动作**在任何情况下都拦得住**：写一个测试，
      让系统尝试执行一个红灯动作，**必须被拒绝并留下记录**
- [ ] 日报里的每个数字**能追到来源**，不是它自己算的

## 这两件的关系

**核心一是"判断得准"，核心二是"手脚快"。**

**只有二没有一** → 一台高效执行错误决策的机器，**而且执行得越快死得越快**
**只有一没有二** → 一个分析得很对但什么都不做的顾问，**跟现在一样**

**两个都要，而且核心一优先**——先保证判断是真独立的，再给它手。

# 六、为了做到那两件，先要有的地基

**这四件不是"也很重要"，是"不做这四件，上面那两件一定会出事故"。**

| | 做什么 | 不做会怎样 |
|---|---|---|
| 1 | **补测试**（覆盖到的命令数远少于 53 条——跑 `bash scripts/check.sh` 看当场有几套，这个数天天变，按第 3 条不写死） | 自动运营出错时**没人知道**，而且是在真实业务上出错 |
| 2 | **CI**（每次改动自动跑 `check.sh`） | 靠人记得跑 = 迟早不跑 |
| 3 | **打包**（现在只能 clone） | 装不上就没有第二个用户 |
| 4 | **错误处理说人话** | 自动运营半夜出错，他起来看到一堆报错，**不知道该干什么** |

**顺序建议**：地基 1、2 先做（几天），然后立刻上核心一，
核心二边做边补 3、4。

**别把地基做完美了再动核心**——那是另一种拖延。

## 每一件的验收标准

1. **测试**：覆盖命令数 4 → ≥20，且**每套都要能测出"看起来对但其实没做"**，
   不是只测有没有报错
2. **CI**：**推一个故意写坏的 commit，CI 必须变红**
3. **打包**：干净机器上一条命令装完能跑 `./loop.sh start "test"`
4. **错误处理**：挑 5 条命令制造失败，输出必须让一个不懂技术的人
   知道**下一步该干什么**

# 七、工程纪律（这几条请严格照做）

1. **一次只做一件事。** 「顺便把文档也更新一下」是灾难的开始
2. **只改点名的文件。** 发现别处该改，**写下来告诉我，别动手**
3. **动手前先说三样**：怎么做（三行白话）／**我怎么验证它真成了**（具体到命令和该看到什么）／最可能出问题的地方
4. **每次改完跑 `bash scripts/check.sh`，把实际输出贴出来**，不是"应该没问题"
5. **做完汇报四条**：改了哪几个文件 ／ 怎么验的（贴命令和输出）／
   **有没有想做但没做成的** ／ 有没有可能弄坏别的地方
6. **验干完的活，照 `references/验证的规矩.md`。**
   每一条都带着逼出它的那件真事——想删哪条，先去把它的出处推翻

**第 5 条的第三问最重要。**
一个说"全都做完了，没有问题"的报告，**几乎总是意味着没认真检查**。

# 八、三个必须先定死的边界（接手的人第一轮就会问）

**这三条不写清楚，核心一和核心二都没法动手。**

## 1. 钱：什么算"运行成本"，什么算"花你的钱"

**红线是「花你的钱永不自动」。但 AI 调用本身就要钱——那这套东西还能自动吗？**

**能，因为这是两种钱，分开管：**

| | 是什么 | 谁管 | 自不自动 |
|---|---|---|---|
| 🟢 **运行成本** | AI 调用费（含调第二家、第三家模型） | **预算闸门**（`./loop.sh budget 50`） | **闸门内全自动**，到顶自动停 |
| 🔴 **生意的钱** | 投放、采购、付供应商、订阅服务 | **必须人批，永不下放** | 每一笔都要点头 |

**分界线只有一条**：**这笔钱花出去，是为了让系统想清楚，还是为了对外产生动作？**

- 为了想清楚（调模型、查资料）→ 运行成本，闸门管
- 为了对外产生动作（投广告、买域名、付服务费）→ 红线，人批

**所以核心一「风控换一家模型」不违反红线**——那是运行成本，
装在预算闸门里，闸门到顶自动停。

**两本账已经是分开记的**：`.loop/账本.tsv` 记生意的钱，
`./loop.sh cost` 记运行成本。**不许合并，不许互相冒充。**

## 2. 它跑在哪（核心二的前置条件）

核心二第一件是"能自己醒"，**那就得有一台一直开着的机器**。三条路，代价差一个数量级：

| | 是什么 | 代价 | 缺点 |
|---|---|---|---|
| **A · 本机** | 就跑在老板自己电脑上，用系统自带的定时任务 | **0** | **电脑关了就停** |
| **B · 一台常开的小机器** | 便宜迷你主机，或最低配云服务器 | 几百块一次性 / 几十块一月 | 要一点点运维 |
| **C · 托管服务** | 我们替所有用户跑 | **数月起步，而且每个用户的 AI 调用成本要先垫** | **这是另一个项目** |

**先做 A**——**A 和 B 的代码是同一套**（都是"系统定时任务 + 跑一条命令"），
**从 A 换到 B 只是换一台机器，不用重写。**
C 现在做等于在没验证的假设上压全部成本。

**「待批」怎么送到他手机上**（按省事排）：

1. **写成文件，同步到网盘或 git** → 手机上打开就能看（**0 成本，今天就能用**）
2. 邮件（一个 SMTP 就够）
3. 微信/飞书机器人推送（要申请接口）

**先做 1。** 后面两个是"更方便"，不是"必需"——
**别让通知渠道拖住核心功能。**

## 3. 交接包里的数字，你必须自己复核

**你说得对，这是应该的。** 按第 6 条「不许说通过了但其实没验」，
**别人屏幕上的 ✓ 不能当已验。**

**第一件事就是复核，而且这也是你的第一份产出**：

```bash
git clone <仓库> && cd <目录>
git checkout claude/project-template-automation-ea9utn

bash scripts/check.sh                              # 号称 5 大项 55 子项全绿，自己看
bash scripts/check.sh 2>&1 | grep -cE '^\s+\[通过\]'   # 号称 55 子项
ls roles-模板/*.md | wc -l                          # 号称 29 个角色
grep -l '^模型：' roles-模板/*.md | wc -l            # 号称只有 2 个指定了不同模型
ls scripts/test-*.sh tests/*.py | wc -l             # 有几套（会随补测试而涨，不是断言）
sed -n '/^main() {/,/^}/p' loop.sh | grep -E '^\s+[a-zA-Z0-9|一-龥-]+\)' | grep -cv help   # 号称 53 条命令（help 不算）
grep -c 'cron\|定时\|schedule\|systemd\|at now' loop.sh   # 号称定时器 0
```

**定义写死：`./loop.sh auto`（也叫 `自动`）不算定时器。**
它是个 while 循环，**要人先敲一次**才开始跑，撞到「预算到顶／轮到你拍板／
卡住了／做完了」就停。**它不会自己醒**——关掉终端这套系统就彻底不动了，
没有任何东西会在明天早上八点把它叫起来。
所以「无人值守」和「会自己醒」是两件事，`auto` 只做到前一件。
**这正是核心二第一项要补的洞。**

**定义写死：`help` 不算一条命令。** 它是"怎么用"的说明，不是一个动作——
数命令那条尺子最后的 `grep -cv help` 就是干这个的。**46 是在这个定义下数出来的。**
不写死这一条，下一个人会把 `help|-h|--help)` 也数进去、数成 47——
这个数字一年内已经烂过一次（45↔46），别让它靠"谁数的"再烂第二次。

（另：旧尺子 `[a-z|一-龥]` 的字符类不含大写、数字和横杠，
一旦以后加了带这些字符的分支就会漏数；新尺子把 `A-Z0-9-` 补进了字符类。）

**对不上的，以你数出来的为准，并告诉我哪条对不上。**
数字错了不丢人，**拿错的数字当真的往下做才丢人。**

# 二、流程：从一段话到能收钱的东西

```
1 听懂★ →  2 目标和算账  →  3 巨人的肩膀  →  4 共性与独特★  →  5 什么算好★
                                                                     ↓
10 自动开做 ← 9 任务清单 ←  8 技术与落地★  ←  7 我不懂的  ←  6 要做什么★
```

**中间随时可以插一步「论证」**：`./loop.sh 论证` ——
十个专家把「这事到底成不成」查一遍，给你一页纸和一个**算出来的**可行性。

**然后画蓝图，一直改到你说「就是它了」**：

```bash
./loop.sh 蓝图        画一版：形态/功能/技术/时间表
./loop.sh 改 "A"      回答它的问题，或者直接说哪儿不对
./loop.sh 定了        对，这就是我要做的 ← 只有你亲口说，才算数
```

蓝图给两版：**默认只给你「人性化那版」**（一句话说清、为什么能成、明天做什么）；
详细版（用户流程／技术路线／时间表／第一周每天做什么）留在文件里，想看再翻。

**它不许自己说「定了」。** 你说"挺好的""行吧"也不算——那是客气，不是拍板。

**定了之后，挑长相、再拿手册开工**：

```bash
./loop.sh 启蒙        四位大师拧出几个方向，细到按钮
./loop.sh 审美        给你看真东西（能打开看的真网站），从你的选择里反推你的审美
./loop.sh 手册        一步一步带你做出来，含所有要花钱的点
```

`启蒙` 是**美学 / 哲学 / 历史人文 / 精神意识**四位大师，一人只管一块：

| 大师 | 只管 | 挂在什么上（不许没出处） |
|---|---|---|
| 美学 | 比例、留白、节奏、颜色 | 具体作品/流派/设计者，带年代 |
| 哲学 | **这东西替用户默认了什么** | 具体的人和他真说过的话 |
| 历史人文 | 这需求以前谁做过、怎么死的 | 具体先例：何时、谁、结果 |
| 精神意识 | **用它那几秒，人心里在发生什么** | 他自己的原话 ＋ 有名字的研究 |

**四个人打架的地方，就是真正的选择点**——四个角度全都一致反而可疑，
通常说明他们在顺着同一个假设说话。

硬要求：**每条判断必须落到一个能做的决定上**。
「要有人文关怀」不算，「删除不弹确认框、改成 5 秒撤销」才算——
**后者能改代码，前者改不了任何东西。**

`审美` **不会问你"喜欢什么风格"**——你答不上来，没人答得上来。
**你看到了能判断，闭着眼描述不出来，这是两回事。**
它给你三个方向，每个挂着 2–3 个你能当场点开看的真东西，
你选完，它把你自己都说不清的那个标准**反推成一句话**给你确认
（比如「宁可少显示一条，也不要让人多点一下」）。
**那句话比三个方向值钱得多——方向是这一次的，标准是往后每一次的。**

`手册` 写给一个**完全不会写代码、也不打算学**的人。合格标准只有一条：
**你照着做，中间不需要问任何人任何问题。**
里面「你干」那一栏只允许出现三种事：**注册／付钱／复制粘贴**。
出现"配置""调试""了解一下"就是不合格——那是我们的活。

所有要花的钱**一次说完**（必须花的／可以先不花的／上架要过几关），
每个数字联网查证带日期。**查不到就写查不到**——
编一个价格出来是这份手册里最贵的一种错。

**★ 是要你拍板的五步。** 划分标准只有一条：
**技术问题它自己定，生意问题必须你定。**

一直敲 `./loop.sh go` 就行，它会自己往下跑，到该你拍板的地方停下来。

## 第1步单独说一下：它得先听懂你

**你说的话和你要的东西，通常不是一回事。**

第1步不做别的，只干一件事：**把你那段话拆开**。

- 哪句是**承重的**（理解反了后面全白做），哪句现在**根本不重要**
- 你说「做个小工具」——那是**形态**，第8步才该定，现在标成不重要
- 你说「我总是忘记…」——**痛点几乎都藏在这种频次词后面**，标成承重
- 承重的那几条往下挖三层：字面要什么 → 为了什么 → 你到底怕什么

挖完它会**问你最多 3 个选择题**（不是问答题，每个选项都具体到能想象出画面）。

```bash
./loop.sh 答 "1A 2C 3 我其实更在意的是…"     # 回答
```

**它没在文档里写下「听懂了」，就不许往下走。**
听懂这件事上装懂，后面八步全建立在一个误解上——**那比多问一轮贵一万倍。**

这个能力也能单独用，不用开项目：

```bash
./loop.sh 听 "任何一段话"      # 只拆一遍给你看，不写文件
```

| 步 | 它干什么 | 产出 |
|---|---|---|
| 1 ★ | **拆解你的原话：分轻重、挖真痛点、问你选择题** | `docs/00-听到的.md` |
| 2 | 接着第1步往下：给谁、谁掏钱、**要赚多少钱、倒推算账** | `docs/00-目标.md` |
| — | **（可选）论证**：十个专家查一遍，给可行性 | `docs/00-论证.md` |
| 3 | 联网查前人做到最好的，带来源和日期 | `docs/01-巨人的肩膀.md` |
| 4 ★ | 共性守什么、独特赌什么 | `docs/02-共性与独特.md` |
| 5 ★ | **不问你标准，给你看 A/B/C，从你的选择里反推标准** | `docs/03-什么算好.md` |
| 6 ★ | 拆成第一版必须有／第二版再说／明确不做 | `docs/04-要做什么.md` |
| 7 | 找出你不知道但会踩的坑，用大白话讲 | `docs/05-我不懂的.md` |
| 8 ★ | 在哪落地、用什么做、**花多少钱怎么赚钱** | `docs/06-技术与落地.md` |
| 9 | 排成可勾选的任务清单 | `docs/07-任务清单.md` |
| 10 | 做→检查→修，循环到过关 | 真正的东西 |

**第2步的倒推算账是全套最狠的一道闸**：

```
一单赚多少 → 每月要多少单 → 要接触多少人 → 每天要多少人看到
→ 这个数字，靠你现在能想到的渠道，拿得到吗？
```

**大多数点子在这儿当场就死——不是想法不好，是算术不成立。**
一分钱不花、一天不等就能知道。

# 三、你的团队：一个 CEO ＋ 两个分支

```
        你（只跟 CEO 说话）
              │
         CEO（唯一拍板的）

     咨询│           │派单
```

## 招人

```bash
./loop.sh hire                     看有哪些人可招（按两个分支列）
./loop.sh hire 战略 财务 风控        招进来
```

**别一次全招。** 一次调用 $0.15~$8，十个人问一遍要几十美元。
**让 CEO 判断该问谁。**

## 用起来

```bash
./loop.sh say "我在想要不要把这个卖给别人"    在群里说话，所有人都看得见
./loop.sh ask 战略 "你怎么看"                  单独问某个人
./loop.sh 会诊 "议题"                          CEO 点名该问谁 → 逐个问 → 裁决
```

## 派活干活

```bash
./loop.sh 派单                       执行总监把 CEO 的决策拆成每个人的活
./loop.sh 排班                       定今天每个员工做什么
./loop.sh 派活 竞品 "查清楚…"         单独派一件活，他会交一个文件
./loop.sh 验收                       CEO 逐份判行不行，打回要写清怎么改
./loop.sh 台账                       谁手上有什么活、到哪一步
```

## 每个员工是一个独立智能体，可以各用各的 AI

**是的，每个人都是独立接口。** 一个员工有三样自己的东西：

| 自己的 | 意思 |
|---|---|
| **会话** | 他记得你跟【他】说过什么，别人的对话他看不见 |
| **工作目录** `work/<名字>/` | 他的资料和交付物，别人动不了 |
| **接口** `.loop/roles/<名字>.env` | **他用谁家的 AI、哪个模型、花谁的钱** |

```bash
./loop.sh 接口                       看每个员工现在用谁家的
./loop.sh 接口 客服 deepseek          把客服换成 DeepSeek（会问你要 key）
./loop.sh 接口 执行层 deepseek        干活那一整层全换，参谋和 CEO 不动
./loop.sh 接口 测 客服                真打一次，看通不通
./loop.sh 接口 客服 官方              换回来
```

**换谁不换谁，只有一条线：**

| 留官方 | 可以换便宜的 |
|---|---|
| CEO 裁决、风控反证、战略、行研 | 客服分拣、竞品巡查、内容初稿、数据整理 |
| **判断错了整个方向就错了** | **干得糙一点，验收那关能兜住** |

**判断力省不得，体力活可以省。**

`[事实]` DeepSeek 自带 Anthropic 格式的接口，不用装任何转换工具。
输出这一头 V4-Pro 比 Opus 5 便宜约 **29 倍**，V4-Flash 约 **89 倍**
（`查证日期 2026-08-13`，明细和来源见 `安装与落地.md` 第三节）。

**一件必须先知道的事**：换过去之后，`./loop.sh cost` 里那几笔的美元数**不作数**——
claude 只会按 Anthropic 的价目表算钱，它不知道别家收多少。
台账和看板都会当场标出来哪几笔走的谁家，**真实花费去那家后台看。**

# 四、外部专家：找真人的判断，不是让 AI 编

# 四之二、上线之后：CEO 帮你运营，你只看仪表盘

```bash

```

**上线前三道闸，一道不过就不许上：**

| 闸 | 谁判 |
|---|---|
| **一单赚不赚钱**（含获客成本） | 商业专家 |
| **撑得到第一笔钱进来** | 商业专家 |
| **第一个真人 30 天内能用上** | MVP大师 |

加上**营销大师**——他不给你"最好的打法"，给你**你这个条件下真能跑起来的**。
判断该用谁的方法只看三件事：**受众像不像 ／ 资源差多少 ／ 依赖什么前提**。
（需要大预算投流的打法，对没预算的人是毒药，不是良药。）

**上线之后你只做一件事：看仪表盘。** 剩下的 CEO 带着人干。
只有三种情况我们会叫你：**快到止损线了 ／ 钱要花完了 ／ 需要你本人拍板的**。

## 「我不确定标准」这件事

**这是最常见也最正常的状态**，`references/判断标准.md` 里写死了怎么办：

- **标准是分层的**：第0层有没有人要 → 第1层能不能用 → 第2层好不好 → 第3层撑不撑得住。
  **只用当前层的标准判断，上面层的一律不许用**——
  拿"好不好看"去判断一个还没验证"有没有人要"的东西，**是最贵的浪费**
- **先看天花板，再选适合的，顺序不能反**。一上来就找"适合新手的方案"会把你锁死在低水平——
  **你压根不知道好是什么样，会把及格当优秀，还很满意**
- **错了先归因再动手**：目标错 / 标准错 / 方法错 / 执行错。**改错层，越改越糟**

# 九、六条「不许」——这才是这套东西的真身

十步是外壳。**真正在起作用的是这六条：**

| | 不许什么 | 挡住的是哪种自欺 |
|---|---|---|
| 1 | **不许编** | 「业内普遍认为」——凭印象说出来的、听着很专业的话 |
| 2 | **不许把猜测当事实** | 一份读起来完美流畅、看不出哪句是猜的文档 |
| 3 | **不许问你答不上来的问题** | 「你的标准是什么」——把该它干的活推给你 |
| 4 | **不许只算一侧的钱** | 算了半天成本，从没问过谁掏钱 |
| 5 | **不许拿「我们更好」当护城河** | 功能更好／效率更高／更有品味 |
| 6 | **不许说通过了但其实没验** | 屏幕上全是 ✓，底下什么都没发生 |

第 6 条不只写在提示词里，**是在代码里硬查的**：
每一步跑完查该产出的文件在不在，不在就记「没做成」，不往下走。

# 十、常见问题

**Q：它跑一半停了，是坏了吗？**
先看它说什么。三种情况完全不同：
- 「不是代码坏了，是 AI 的额度用完了」→ **等就行，重跑没用**
- 「轮到你了，这条 AI 干不了」→ **该你上手了**，上面写了要你干什么
- 「这一步没有产出 XXX，按没做成处理」→ 看 `docs/05-我不懂的.md`，里面有选择题

**Q：能不能全自动，我什么都不管？**
**不能，而且不该。** 四个闸门定的是生意问题——凭什么是我们、什么算好、
砍哪个功能、花多少钱。**这些 AI 替你做只能靠编。**

**Q：贵吗？**
跑通十步大概 $20~40（实测，第1步「听懂」实测 $0.62）。跑之前用 `budget` 设上限，到顶自动停。

**Q：换个项目怎么办？**
`./loop.sh close` 结项写复盘 → `./loop.sh reset` 清空重来。
**`references/` 里的判断档案不会被清掉**——那是你攒下来的判断力。

# 这个项目的铁律

## 我是谁
使用这个项目的人是**生意人，不是程序员**。判断力强、审美好、知道什么东西能赚钱，
但不懂技术名词、不会看代码。请把我当成一个聪明的甲方，而不是同事。

## 说话方式（最重要，违反了整个项目就废了）

1. **术语必须当场翻译。** 任何技术名词第一次出现，必须紧跟一句大白话解释，最好带类比。
   - ✅ 「用 Supabase 做数据库（数据库＝存数据的仓库；Supabase 是个现成的云仓库，不用自己搭）」
   - ❌ 「使用 Supabase 作为 BaaS 层持久化数据」

2. **不许问我答不上来的问题。**
   - ❌ 「你想用 React 还是 Vue？」——我怎么知道
   - ✅ 「我建议用 React。理由：会的人多，以后找人接手容易。代价：比另一个选择多花两天上手时间。
     如果你更在意上线速度，我们换 B 方案，你说一声就行。」

3. **要我做判断时，出选择题，不出问答题。** 给 2–3 个选项，每个写清楚：
   是什么（白话）、好在哪、代价是什么、我推荐哪个及为什么。

   **推论（很重要）**：不许问我「你的标准是什么」。我答不上来，没人答得上来。
   **我看到了能判断，闭着眼描述不出来**——这是两回事。
   要标准就给我具体的东西看（A/B/C 三个版本，能想象出画面的那种），
   从我的选择里把标准提取出来，写成一句话给我确认。
   问我要标准，等于把你该干的活推给我。

4. **区分「技术问题」和「生意问题」。**
   技术问题你自己定，别烦我。生意问题（花多少钱、**怎么赚钱**、做给谁、砍哪个功能、
   什么算好）必须问我。

   **钱要算两侧，不许只算一侧。** 这套东西以前只算成本不算收入，那是漏的——
   「谁掏钱、凭什么掏、卖多少单回本」跟「花多少钱」一样重要。
   方法见 `references/框架库.md` 第八节。

5. **不许编。** 价格、平台规则、免费额度、竞品情况、某个工具能不能干某事——
   凡是会变的事实，先用 WebSearch 查证再写，并注明查证日期。查不到就写「查不到，需要验证」。
   **靠训练记忆写出来的"业内普遍认为"，一律不算数**——我要的是现在的真实情况，
   不是你印象里的。

6. **关键判断必须标来源，不许把猜测伪装成结论。**
   `[事实]` 有来源有日期能核对 ｜ `[推断]` 基于事实推的，逻辑写出来 ｜
   `[猜测]` 就是猜的，后面补一句「如果错了会怎样」。
   **猜测本身没问题，把猜测当事实才有问题。**
   一份读起来完美流畅、看不出哪句是猜的文档，是**危险**，不是专业。
   标出来我才看得见承重墙在哪——那些 [猜测] 且"错了很惨"的，就是该先验证的。

## 干活方式

- **每一步的结论都要落盘**到 `docs/` 下对应的文件里，不要只在对话里说完就算。
  我随时可能关掉窗口，文件是唯一的记忆。
- **写决定必须写「为什么不选另一个」。** 三个月后我会忘记，那时候这行字能救我。

## 两条底层原则（我做这个项目的根本诉求）

### 一、站在前人最好的基础上，不重造轮子
这世上大概率已经有人把这件事做得很好了。**默认先找、先抄、先用现成的**，
自己做只是最后手段。每决定"自己做一样东西"，都要先说明为什么现成的不够用。
思考框架也一样——`references/框架库.md` 里是别人验证过几十年的思考工具，
直接调用，别自己瞎琢磨。

### 二、共性做扎实，独特下重注
- **共性**＝所有人都需要、不做就出局的东西。老实照做，**不许在这儿创新**，创新就是挖坑。
- **独特**＝我们跟别人不一样的那一点，包括「用户自己想不到、但一用就对」的东西。
  这是这东西的命，必须早做、做到极致。
- 差异化的本质是**取舍**，不是叠加。什么都做＝什么都平庸，而且钱不够。

`docs/02-共性与独特.md` 是这两条的落地。**后面每一步的取舍，都回去看那个文件。**

### 三、判断之前先看层级
需求是分层的：第0层有没有人要 → 第1层能不能用 → 第2层好不好 → 第3层撑不撑得住。
**只用当前层的标准判断，上面层的标准现在一律不许用。**
拿"好不好看"去判断一个还没验证"有没有人要"的东西，是最贵的浪费。
当前层级写在 `docs/00-目标.md` 开头，判断前先看它。
完整方法见 `references/判断标准.md`。

### 四、标准是产出，不是输入
**「什么算好」不是第5步定完就锁死的输入，是随着证据不断修订的产出。**
每转一圈要同时更新两样东西：做出来的那个东西，和「什么算好」的定义。
**只更新前者的系统，会非常高效地跑向一个错的地方。**

落地：每次我看到实物（半成品、真人反应、真实数据），你必须问一句
「有没有哪条标准要改」，并把结果记进 `docs/03-什么算好.md` 末尾的「标准修订记录」。
跑了很久一条都没改过，是个危险信号——要么还没碰到现实，要么在护着旧判断。

同理，「评价」是两件事，别混：
①做出来的东西符不符合标准（容易，可自动化）
②**标准本身是不是定错了**（难，只能人来）。
绝大多数人只做①还以为自己在做评价，结果是高效地朝错方向前进，而且每步验收都通过。

## 一句话

> **任何一个想法输入，都能快速得到一个诚实的答案——
> 要么变成赚钱闭环，要么在你花大钱之前告诉你它不行。**

**为什么叫 MoneyLoop**：因为名字里带 Money，就不可能忘掉变现那一环。
（这不是玩笑——变现这一环之前真的漏掉了，就是因为它在系统里没名字。）

### 这句话是怎么定下来的（别改掉这段来历）

使用者的原话是：「MoneyLoop 就是一个赚钱闭环，**任何一个想法输入都可以产出赚钱闭环**。
帮助解决掉这个过程中所有信息差、调研、各种琐事。实现效率最大化、**信息平权**、
每个人的价值最大化。快速解决这个世界上的问题。」

只改了一处：**「都可以产出赚钱闭环」→「都能得到一个诚实的答案」**。

**为什么必须改这一处**：「任何想法都能变成赚钱闭环」这个承诺，
会让这台机器**永远没有资格说"这个不行"**——止损线当场作废。
而"在你花大钱之前拦住你"恰恰是它最难被替代的能力：
帮你做东西的工具遍地都是，**肯拦住你的没有**。
改完之后使用者想要的全保留了（任何想法能进、快、解决信息差、信息平权），
但它变成了一句不会骗人的话。

**另外两个词，写下来防止以后又滑回去：**
- **「解决掉*所有*信息差」做不到。** 能解决的是查得到的那部分（领域差、时间差）；
  解决不了**执行差**（真做一遍才知道的）和**关系差**（谁认识你、谁信你）——
  而后两种恰恰是 2026 年唯一还算护城河的东西。
- **「效率最大化」不能当卖点。** 见原则九：效率是杠杆不是资产，用户摸不到。
  追问一句就塌——这个效率换到了什么抄不走的东西？

## 它到底是什么：承诺 ＋ 保证

这两层缺一个都不成立，别只记住一层。

| | 是什么 | 作用 |
|---|---|---|
| **赚钱闭环** | 承诺 | 用户**为什么来** |
| **六条「不许自欺」** | 保证 | 用户**为什么信、为什么留下** |

只有承诺没有保证 ＝ 又一个吹牛的 AI 工具。
只有保证没有承诺 ＝ 一套没人想学的方法论。

**一个会让你自欺的「赚钱闭环」，不是赚钱闭环，
是一个让人感觉很充实的赔钱闭环。**

### 六条「不许」——机器的真身

十步是外壳，这六条才是这台机器真正在干的事。
（894 行代码 ＋ 1483 行说明书 ＋ 1831 行参考资料，都是把这六条送到人面前的包装。）

| | 不许什么 | 挡住的是哪种自欺 |
|---|---|---|
| 1 | **不许编** | 「业内普遍认为」——凭印象说出来的、听着很专业的话 |
| 2 | **不许把猜测当事实** | 一份读起来完美流畅、看不出哪句是猜的文档 |
| 3 | **不许问答不上来的问题** | 「你的标准是什么」——把该我干的活推给使用者 |
| 4 | **不许只算一侧的钱** | 算了半天成本，从没问过谁掏钱 |
| 5 | **不许拿「我们更好」当护城河** | 功能更好／效率更高／更有品味 |
| 6 | **不许说通过了但其实没验** | 屏幕上全是 ✓，底下什么都没发生 |

**这个结论不是想出来的，是三件真事逼出来的**：
① 这台机器自己的十个 bug，六个是同一种病——跑过≠跑成了、勾了≠做了、通过了≠验了。
**它自己身上长的病，和它要治的病，是同一种。**
② 第3步没联网权限时它拒绝凭印象编竞品，把卡点写进文档停下来。那次它要是编了，没人会知道。
③ 使用者说「他们效率肯定没我们高」「他们没有咱们的哲学」，
系统按自己的规矩把这两句划掉了——**一个只会顺着人说的工具，不会这么干。**

### 选了 B，这四件事的性质变了

写清楚，因为它们从"以后再说"变成了"现在就得管"。

**一、「愿不愿意付费」从猜测变成承重墙。** `[猜测 → 必须验证]`
之前它标着「如果错了，整个定位要重来」，那时还能拖，因为自用工具不需要别人付钱。
**现在整个东西架在这条猜测上。它是现在最该先验的一条，排在做任何新功能前面。**

**二、重量从"可以慢慢改"变成生死问题。** `[事实]`
自用工具可以重——反正你自己愿意忍。**产品不行。**
已有公开数据：同一个任务，最轻的同类 12 分钟，最重的 5.5 小时，
而这个品类**被记录在案的死法就是"重到没人愿意天天用"**。
MoneyLoop 目前属于重的那一派（说明书最长 212 行，参考资料 1831 行）。
**选 B 等于把砍重量从可选项变成了必答题。**

**三、建受众从"应该做"变成"第一阶段必做"。** `[事实，见原则七]`
受众要时间养，产品可以后补，**反过来不行**。
而且诚实的护城河账算下来，**受众/信任是唯一成立的那条**
（效率、哲学、功能都被自我安慰识别器划掉了）。
**它最慢、最不性感、最不容易在跑 loop 的过程中顺手完成——所以必须专门排任务。**

**四、第8步的「收钱这一侧」不能再写"不适用"。**

以及**这个产品自己的止损线**（花多少钱、到什么时候、见到什么信号就停），
全都要真答。方法见 `框架库.md` 第八节和第九节。

## 已经确立的十一条原则

这十一条是一路讨论下来沉淀的结论，**后面所有判断都回来对照它们**。

**一、站在前人最好的基础上，不重造轮子。**
默认先找、先抄、先用现成的。自己做是最后手段，且必须说明为什么现成的不够用。
思考方式也一样——框架库里是别人验证几十年的工具，直接调用。

**二、共性做扎实，独特下重注。**
共性＝不做就出局，老实照做，**不许在这儿创新**。
独特＝这东西的命，早做、做到极致。
差异化的本质是**取舍**，不是叠加。

**三、判断之前先看层级。**
第0层有没有人要 → 第1层能不能用 → 第2层好不好 → 第3层撑不撑得住。
**只用当前层的标准判断。** 拿"好不好看"去判断一个还没验证"有没有人要"的东西，是最贵的浪费。

**四、标准是产出，不是输入。**
「什么算好」随证据不断修订。每转一圈同时更新东西和标准。
**只更新前者的系统，会非常高效地跑向一个错的地方。**

**五、不问你标准，给你东西看。**
你看到了能判断，闭着眼描述不出来——这是两回事。
标准从你的具体选择里提取，不从你嘴里问。

**六、钱要算两侧。**
只算成本不算收入，是漏的。谁掏钱、凭什么掏、卖多少单回本，和花多少钱一样重要。

**七、先建受众，再建产品。**（2026-08 调研结论，见 `现在什么防得住.md`）
AI 把「做出来」压到接近零，**能被抄的都不算护城河**。
剩下抄不走的只有"谁认识你、谁信你"。
**受众要时间养，产品可以后补，反过来不行**——所以建受众的动作
要和做产品并排排进第一阶段，不许等做完再说。

**八、速度不是护城河，速度是买护城河的钱。**
领先几个版本只给你一段缓冲期——**对手抄你的成品，不抄你的失败**。
缓冲期里必须换到抄不走的东西（受众/数据/关系/习惯）。
换到了你还站着，没换到，缓冲期一过就归零。
所以每领先一版该问的不是"能领先多久"，是**「这一版换到了什么抄不走的东西」**。

**十、抄形不抄神，抄来的一定长歪。**
别人的做法是从**他的约束**里长出来的（他的钱、团队、受众）。
只抄做法，搬到你的约束里必然变形，而且抄的时候看不出来。
每偷一样东西，都要问：**他为什么这么做？他在哪儿认输换了哪儿领先？
换成我的约束，同样的逻辑推出什么？**

**十一、品味不是护城河，品味是护城河的生产设备。**
品味本身抄不走，但**品味的产出抄得走**，而且现在以天计。
所以品味给你的不是某个差异的持久性，是**持续产出新差异的能力**——
必须一直转才有价值，停一年就被追平。

**九、警惕自我安慰式的护城河。**
「功能更好」「效率更高」「更有品味」——这三句每个项目都会冒出来，
**听着都对，但都不是护城河**。每一句都要追问到「用户摸得到的差别」为止，
说不出来就不算。特别是"效率更高"：**你看不见对手的内部流程，
拿自己的内部过程比别人的外部结果，永远显得自己更聪明。**

## 这台机器最危险的失败模式

**它太好用了，好用到你会一直待在里面。**

循环本身让人有成就感——每一步都有产出、都很精致、都在推进。
而**发布是痛苦的**，因为发布会被拒绝。

所以一个思考能力强的人，用这套东西最可能的下场不是做出烂东西，
是**做出一摞漂亮的文档，然后什么都没发出去**。

拦住它的东西只有两个，都在 `docs/03-什么算好.md` 里：
**完成线**（到这儿就发，不许再改）和**止损线**（到这儿就停，不许再投）。
这两条不写，这台机器会变成一个很高级的拖延工具。

# Orbis · 公司总纲

**Orbis,拉丁语:圆环、世界、轨道。**

2026-08-18 定。除最后「放哪、怎么分层」那一节,**全部是老板原话,一字未改**。

## 我们信什么

万物有道。规律先于愿望:
先给别人创造价值,钱才会来。顺序不能反,反了就是自欺。

## 我们的使命

带领人不断接近道。
不是替他走——是把顶尖的判断送到他手里,
让他自己看清、自己选、自己走过来。

## 我们怎么做(第一个产品:MoneyLoop)

把顶尖人类的判断,做成普通人绕不过去的流程。
不讲道理,道理没人听;把道理做成流程里不答就过不去的那一关。
他做执行端口,我们做判断端口。执行越便宜,判断越值钱。

## 两个战场

物质:一个想法进来,要么变成赚钱闭环,要么在花大钱之前听到"不行"。
精神:一面镜子,把他自己说过的话摆在他面前。
我们只当镜子,不当医生。编造的洞察比没有洞察更害人。

## 一条铁律

使命可以大,验收必须小。
每一天的工作必须能回答:这一步让哪个真实的人,离他的答案近了一步?
答不上来的,说得再宏大,都不算工作。

## 放哪、怎么分层(这一节不是原话,是接手方按仓库惯例补的)

- **Orbis 是公司,MoneyLoop 是第一个产品。**
  这一份管信什么、往哪走;产品的门口在 `references/00-总纲.md`,
  那一份管 MoneyLoop 是什么、怎么做。
- **两层各有一条使命,层级不同,不冲突、不合并、不互相抄**:
  公司使命是上面那条「带领人不断接近道」;
  产品使命是 00-总纲里 2026-08-12 定的那条(增量第一)。
  哪天两条打架了,拿去找老板裁——接手的人不许自己挑一条当真的。
- **为什么放 `references/`**:reset 清不掉、跨项目活着——
  公司层的东西必须比任何一个产品活得久。
- 上面那条铁律不是挂在墙上的:这仓库已经有它的执行件——
  `references/验证的规矩.md`(验收必须小、必须可数)和

▼▼▼ FILE: references/专家的认可度.md ▼▼▼
# 什么样的人才算专家（认可度）

**这一份是唯一的真身。** `专家团.md` / `蒸馏.md` / `行业专家.md` 都指向这里，
不许各自再抄一遍——抄一遍就会有一天三处对不上，而你不知道哪个是真的。

---

## 一、认可度 ＝ 可核对的凭证，不是名气

**判断一个人算不算专家，只有一条：他凭什么被信，能不能核对。**

| 算 | 不算 |
|---|---|
| 出过书、参与过国家/行业标准、写过教材 | 粉丝多 |
| 有可查的战绩（公司、销量、融资、任职） | 自称"操盘过上亿" |
| 公开演讲、访谈、判决书、财报里能查到 | 二手转述、"业内都知道" |
| **失败的当事人**（有公开复盘） | 别人替他总结的失败 |

**没有凭证的一律不收。** 不是因为他不厉害，是因为**你没法核对，
而没法核对的东西一旦错了，你永远不知道错在哪。**

---

## 二、配比写死：A≥3　B≥3　C 0–2　失败方≥1

| | 至少几位 | 他给你什么 | 他给不了什么 |
|---|---|---|---|
| **A 体系**（写书的、国家标准、教材、行业规范） | **3，不许缺** | **知识骨架**：这行分几块、每块的标准做法、行业黑话 | 当下的具体打法 |
| **B 操盘**（有可核对战绩的一线） | 3 | 什么条件下会失效、真实的数字量级 | 体系（他只有他那条路） |
| **C 标杆**（乔布斯、马斯克这类跨行的） | 0–2 | **判断范式**——他怎么想事情 | **你这行的任何细节**（别问，问了就是编） |
| **失败方**（死掉的那批） | 1 | 怎么死的、死在哪一步 | —— |

### 为什么 A 类不许缺

**只按"有战绩"去找，会找回一堆网红。**
有故事没体系，而且他的成功高度依赖那个年代的红利——
**拿到手你没法用，因为你不知道哪部分是方法、哪部分是运气。**

A 类给的是**骨架**：这个行业由哪些环节构成、每个环节的标准做法是什么。
有骨架，B 类的故事才挂得上去。

**A 类是骨架，B 类是血肉，C 类是眼光。**
只有 B 类，你就只有一堆故事。

### 为什么必须有失败方

九个人告诉你怎么成，一个人告诉你怎么死。
**"怎么死的"比"怎么成的"可复用得多**——成功高度依赖时机，
失败的原因却反复出现。

---

## 三、诚实红线（这条最要紧）

**它读不到那些书的全文。** 它有的只是目录、摘要、书评、演讲、访谈。

所以每一位都必须标明**掌握到什么程度**：

```
读过全文 ／ 只有目录和摘要 ／ 只有二手转述 ／ 只有一次演讲
```

**顺着目录编内容，是这件事最像模像样的一种编造。**
一份读起来充实流畅、看不出哪句是编的专家意见，**是危险，不是专业**。

### 每次开口必须分层

```
【他说过的】 ——  有出处，能核对到原话
【据此推断】 ——  基于他的公开判断推的，逻辑写出来
【我的补充】 ——  他没说过，是我加的
```

**混在一起说，等于借他的嘴说你的话。** 借方法可以，借嘴不行。

---

## 四、还要问一句：他说那话的时候，条件是什么

一个专家的判断永远绑着他当时的条件——那年的平台规则、流量成本、
竞争格局。**条件变了，判断可能整个反过来。**

所以蒸馏一个人的时候，除了"他说过什么"，必须记：

```
他说这话是哪一年、在什么环境下：____
那时候成立的前提，现在还成立吗：____
如果不成立，他的结论要怎么改：____
```

**不问这一句，你请回来的是一个活在过去的顾问。**

# 两条腿 · 借来的和自己的

**2026-08-18 定。** 起因：老板说「可以让 Manus 跑，再让咱们的 OIC 自己再跑一遍。

# 一、这份文件防的是什么

**把借来的能力当成自己的。**

免费期会结束、账号会被封、平台会改规则、工具公司会倒闭。
**每一次都是突然的，而且都是在你已经离不开它的时候。**

所以这套东西从第一天起就分两条腿走路：

| | **借来的腿** | **自己的腿** |
|---|---|---|
| 谁 | Manus 等外部工具、别家的模型、任何免费额度 | OIC（`claude/intelligent-opportunity-analysis-system-q0zq4t`） |
| 产出叫什么 | **线索** | **证据** |
| 放哪儿 | 灵感池 | 证据库 |
| 能干什么 | 给人看 · 帮人想方向 · 决定「下一步该查什么」 | **进模型 · 进评分 · 进对外结论** |
| 取数方式 | 浏览器、公开页面、随便看 | 官方 API ／ 授权采购 ／ 官方公开下载 ／ 用户自己上传 |
| 会不会消失 | **会。随时。** | 不会 |

# 二、三条硬规矩

### 1. 线索永远不许升级成证据

一条线索想要算数，**必须由自己那条腿从合规渠道重新取一遍。**
**取不到，就不算数**——不管它看起来多对、多诱人。

**「我们已经看到过这个信息了」不构成证据。**
看到过和拿得到，是两回事。

### 2. 自己那条腿不许依赖任何外部工具的产出

**验收方式是一条能跑的命令，不是一句保证**（见第四节「拔腿测试」）。

### 3. 每一条线索必须自带出身标记

```
来源方式：浏览器抓取 · 不可用于对外结论
```

**这一行不许省。** 省了以后，三个月后没人分得清哪条是买来的、哪条是看来的——
**而分不清的那一刻，整个证据库就降级成了灵感池。**

# 三、为什么爬来的东西不能当证据（不是洁癖，是有依据的）

OIC 的 `oic/compliance/provenance.py` 里写死了：

```python
FORBIDDEN_METHODS = frozenset({AccessMethod.SCRAPING})
```

**爬取来的数据，无论法务怎么说，一律不放行。** 代码闸 ＋ 数据库约束双保险。

依据（不是我编的，是那份代码的注释里带着的）：

- 《反不正当竞争法》（2025）第 13 条第 3 款：
  禁止「以避开或者破坏技术管理措施等方式获取他人合法持有的数据」
- 德恒统计 2011–2022 年 12 起「爬虫 ＋ 不正当竞争」案，
  **爬取方胜诉率不足 16.67%**

那份代码还留了一句，值得抄在这儿：

> **反爬不是待修的 bug，是停止信号。**

**这条禁令不许改。** 它是代码级护栏，改了以后出事没有第二道防线。
想要那类数据，走授权渠道买——**买不到就是买不到，那也是一个答案。**

# 四、拔腿测试（这一节是这份文件的牙齿）

**每次有人说「我们自己也能跑」，就跑这个。**

```
把所有从借来的腿产出的东西全部拿掉，自己那条腿必须照样跑完一轮。
```

- **跑完了** → 「自己也有能跑的」这句话是真的
- **跑不完** → 这句话是假的，**而且是最危险的那种假**：
  平时看不出来，等工具断了那天才发现

**这个测试要定期跑，不是做完一次就算。**
依赖是慢慢长出来的，长的时候没人察觉。

# 五、什么时候可以借

**别理解成"不许用外部工具"。** 借是对的，MoneyLoop 第一条原则就是

**可以放心借的**：想方向、铺范围、初筛、查价格、找线索、当第二双眼睛

**绝不能借的**：

- **任何"停了就停摆"的环节**

> **借它的眼睛可以，借它的骨头不行。**

写成感慨的,它只会模仿语气。所以本档案一律三段式。

**输出义务**(写进相关角色的提示词,硬要求):

## 二、公理(草稿区 · 支撑档案满 3 条才转正)

格式:公理 / 触发信号 / 规矩 / 支撑档案 / 什么情况推翻它

**公理一:人考虑不了这么多点。**
思考大多是无意识的,被偏见、经历、当天的情绪驱动;想清楚是例外,不是常态。

- 规矩:永远不要求对方"想清楚"。替他想,他只确认。
- 支撑:档案001。| 推翻条件:出现连续多个客户自己想清楚后主动成交。

**公理二:情绪先于道理,利益终会回来。**
同一个人换一天答案不一样;情绪差时拿到的"不"不算数。

- 规矩:记录【当时的状态】;隔几天二次确认,两次"不"才算真拒绝。
- 支撑:档案001。| 推翻条件:二次确认的答案与首次高度一致(说明情绪影响被高估)。

**公理三:多数人要的是感觉,不是价值,且乐在其中。**

- 规矩:不救所有人。只服务疼得够狠的;对其余人,第一口必须立刻有用,不许说教。
- 支撑:档案001(反面)。| 推翻条件:说教式内容带来真实付费。

**公理四:顺着情绪说,不顺着情绪改结论。**
只有表达层没有分析层的产品(渣男、成功学)复购率很高——表达层的价值已被市场验证;
分析层的价值要靠账本证明。

- 规矩:分析层不为好听让步;表达层不许改结论、不许动 [标记]、不许改评级。
- 支撑:既有架构 + 档案001。| 推翻条件:无(此条与六条不许同层)。

(公理的内核版存在 `创造者语言库/价值内核.md`;这里是执行版。
改哪一边,另一边必须跟着改——两边对不上,以老板最后说的为准。)

## 三、信号翻译表(给 AI 的判错表 · 人版)

| 听到 | 别当成 | 翻译成 | 规矩 |
|---|---|---|---|
| "没钱" | 余额陈述 | 优先级:不想为这个花钱 | 不辩论钱,去找价值没被看见的地方 |
| "想明白再说" | 拖延 | 他在等一个帮他想明白的人 | 别催。给一道选择题,不给一张表格 |
| "除了X其他都行" | 让步 | X 是雷区(利益/权力/面子) | 记下X绕开,不追问为什么 |
| "你根本不知道什么情况" | 抬杠 | 他有没说出口的约束 | 停止推销,改问一个事实题 |
| 反复横跳 | 愚蠢 | 两个自己在打架:想要 vs 怕失去 | 把两边的账替他摆出来,让他看见 |
| 突然不回复 | 拒绝 | 表格太大答不动 / 情绪没到 | 缩成一个问题,隔几天轻轻再碰 |

## 四、防骗七检(识别"讨好你但是错的")

对外——人骗你:

1. 顺着你情绪说的话,价值减半再听。
2. 要你现在就决定的,基本都有问题——真机会等得起一晚。
3. "只有你特别""就差你了"是按钮,不是事实。
4. 全是好处、没讲代价的方案,是没算完的方案(不许只算一侧的钱)。
5. 说不出怎么验证的承诺,按编的处理。

对内——AI 和你自己骗你:

6. 听完特别舒服的分析,先找它回避了什么——舒服本身是信号。
7. AI 全票通过要警惕;夸你的那句先划掉,再读结论。

## 五、档案记录

格式:原话 / 当时的状态 / 我当时的解读 / 复盘后的真实动机[标记] / 下次的规矩

### 档案 001 · 2026-08-18 · 电商公司老板娘 · 推销失败

【她的原话】
"想明白就弄好,想不明白就不弄" / "没钱"→"有钱"反复 /
"除了主播其他都接入行" / "你根本不知道什么情况" / 最后不回复

【当时的状态】
不清楚。可能当天情绪不好([猜测],未验证)。

【我当时的解读】
她蠢、横跳、不讲道理。

【复盘后的真实动机】(均为 [推断])

- 一次收到三个系统+买电脑的要求 = 一张表格,答不动,所以不答
- "没钱" = 优先级陈述,不是余额陈述
- "主播除外" = 怕动内部权力结构
- "想明白就弄" = 在等一个帮她想明白的人,而我让她自己想

【下次的规矩】

1. 一次只推一个东西,只问一个问题
2. 不许让客户第一步买设备;最贵的一步先用零成本验证
3. 听到"没钱",翻译成"价值还没被看见",不辩论钱
4. 对方点名排除的领域,是地图上的雷区标记,不是拒绝
5. 情绪差的时候拿到的"不",隔几天二次确认才算数

## 六、这份档案自己的红线(比前五节都重要)

1. **只记具体的人、具体时刻、具体的话。不记对任何群体的判断**——
   对群体下判断,就是"编",正是第 1 条不许。
2. **每条公理必须写明"什么情况会推翻它"。** 写不出推翻条件的,不许立。
3. 深夜或情绪激动时写的条目,标【情绪时段】,次日复核再转正。
4. **理论按需引进**:同一模式在档案里出现满 3 次、又没有名字,
   才去查文献给它一个名字。先攒证据,再请理论。
5. **反例必须记**:档案证明公理错的时候,改公理,不删档案。

# 怎么判断 · 怎么纠错

这个文件回答五个问题：
1. 需求是分层的，标准也得分层——现在该用哪一层的标准？
2. 「最好的」和「最适合我的」不是一回事，怎么选？
3. 它给了个方案，我怎么判断好坏？
4. 发现错了，怎么纠？
5. 标准本身错了怎么办——**这条最容易被忽略，也最贵**

> 先说一句最重要的：**你不用能说出标准，你只需要能认出好坏。**
> 这两件事完全不同。让你凭空描述"什么是好"，谁都答不上来；
> 但把三个东西摆在你面前问"哪个顺眼"，你一秒就能答。
> 所以后面所有的判断方法，都是**给你东西看**，不是**问你标准**。

---

## 一、需求是分层的，标准也必须分层

同一个项目，在不同阶段，"做得好"的意思完全不一样。
**拿错层的标准去判断，是最贵的浪费——而且几乎所有人都在犯。**

| 层 | 这一层在问 | 过关标准 | 这一层**不许**看什么 |
|---|---|---|---|
| **第0层 有没有人要** | 这事有人真需要吗 | 有人愿意为它付出点什么：时间、钱、留个联系方式、认真提意见 | 好不好看、精不精致、功能全不全 |
| **第1层 能不能用** | 拿到手会不会用 | 一个没人教过的人，能独立走完全程 | 快不快、美不美、能不能扩展 |
| **第2层 好不好** | 用完什么感觉 | 会主动再用第二次；会主动跟别人提起 | 能不能承受一万人 |
| **第3层 撑不撑得住** | 人多了会不会塌 | 量涨十倍，成本和麻烦不会跟着涨十倍 | —— |

### 铁律：只用当前层的标准判断，上面层的标准现在一律不许用

**最常见、最烧钱的错误**：拿第2层的标准（好不好看、够不够精致）
去判断一个还在第0层的东西（还没验证有没有人要）。

结果是：花两个月做了个精美的东西，然后发现没人要。
如果第一周用第0层的标准判断，一周就知道了。

反过来也错：东西已经有人抢着用了（过了第0层），
你还在用第0层的标准说"能用就行"——那你会被后来的人用体验碾过去。

### 第0层的信号，强弱差很多——别把礼貌当验证

不是所有"有人要"的信号都算数。按可信度排：

| 信号 | 可信度 | 为什么 |
|---|---|---|
| **预付了钱 / 给了定金** | 最高 | 掏钱有成本，所以它不撒谎 |
| 报名了，而且真的来了 | 高 | 花了时间，时间也是成本 |
| 主动追问「什么时候能用上」 | 中高 | 有急迫感 |
| 留了个联系方式 | 中 | 成本很低，随手就留了 |
| 说「挺好的」「做出来我一定用」 | **接近零** | 说话不要钱，而且人不忍心当面泼你冷水 |

**如果这东西最终要收钱，那「有人愿意付钱」是唯一不打折的信号，其余都只是参考。**

拿一堆"大家都说好"当第0层验证通过，是这一层最常见的自欺——
而且赞美是真心的，所以你不会怀疑它，只会以为"还没找到方法"，然后继续投钱。

### 什么时候升层
上一层的过关标准**稳定地**达到了，才升。
"稳定"的意思是：不是一次侥幸，是重复出现。

在项目里的落地：`docs/00-目标.md` 开头必须写明**现在在第几层**。
后面每一次判断，先看这个数字。

---

## 二、「最好的」 vs 「最适合我的」

这两个不是一回事。混淆它，是新手最贵的错误之一。

- **最好的** = 不考虑你的约束时，这件事的天花板。
- **最适合的** = 在你的钱、时间、能力、受众之下，真正能跑起来的。

### 顺序不能反：先看最好的，再选最适合的

很多人一上来就找"适合新手的方案"，这会把你**锁死在低水平**——
因为你压根不知道好是什么样，你会把及格当优秀，还很满意。

先看天花板的作用不是让你去够它，是**校准你的眼睛**。
看过满分长什么样，你才知道自己手里这个是 60 分还是 85 分。

### 四步选择程序

**第一步：看天花板。**
找这件事做得最好的三个，搞清楚他们**凭什么**好——
具体到能说出机制，不能停在"他们做得很棒"。

**第二步：诚实列约束。**
钱多少、时间多少、你能坚持多久、你的受众是谁、你自己会什么、有没有人帮你。
**虚报约束等于自欺**，后面全乱。

**第三步：拿约束去砍天花板方案。**
逐条问「这一条我做得到吗」。做不到的划掉。
砍完剩下的，就是"最适合"。

**第四步（最容易漏，但最重要）：写下切换条件。**
「等到 ____ 的时候，我就该从现在这个换成 ____ 。」
不写这条，你会一直用着入门方案不自知，三年后还在原地。

### 具体到「用哪个大师的方法」

大师的方法都是在**特定环境**下验证出来的。判断适不适合你，只看三件事：

1. **他的受众跟你的像不像？**（他面对的是企业客户，你面对的是街坊，方法不能直接搬）
2. **他的资源跟你差多少？**（他有团队有预算，你一个人——差十倍以上的，方法多半失效）
3. **他的方法依赖什么前提？**（需要大预算投流的打法，对没预算的人是毒药，不是良药）

**两条实操建议：**

- **同时只用一套方法，别混搭。** 不同大师的方法各有内在逻辑，
  混在一起会自己打架，做出来四不像。跑完一轮看结果，再决定换不换。
- **判断一个方法是不是过时了，看它依赖的平台规则还在不在。**
  很多"经典打法"死于平台改规则，不是死于方法本身错。这一条必须去查，不能靠印象。

---

## 三、它给了个方案，我怎么判断

**不要通读一遍然后凭感觉。** 用逼问法，五个问题，十分钟。
按杀伤力排序——**前面的不过关，后面的就别看了**。

### 1. 这个方案最可能怎么死？
让它自己回答。**说不出来的，就是没想清楚。**
好方案的作者一定知道自己的方案哪儿脆。

### 2. 哪些是假设，不是事实？
逼它把假设一条条揪出来，每条标上「如果这条错了，损失多大」。
**没有标假设的方案，等于把赌注藏起来了。**

### 3. 最贵的那一步，能不能先花小钱验证？
能——那就先验证再投钱。
不能——这就是高风险项，你要明确知道自己在赌什么。

### 4. 如果预算砍一半，砍哪儿？
这题是逼出优先级的。
**砍不动的方案 = 没有优先级 = 没想清楚。**

### 5. 跟「什么都不做」比，好在哪？
很多方案真正的对手不是竞品，是**维持现状**。
比不过现状的方案，再漂亮也没用。

### 另外两个"闻味道"的信号

- **凡是"全都要"的方案，都是没想清楚。** 好方案一定看得见取舍的痕迹——
  明确说了在哪儿认输，换取在哪儿领先。
- **凡是没有数字的方案，都是空的。** 多久、多少钱、多少人、什么时候能看到结果——
  一个都不能少。全是形容词的方案，等于没方案。

---

## 四、错了怎么纠 —— 先归因，再动手

**最重要的一句话：先搞清楚错在哪一层。不同层的改法和成本，差一百倍。**

### 四层错误，从便宜到贵

| 层 | 是什么 | 代价 |
|---|---|---|
| **执行错** | 东西做歪了，跟当初说好的不一样 | 最便宜，重做那一步 |
| **标准错** | 做的跟说好的一致，但"说好的"本身定错了 | 中等，改标准 + 重做受影响的部分 |
| **需求错** | 标准也对，但根本不该做这个东西 | 贵，大部分工作作废 |
| **目标错** | 整件事的方向就不对 | 最贵——**但发现得越早越值钱** |

### 怎么归因（按顺序问，第一个「是」就停）

1. 做出来的东西，符合当初写的验收标准吗？ → **不符合 = 执行错**
2. 符合标准，但你还是不满意？ → **标准错**
3. 标准也没问题，但根本没人用？ → **需求错**
4. 有人用，但对你的生意没帮助？ → **目标错**

### 纠错三条铁律

1. **不许在错的层上使劲。**
   目标错了还在打磨执行，是最常见的烧钱方式——而且因为"我很努力"而感觉良好。
2. **一次只改一层。**
   同时改两层，你永远不知道是哪个改动起的作用，下次还会错。
3. **改完回头问一句：这个错是怎么发生的？**
   是信息不够？判断失误？还是当时就知道有风险、赌了一把没赌中？
   **第三种最值得记下来**——那说明你的判断没错，只是运气不好，下次同样情况还该这么赌。

---

## 五、标准会变——这是功能，不是缺陷

**「什么算好」定完不是终点。** 每次见到实物，你的判断都会更精确一点——
那个变化是真的，纸上原来写的是猜的。

所以 `docs/03-什么算好.md` 末尾有一张「标准修订记录」表，见到实物就回来记一笔。

**跑了很久一条都没改过，是危险信号**：要么你还没真正碰到现实，
要么你在护着自己当初的判断（这个更常见，也更难察觉——
已经照着一个标准干了两周之后，人是不愿意承认它错了的）。

配套：「评价」是两件事，别混成一件。
①做出来的符不符合标准——容易，能自动化。
②**标准本身是不是定错了**——难，只能你来。
只做①会让你非常高效地朝一个错方向前进，而且每一步验收都通过。

---

## 六、还有一件事：什么时候停

**先分清三条不同的线，它们经常被混成一条：**

| 线 | 管什么 | 写在哪 | 缺了会怎样 |
|---|---|---|---|
| **解决到什么程度** | 需求覆盖的边界 | `00-目标.md` | 无限扩张，功能越加越多 |
| **完成线** | 质量的边界 | `03-什么算好.md` | 无限打磨，永远发不出去 |
| **止损线** | 投入的边界 | `03-什么算好.md` | 在没戏的事上一直加注 |

大多数人有"什么算好"，但没有"什么算够"和"什么算该放弃"。
这两条不写，项目会烂在半路——**要么无限打磨永远不发布，要么在明显没戏的事上一直加注。**

```
完成线：____
（到这儿就停手发出去，不许再改。没有这条，你会无限返工。）

止损线：如果 ____（花了多少时间/多少钱/试了几次），
        并且 ____（关键指标还是没到），就停。

停了之后我会：____（转向什么 / 接受多大损失）
```

**止损线必须在开始之前写。**
开始之后你写不出来了——因为钱和时间已经投进去了，
人对已经付出的成本会本能地舍不得，那时候你的判断已经不干净了。

写在 `docs/03-什么算好.md` 的末尾，白纸黑字。
三个月后你会想删掉它，那一刻正是它在起作用。

# 判断档案 · 跨项目

**这份东西不属于任何一个项目。** 项目会结束、会死、会被推倒重来，
但**「怎么判断」这件事应该越攒越准**。

---

## 为什么单独放在 references/ 而不是 docs/

`docs/` 是**这个项目**的东西，`./loop.sh reset` 会连着清掉。
`references/` 是**跨项目**的东西，换个题目重来，它还在。

**判断力如果跟着项目一起死，那这套东西就永远是第一次做项目。**

---

## 怎么用

- **新项目开始前**：先读这一页，再读第2步的目标。
  **别凭上一个项目的惯性做判断**——上个项目的对，可能是这个项目的错。
- **每次重大决定之后**：回来追加一条。当时怎么想的、后来怎样了。
- **每次结项**：把 `docs/99-结项.md` 里"下次不再犯"的那几条，
  提炼进下面的「已经验证过的取舍标准」。

---

## 一、已经验证过的取舍标准

> 这里只放**被真实结果验证过**的。没验证过的属于"信念"，不属于这里。
> 每条必须写明：什么时候、哪个项目、验证它的是什么结果。

| 取舍标准 | 验证它的结果 | 什么时候 / 哪个项目 | 什么情况下不适用 |
|---|---|---|---|
| （空着不丢人。一条都没有，说明还没有任何判断被现实检验过。） | | | |

**最后那一栏最重要。** 一条没有边界的标准，用到第二个项目上就会伤人——
**这就是「抄形不抄神」的自我版本：连自己上次的做法都不能无条件照抄。**

---

## 二、重大决定的复盘

> 只记**重大**的。什么算重大：改了方向、花了大钱、或者不可逆。
> 记流水账等于没记。

```
### 日期 · 项目 · 一句话决定了什么

当时的处境：____
当时看到的信息：____（哪些是查证的、哪些是猜的）
定了什么：____
为什么这么定：____
**当时最担心错的地方**：____

—— 以下等结果出来了再填 ——

后来怎样了：____
判断对不对：[对 ／ 错 ／ 部分对]
**真正让它对/错的，是当初那条理由吗**：____
　（这一问最狠：很多"判断对了"其实是运气，理由根本没成立）
下次遇到同类处境，改什么：____
```

---

## 三、栽过的跟头（按类型归，不按项目归）

> 按项目归，换个项目就想不起来。按类型归，才会在同类处境里响。

| 跟头的类型 | 具体发生过什么 | 现在怎么防 |
|---|---|---|
| **看着是 ✓，其实没发生** | 这套系统自己身上犯过 9 次：跑过≠跑成了、勾了≠做了、通过了≠验了、规矩写了≠规矩执行了 | 每个"成功"都必须有一个能查的产物；查不到就是没发生 |
| **抄形不抄神** | 从外部批评推断"我们也有同样毛病"，没验证机制是否适用，差点删掉有用的东西 | 每偷一样东西先问：他的约束是什么？换成我的约束会推出什么？ |
| **把猜测当事实** | 报过一次假成果："只给该看的 3 份文档"，实际是"给漏了" | 关键结论必须能指到具体证据；报成果前先验一遍它真的发生了 |

---

## 四、当前的目标栈（同时有几件事的时候用）

> **任何时刻只有一个最高优先级。** 其余排队。
> 「都很重要」等于「没有优先级」，那是这套东西最常见的死法之一。

```
[ 正在做 ] ____
[ 排队中 ] ____
[ 冻结的 ] ____（明确暂停，写清什么条件下解冻）
```

**每次要往「正在做」里塞第二件事之前，先问一句：
上一件是做完了，还是只是不想做了？**

---

## 五、这份档案自己的健康度

- **上次更新**：____
- **累计验证过的标准**：__ 条
- **累计复盘的重大决定**：__ 条

**如果跑了好几个项目，这一页还是空的**——
那说明判断力根本没在积累，每个项目都是从零开始。
**那才是这套东西最大的浪费**：花了钱、花了时间，只换到一个产物，没换到判断力。

# 零、先把最贵的那个错误说在前面

你想的是「我有很多额度，让它一直跑，别停」。

**但这套东西真正的瓶颈不是 token，是你早上的判断带宽。**

一晚上烧一百块钱，早上给你二百页文档——**那不是产出，那是作业。**
你看不完，于是你随便扫一眼说"挺好"，**于是这一晚白烧。**
更糟的是它会一直这么跑下去，**非常高效地跑向一个错的地方，而且每一步验收都通过。**

所以夜班的设计目标只有一句：

> **用无限的夜里，换早上你那十五分钟的最高价值判断。**

**夜里可以无限铺，早上只许交一页。**
**淘汰工作必须发生在夜里**——它要是不自己淘汰，淘汰就落到你头上了。

---

# 一、三条铁律

### 1. 夜里只许做可逆的事
🟢 想、查、写、算、比——随便跑。
🔴 花生意的钱 / 对外发东西 / 不可逆（删除、上线、签约）——**一条都不碰，永不下放。**

### 2. 夜里不许停下来等人（闸门改成沙盘）

这套东西有五道闸门必须你点头。**但"等你点头"和"一直跑"是打架的。**

解法不是取消闸门，是**改成沙盘推演**：

> 它撞到闸门时，**不停**。它自己选一个假设，**盖上「假设未定」的戳，
> 然后带着这个戳继续往下推。** 早上你一句话：这个假设留还是砍。
> 砍了，**这条戳下面的所有东西一起作废**——因为都标着，所以作废很便宜。

**闸门的权力一点没丢**（最终还是你说了算），**但它永远不会卡住。**

### 3. 早上只许交一页纸
夜里的东西全在文件里，随时能翻。**但早报就一页。**
一页装不下的东西，说明它没替你想清楚。

---

# 二、它夜里到底干什么（工头 ＋ 队列）

队列里只有三种活：

| 活 | 干什么 | 为什么值钱 |
|---|---|---|
| **推进** | 把某个想法往下推一步，撞闸门就开沙盘 | 往前走 |
| **查证** | 把标了 `[猜测]` 又承重的那句话，去找一条真证据 | **这是夜里最值钱的活**——白天你没空查 |
| **对跑** | 同一段话两个模型各拆一遍，数分歧（`./loop.sh 试金石`） | 分歧本身就是信号，全票通过反而要警报 |

**工头每轮怎么选活（可数，不许靠感觉）：**

```
1. 有「假设未定」的戳挡着 ≥2 条下游？   → 先去查证它
2. 可行性 <90% 且有承重条件还没验？     → 去查证那一条
3. 都没有？                             → 推进排名最高的那个想法
4. 全都推不动？                         → 从想法箱里拿一个新的进来
```

**每一轮结束必须写一行台账**：花了多少 · 干了什么 · 产出在哪 ·
可行性变了没 · 淘汰了什么。**没有这一行，这一轮不算数。**

---

# 三、便宜模型还要不要用？要，但理由变了

你的额度是**订阅制、不按次收钱**的。那"用便宜模型省钱"这条**就不成立了**——
省下来的钱本来就不花。

**但便宜模型还是要接，理由换成了这个：**

> **两家模型对跑同一段话，分歧本身就是信号。**

一家模型自己跟自己商量，永远商量得很和睦。**换一家，错得不一样，
分歧就浮出来了**——分歧多的地方就是这个想法真正没想清楚的地方。
这个机制（`./loop.sh 试金石`）已经做出来了。

**所以分层的新版本：**

| 谁 | 干什么 | 为什么 |
|---|---|---|
| **主力（你的订阅）** | 夜里所有的推进、查证、综合 | 额度管够，不用省 |
| **第二家（便宜的）** | **只在关键节点对跑一次，取分歧数** | 买的是"错得不一样"，不是省钱 |

**关键节点建议只有两个**：听懂那段话的时候、以及可行性判定之前。
**别每一步都对跑**——那不是取分歧，那是重复劳动。

**[推断] 订阅再大也有上限。** 真撞上了，夜班会表现成想法一个个"卡住"，
早上战报里看得见——**不会静默烧一整晚**。这是它现在的行为，不是我保证的额度。

---

# 四、它什么时候必须停（可数，不许靠感觉）

1. **预算到顶**
2. **`bash scripts/check.sh` 红了** → 立即停。**不许在坏地基上继续生产**
3. **连续 N 轮：可行性没变、没有新证据、没有新淘汰** → 原地打转，停
4. **产出重复度过高**（同样的话换个说法又写一遍）→ 停
5. **撞红线** → 停，并且大声记下来，早报第一行就是它
6. **到点了**（比如早上七点）→ 停下来写早报

**这六条都要能被一条命令算出来。** 算不出来的停机条件等于没有。

---

# 五、早上给你的那一页（长这样）

```
昨晚：跑了 __ 轮，花了 __，停在第 __ 条停机条件

排行榜（它自己排的，你只管砍）
  1. ____   可行性 82%   承重猜测还剩 3 条   分歧 7 处   ——一句话
  2. ____   可行性 61%   承重猜测还剩 6 条   分歧 2 处   ——一句话
  3. ____   已淘汰：____（为什么被淘汰）

要你拍板的（最多三道，都是选择题）
  1. ____  A ____ / B ____   我推荐 A，因为 ____，代价是 ____

它自己承认的
  最不确定的一条：____
  最可能白跑的一件事：____

如果你今天只做一件事：____
```

**你早上做的唯一动作是「砍」，不是「批准」。**
砍比批准快十倍，而且砍错了看得出来，批准错了看不出来。

---

# 六、防止它高效地跑向错的地方

**这是最容易漏的一条。**

标准（什么算好）**不是一开始定死的输入，是随着证据不断修订的产出**。
**只更新产出、不更新标准的系统，会非常高效地跑向一个错的地方。**

所以：**每 N 轮，它必须问自己一次「有没有哪条标准要改」**，
结果写进 `docs/03-什么算好.md` 末尾的修订记录。

**跑了一整晚一条标准都没改过 → 早报必须报出来。**
那说明要么它还没碰到现实，要么它在护着旧判断。

---

# 七、怎么落地（三步，别一次做完）

### 第一晚：手动跑一次，先测出真实数字

```bash
./loop.sh 想法 "帮小区宠物店做一个自动约洗澡的东西"
./loop.sh 想法 "把我十年的装修报价单变成一个报价小程序"
./loop.sh 想法 "给做外贸的人做一个自动跟进催单的助手"
# ……丢 5~10 个进去，只有一个的话那不叫赛马，叫深挖

./loop.sh 夜班 8            # 最多跑 8 小时，跑完自动出战报
```

早上起来：

```bash
./loop.sh 战报              # 一页纸：排行榜 ＋ 谁在等你
./loop.sh 砍 002            # 你早上只做这一个动作
./loop.sh 留 002            # 砍错了随时放回去，东西没删
```

**目的只有一个：测出一晚上真跑多少轮、卡在哪、产出值不值得看。**
**这个数出来之前，下面两步全是猜的**，包括我写的这份。

### 第二步：让它自己醒（定时器）

现在还得你手动敲一次。要真的"睡着了它自己跑"，得在**一台一直开着的机器**上
挂个系统定时任务（到点自己执行一次）：

```bash
# 每天晚上 11 点开跑，最多 8 小时
0 23 * * *  cd /你的仓库路径 && ./loop.sh 夜班 8 >> 赛马/夜班.log 2>&1
```

**验收：你什么都不做，第二天早上战报自己出来了。**

### 第三步：沙盘戳 ＋ 对跑取分歧
撞到闸门不停、盖戳继续推；关键节点换第二家模型对跑一次。
**这一步最不该提前做**——第一晚的实测会推翻很多假设。

# 四位大师的共同规矩

精神意识大师 · 美学大师 · 历史人文大师 · 哲学大师
——四份角色文件都指向这里，不各写一遍。

---

## 一、你们不是来说漂亮话的

**这一层是整套东西里最容易变成装饰的。**

"这个产品应该承载一种存在的诗意"——这种话零成本、听起来很高级、
**而且完全没法照着做**。写十句这样的话，产品一个像素都不会变。

**判断标准只有一条：**

> **你说的每一条，必须落到一个能做的决定上。**
> 落不到的，删掉。

```
❌ 「界面应该体现对使用者的尊重」
✅ 「删除操作不要弹确认框，改成删完给 5 秒撤销。
    确认框是把责任推给用户，撤销是自己扛住。」
```

**后面那句能直接改代码，前面那句改不了任何东西。**

---

## 二、必须挂在可核对的东西上

**每一条判断后面要有出处**，而且是能查的：

| 谁 | 挂在什么上 |
|---|---|
| 美学 | 具体的作品／流派／设计者，带年代 |
| 历史人文 | 具体的先例，什么时候、谁、结果怎样 |
| 哲学 | 具体的人和他真正说过的话，不许把观点熬成一句鸡汤 |
| 精神意识 | **他自己说过的原话**，加上有名字的传统／研究 |

**不许出现「自古以来」「人们普遍认为」「东方智慧告诉我们」。**
这些是没有出处的出处。

**查不到就说查不到。** 编一个出处，比不给出处糟得多——
**因为它看起来可核对，实际上一查就崩。**

---

## 三、每人只答一块，不许重叠

四个人答同一题，会得到四份互相重复、谁也不负责的漂亮话。

CEO 会给每人一个窄问题。**只答你那一块。**

---

## 四、最后要落到"给他几个选项"

**不许替他选。** 你们的活是把选项做到足够好，让他选起来不吃亏。

每个选项要有：**是什么** ／ **好在哪** ／ **代价是什么** ／ **像什么**（真东西）。

**代价必须写。** 三个选项都很美、都没代价——
说明你没认真想，回去重写。

---

## 五、说话

见 `references/怎么说话.md`。这一层特别容易犯的两条：

1. **不许掉书袋。** 引一个人是为了让他更快做决定，
   不是为了显得有学问。**他不需要知道那个人是谁，
   只需要知道该选哪个**
2. **不许煽情。** 他要是觉得你在写文案，这一层就废了

# 实测 · 判级噪声底（2026-08-19）

**一句话**：同一个模型、同一段话、连跑三次，
`对分歧.py` 每一对都报 **「不同 3 对」**。
而他们拿来支撑「换脑子有用」的那个数，是同一把尺子报的 **「不同 2 对」**。

> **信号 2，噪声 3。核心一那个结论，现在不成立。**

---

## 怎么跑的（可原样复现）

```bash
./loop.sh budget 2
./loop.sh 听 "<饰品订货那段话>"     # 跑三次，一个字不改
python3 scripts/对分歧.py <日志A> <日志B>   # 三份两两对比
```

- **模型**：`claude-sonnet-5`，三次都是——**从调用日志 `modelUsage` 验的，不是看配置**（第 6 条）
- **输入**：完全相同的一段话（饰品订货那段），存在 `/tmp/一段话.txt`
- **花费**：3 次调用 **$0.65**（$0.41 / $0.13 / $0.11——后两次便宜是缓存命中）
- **日志**：`.loop/log/20260819-08{5845,}…-听一次.log` 三份 ＋ 各自的 `.json`

## 数出来的

| 对比 | 不同 | 一方独有 | 其中【逐字同一句、星级却翻了】 |
|---|---|---|---|
| 第1跑 vs 第2跑 | **3 对** | 各 1 句 | **2 句** |
| 第1跑 vs 第3跑 | **3 对** | 0 | 0 |
| 第2跑 vs 第3跑 | **3 对** | 后一份 1 句 | 0 |

**三对全是 3，一次没变。这不是巧合，是这套提示词在这台尺子下的噪声底。**

### 抓到的两句纯翻转（逐字一模一样，星级不同）

```
「每天产品线有一百多款」                  ★★ → ★★★
「订货订得不符合科学逻辑、不符合周期」      ★★ → ★★★
```

---

## 这两句为什么要命

**「每天产品线有一百多款」正是他们吵了一整天的那句。**

当时的判断链是这样的：
- 策略 AI 的密封答案：★★★
- DeepSeek 两个模型：都判 ★★
- 于是按第 7 条判定：**「两个脑子一起犯同一个错 → 该改判错表」**

**但同一个模型自己跑三次，这句在 ★★ 和 ★★★ 之间来回翻。**

所以它不是「两个模型一致地判错了」，是**这句话的判级本来就是掷硬币**。
拿掷硬币的结果去改规则，改的是运气，不是规则。

同一天还有一条同样的：「直播带货卖饰品」pro 判 ★★、flash 判 ★★★，
被当成「吵起来 = 模型差异，别动规则」。在我这三次里，
这句同样在自己跟自己之间摇（★★ ↔ ★★★，只是被切分差异盖住了）。

> **既没有"模型差异"，也没有"一致的错"。有的是抛硬币。**

---

## 还顺手抓到一件：这把尺子自己有个毛病

`对分歧.py` 报的「不同 N 对」，**把两件事混成了一个数**：

1. **判级不稳**——逐字同一句，星级不同（三对里抓到 2 句）
2. **切分不稳**——同一段原话，模型每次切的行都不一样
   （比如第 3 跑把「直播带货卖饰品」和「一百多款」合成了一行）

三对稳定报 3，但其中大部分是第 2 种。**这两件事该分开报，否则
"分歧多"到底是"判断不同"还是"断句不同"，看不出来。**

**这条只记录，没动代码**——`对分歧.py` 的三个检查逻辑现在是冻结的。

---

## 老实说这次测量的边界（别拿它多说一句话）

| 边界 | 说明 |
|---|---|
| **测的是 sonnet-5，不是 DeepSeek** | 严格讲，DeepSeek 自己的噪声底**仍然没量过**。但「信号 2」和「噪声 3」是**同一把尺子、同一个量纲**，所以量级的对比成立 |
| **n=3，一段话** | 三对全是 3，稳得出奇，但只有一段话。换一段话噪声底是多少，不知道 |
| **有缓存** | 第 2、3 次便宜很多（$0.13/$0.11），说明命中了缓存。缓存会不会让后两次更像前一次？**不知道，没测**。如果会，那真实噪声底只会**更高**，不会更低——结论方向不变 |

`[事实]` 上面的数字全部来自可复现的命令和日志。
`[推断]` 「所以核心一的结论不成立」——这一步是推的，逻辑写在上面。
`[猜测]` 「问题在提示词不在模型」——如果错了，那就是 DeepSeek 的噪声底
显著低于 sonnet，得单独去量。

---

## 所以该做什么（三条，按顺序）

1. **核心一那个结论撤回**，改成「未证实」。不是证伪——是**证据不够**：
   信号没超过噪声。要立起来，得先量 DeepSeek 自己的噪声底，再看差值。
2. **判错表继续冻结**。原来冻它是因为「承重」一词二义；现在多一条理由：
   **拿来改表的那个证据是噪声。**
3. **真正该修的可能不是模型，是提示词**——同一段话每次切法都不一样、
   同一句每次星级都不一样，说明**判级标准没被写到能复现的程度**。
   这条不花一分钱就能改，而且改完噪声底会自己降下来。

## 二、【最重要的一条】P2 明确不做

**这一节是整份文档的核心。抄错这一条，这个项目就废了。**

### 先问：他为什么这么做？

Grok Bot 给每个 Bot 一台云电脑，是因为它的用户是
**大公司里的知识工作者**——卡点是「AI 碰不到我的 Salesforce / Gong / Outreach」。
$200/月/席的定价，付得起那台虚拟机。

### 换成我们的约束，同样的逻辑推出什么？

| | Grok Bot | 我们 |
|---|---|---|
| 用户是谁 | 有十几个 SaaS 账号的知识工作者 | **手上有个模糊点子的生意人** |
| 卡在哪 | AI 碰不到我的工具 | **我想不明白** |
| 钱从哪来 | $200/月/席，养得起虚拟机 | 还没验证有人付费 |
| 品类死法 | —— | **重到没人愿意天天用**（已记录在案） |

**结论**：抄 P2 等于**把一个卖判断的东西改造成卖执行的东西，
然后去和一个刚拿了 600 亿美元的对手正面打执行。**

这正是原则十「抄形不抄神」要拦的那类决定：
**他的做法是从他的约束里长出来的，搬到我们的约束里必然长歪，而且抄的时候看不出来。**

### 写进「明确不做什么」

```
- 不做 GUI 自动化 / 浏览器自动化 / 云端执行环境
  为什么不做：那是 Grok Bot 的战场，它有 600 亿和 $200/月/席撑着。
  我们的卡点不是"碰不到工具"，是"想不明白"。
  往那个方向走，我们的重量会直接撞上这个品类被记录在案的死法。
```

**如果哪天要推翻这条**，先回答一个问题：
**我们的用户里，有多少人是因为"AI 碰不到我的工具"才不用我们的？**
答不出具体数字，就不许动。

## 三、P3 Routine：该抄，而且是最该抄的一条

**Grok Bot 的做法**：你演示一次工作流程 → 它存成 Routine → 之后自动复跑。
官网原话是「Show a Bot how it's done.」

**为什么它值钱**：把**流程变成资产**。做过一次的事，第二次不用再想。

**换成我们的约束会推出什么**：
我们不需要"录屏 → 转成 GUI 操作"（那是 P2 的配套）。
我们要的是更朴素的一件事——

> **一件事你做过一次、而且有效，就存下来，以后自动重跑或者提醒你重跑。**

对我们的用户，典型的 Routine 是：
- 每周日晚上，让操盘手看一遍数、出下周决策令
- 每天早上 8 点，出今天该做的 3 件事
- 每周一次，问「获客」这个角色：上周的动作有效果吗

**这三条都不需要云电脑，`cron` ＋ 现有命令就够。**

## 四、P6 记忆新陈代谢：我们只有一半

**现状**：`docs/` 只增不减。`学习笔记.md`、`08-每天.md`、`09-操盘记录.md`
会一直长，长到没人看得动，然后就等于没有。

**Grok Bot 那边怎么做**：越用越懂你（具体机制未公开）。
**别人的做法**：短期记忆加权 → 达到阈值才晋级成长期记忆 → 旧的自动衰减归档。

**换成我们**：不需要复杂的加权算法，需要的是**一条规矩**——
每份只增的文件，都要有「什么时候该归档／什么时候该提炼」的规则。
否则它们会变成第二个"看着很充实、实际没人看"的东西。

**这条列为欠账，先不动手**——因为文件还没长到看不动，
现在做是提前优化。**等 `08-每天.md` 超过 300 行再回来做。**

**它的 Bot 只执行，不裁决。**

# 这套循环的本质是什么

> **先看 `00-总纲.md`。** 这个文件是三轮讨论的完整论证过程，比较长，
> 只在"想不通、要看推导"的时候翻。

**目录**
- 前半篇：「这本质是调试」对在哪、错在哪（四条），以及更准的说法
- 续一：五件套架构的三个盲点 + 「不知道标准」的四种逼近法 + 标准是产出不是输入
- 续二：Definition 是最底层——九问对账、两个缺口、四条修正、「为什么是你」

---

起因：使用者提出一个判断——
「用世界现实最强的方法论 + AI 的系统提示词和上下文，
本质还是一个不断逼近最优解的调试过程。」

这个判断对了一半。**对的那一半是机制，错的那一半是目标。**
错的这一半如果不纠，会导致一种很贵、而且当事人感觉良好的失败：
**东西越做越精致，但一直没人要。**

> 说明：本文用到的都是稳定的思想工具（波普尔、Boyd、Ashby、Goodhart 等），
> 不是会变的事实，所以没有走 WebSearch 查证。
> 凡是涉及价格、平台规则、竞品现状的，仍然必须查证——那条规矩不变。

---

## 一、对的那一半

### 1. 机制确实是搜索
可能的做法有无数种，你在用反馈一步步逼近。这确实是优化过程，这个直觉是对的。

### 2. 上下文确实是主要杠杆
AI 产出的质量，主要由**你喂给它什么**决定，不是由你怎么客气地问它决定。
把最好的方法论、最准的资料、你自己的判断喂进去，输出的档次直接换一层。
这一点你抓得很准，这也正是这套流水线把 `docs/` 当作唯一记忆的原因。

### 3. 不重造轮子确实是对的
用别人验证过几十年的东西当输入，比自己憋一套强。这条已经写进 `框架库.md`。

---

## 二、错的那一半（四处，按杀伤力排序）

### 错误 1：调试有裁判，做生意没有 —— 这是最要命的一条

**调试为什么能收敛？** 因为它有一个**又快、又便宜、又诚实**的裁判：跑一下测试，
一秒钟就知道对不对，而且它不会撒谎。

做产品、做内容、做服务，**没有这个裁判。**
反馈慢（几周到几个月）、贵（要花钱才拿得到）、还带噪音（十个人说好可能只是客气）。

这意味着一件反直觉的事：

> **真正的瓶颈从来不是"调得多好"，而是"裁判有多快、多诚实"。**

你想用世界最强的方法论去调——这等于**给一辆没有仪表盘的车换更强的发动机**。
马力上去了，但你还是不知道自己在往哪儿开。

控制论里有条老规矩（Ashby 的必要多样性定律）：
**一个系统的调节能力，上限被它的反馈能力锁死。** 反馈不够，控制器再聪明也没用。

**推论（这条最值钱）**：
在这件事上，能提升产出的最高杠杆动作不是"换更强的方法论"，
而是**想办法让裁判变快、变便宜、变诚实**。
能把反馈周期从三个月压到三天的人，会碾压那个用了更好框架但要等三个月的人。

### 错误 2：调试只能爬你现在站的这座山

调试是**局部优化**——它让你脚下这条路越走越顺，但它永远不会告诉你
"你应该去爬旁边那座山"。

而你最想要的那个东西——**「用户自己想不到、但一用就对」**——
恰恰是调试调不出来的。那不是把现有的东西改好，
那是**换一个物种**。它是一次不连续的下注，不是一次连续的优化。

> **调试能让你做出 90 分的同款，做不出 60 分的另一个物种。**
> 而在有先发者的市场里，90 分的同款打不过先来的，60 分的另一个物种能。

如果你把整件事都框成"调试"，你会系统性地少投差异化，
最后得到一个**打磨得非常好的平庸品**。这是最贵的一种失败，
因为过程中的每一步都很努力、很有质感，直到最后发现没人在乎。

### 错误 3：「世界最强」拼起来 ≠ 最强

每个"最强"都是在**它自己的约束下**最强的。
把五个不同环境下的最优解拼在一起，它们会互相打架——
这个要求大预算，那个要求极简；这个要慢慢养，那个要爆发式起量。

拼出来的通常不是超级方案，是一个**内部冲突的四不像**。

`判断标准.md` 里那条"同时只用一套大师方法，别混搭"就是这个意思。
再补一条更狠的：

> **系统的强度不取决于零件的强度，取决于零件之间合不合。**

### 错误 4：一旦盯着「最优解」调，你会调到指标上去

Goodhart 定律：**一个指标一旦变成目标，它就不再是个好指标。**

因为"最优"必须可衡量，你会不自觉地挑一个能衡量的东西去优化——
然后你会在那个数字上做到极致，而真实价值在别处流失。
做内容的调到标题党，做产品的调到日活，做服务的调到好评率。
数字很漂亮，生意在烂。

---

## 三、更准的说法

把「调试逼近最优解」换成这句：

> **这是一个「下注 + 尽快证伪」的过程，不是「计算 + 逼近最优」的过程。**

区别在哪：

| | 调试思维 | 证伪思维 |
|---|---|---|
| 假设 | 有一个正确答案，我能推出来 | 不知道对不对，但能便宜地知道错没错 |
| 动作 | 想清楚，然后做对 | 先下小注，让现实告诉我 |
| 花钱在 | 想得更周全 | 更快拿到真实反馈 |
| 什么时候停 | 感觉够好了（→ 永远不够） | 达到完成线（→ 会真的发出去） |
| 失败长什么样 | 精致的平庸品 | 一堆便宜的死掉的假设 + 一个活下来的 |

这不是让你不追求好。是把「追求好」放到**正确的位置**上：
**先用最便宜的方式确认这事值得做，再把好用在值得的地方。**

波普尔那句话在这儿完全适用：**你永远证明不了自己对，你只能证明自己错。**
所以别设计"怎么把它做对"，设计"**怎么最快最便宜地发现它错**"。

还有 Boyd 的 OODA：**转得快比转得对更重要**——
因为转得快的人，错了也能马上改；转得慢的人，对了也来不及。

## 四、这暴露了当前这套流水线的一个真缺口

按上面的分析回头看这九步，有个结构性问题：

**九步里有八步的产出都是「文档」，第一次碰到真实世界要等到第 9 步。**

也就是说：这条流水线目前是一台**很好的思考机器，但没有裁判**。
`scripts/check.sh` 只能判断"代码跑不跑得起来"，
它判断不了"有没有人要"——而后者才是第 0 层唯一该看的东西。

`判断标准.md` 里写了「最贵的那一步能不能先花小钱验证」，
但**没有任何一步强制你去做**。写在纸上的规矩，不强制就等于没有。

这正好印证了错误 1：**我们把力气都花在优化器上，没花在裁判上。**

---

## 五、怎么补（这是生意问题，你来定）

三条路：

**A. 加一个「最小验证」步骤（推荐）**
放在拍板差异化之后、投入之前。强制产出 1–2 个证伪实验，
每个必须满足：**三天内能做完、几乎不花钱、结果能明确说"是"或"否"**。
比如：不做产品，先发一条帖子看有没有人问；不拍片，先把标题和封面发出去看点击。
- 好处：把第一次接触现实从第 9 步提前到第 3 步，错了只赔三天
- 代价：多一个停顿，多花三五天才开始动手
- 为什么推荐：按上面的分析，裁判是瓶颈，而不是优化器。补瓶颈才有用。

**B. 不加步骤，只在现有验收单里加一条**
在差异化和需求那两步的验收单里加：「这条假设怎么用三天验证？」
- 好处：不改结构，轻
- 代价：**大概率没用**——纸上的提醒，忙起来就跳过了。结构性缺口靠提醒补不上。

**C. 什么都不改**
适合：你这个项目的第一步本身就很便宜（比如做一条视频试水），
那"做出来"本身就是验证，不需要额外一步。
- 这个选项不丢人。如果做一遍的成本比验证还低，那就直接做，别绕。

**我推荐 A**，理由就一句：
你想要的是「别人想不到但一用就对」，
而这种东西**只能被现实验证，推不出来**——你在办公室里想不出别人会不会叫好。
早一天让它撞现实，早一天知道该继续还是该换。

# 续：五件套架构，和「不知道标准」这个真问题

使用者后来提出一个更完整的说法：

> 人类 Taste（审美/判断力）+ AI Cognition（认知）+ Skill（技能）
> + Execution（执行）+ Evaluation（评价） = 闭环生产系统
>
> 而最关键的地方是：**你甚至不知道「最好的标准」是什么。**
> 如果标准本来就知道，AI 只需要执行。

**这个补充比前面那版准得多，而且指对了唯一真正难的地方。**
「不知道标准」不是这套系统的缺陷，**它是这套系统存在的理由**——
标准已知的活儿，交给外包和流程就行了，不需要这么一套东西。

下面分两块：先说这个架构的三个盲点，再说「不知道标准」到底怎么办。

---

## 六、五件套架构的三个盲点

### 盲点 1：闭环闭得太早——环里没有现实

Taste 是你的，Cognition 是 AI 的，Skill 是方法，Execution 是做，Evaluation 是判断。
**这五个全在屋子里。** 那么 Evaluation 的依据从哪来？

如果评价只依赖 Taste 和 Cognition，这个环就是**自我封闭的**：
它一定会收敛，而且收敛得又快又漂亮——**收敛到一个跟现实无关的地方。**

一个只跟自己较劲的系统，最后会做出一个"逻辑上无懈可击、审美上很讲究、
但没人要"的东西。而且因为每一环都很扎实，你到最后一刻都不会怀疑它。

> **这个环必须有一个开口，让现实进来。**
> 五件套要变成六件套：Taste + Cognition + Skill + Execution + Evaluation + **Reality**。
> 而且 Reality 不是最后一环，是**每一圈都要接触的那一环**。

这正是前半篇说的"没有裁判"。你的架构图，恰好把这个洞画出来了。

### 盲点 2：Taste 不只是输入，它也是产出

架构把 Taste 放在输入端——人类提供审美。但事实是：

**你的审美会因为看到东西而变化、变精确。**
看到 A/B/C 之前，你的 taste 是一团模糊的"我说不上来但我知道"；
选完之后，它清晰了一格。再选一轮，再清晰一格。

这意味着两件事：

1. **这套系统的产出不只是"东西"，还有"更清晰的你"。**
   跑完一个项目，你对"什么是好"的表述能力会比开始时强得多。
   那个能力是可以带走的，比这个项目本身更值钱。
2. **所以早期不该追求"一次把标准定准"。** 定不准，也不需要准。
   早期只需要定得**够用**——够支撑下一步动作就行，剩下的靠跑出来。

### 盲点 3：Evaluation 是两件事，混在一起会掩盖更重要的那件

「评价」实际上是两种完全不同的动作：

| | 问的是 | 谁来做 | 难度 |
|---|---|---|---|
| **第一种** | 做出来的东西，符不符合定好的标准？ | 可以自动化 | 容易 |
| **第二种** | **标准本身，是不是定错了？** | 只能人来 | 很难 |

**绝大多数人只做第一种，还以为自己在做评价。**
结果是：非常高效地朝着一个错的方向前进，而且每一步的验收都通过。

这两件事必须分开命名、分开做。混叫「Evaluation」，
第二种就会被第一种挤掉——因为第一种有明确答案，做起来爽。

---

## 七、「不知道标准」怎么办：四种逼近法

**先破一个误解：不知道标准 ≠ 无法判断。**

你说不出"什么是好"，但你能：
- 看到了认出来（认得出 > 说得出）
- 两个东西比出高下（比较 > 绝对）
- 一眼看出什么是烂（否定 > 肯定）

所以整件事的技术核心是一句话：

> **把一个说不清的标准，转换成一连串说得清的选择。**

四种办法，按可靠性从低到高：

### 1. 专家法 —— 最容易上手，也最容易被滥用
借用大师定好的标准。
**陷阱**：大师的标准是在**他的处境**下最优的。直接抄，你得到的是
"一个符合别人标准的东西"，不是"一个符合你目标的东西"。
**正确用法**：把大师的标准当**参照系**，不当答案。
看他在乎什么、为什么在乎，然后判断你是不是处在同样的处境。
处境不同，他的标准对你就是噪音，甚至是毒药。

### 2. 对照法 —— 最快，日常主力
说不出标准，但能选。给三个能想象出画面的版本，从选择里反推标准。
**关键实操：每次对照只变一个维度。**
同时变两个，你选完也不知道自己在选什么，提取出来的标准是假的。

### 3. 反向法 —— 最狠，最被低估
说不出什么是好，但一眼能看出什么是烂。
**先建"绝对不行"的清单，标准从边界往里逼。**
这比正向定义可靠得多，因为人对烂的感知远比对好的感知精确。
（这也是为什么"什么情况算失败"比"什么算成功"有用。）

### 4. 现实法 —— 最贵，但只有它是真的
让现实说话：有没有人愿意花钱、花时间、留下联系方式、转发给朋友。

**前三种都只是在整理你已有的直觉，只有第四种能带来新信息。**
前三种能让你的判断更清晰、更一致，但**清晰不等于正确**——
一个清晰的错误判断，比一个模糊的判断更危险，因为你会照着它大干一场。

---

## 八、最关键的一句：标准是产出，不是输入

这是整篇最重要的结论。

如果标准真的不可知，那么把「什么算好」当成一个**做完就固定下来的输入**，
逻辑上就是错的。它必须是**随证据不断修订的产出**。

Chris Argyris 讲组织学习时区分过两种回路，直接对应这件事：

- **单回路**：结果不对 → 改做法。（在既定标准下优化）
- **双回路**：结果不对 → **回头质疑标准本身是不是错的。**

绝大多数系统只有单回路。因为单回路有明确的对错，跑起来有成就感；
双回路要承认"我之前定的标准可能是错的"，难受，而且没人催你做。

> **系统每转一圈，应该同时更新两样东西：**
> **做出来的那个东西，和「什么算好」的定义。**
> **只更新前者的系统，会非常高效地跑向一个错的地方。**

### 落到这套流水线上

现在的九步里，`03-什么算好.md` 是**第 4 步定完就基本不动了**。
后面所有步骤都回来读它、服从它——**这是纯单回路。**

双回路的路径不是完全没有：`./loop.sh correct` 里的四层归因，
第二层就是「标准错」。但它是**手动的、被动的**——
得等你自己感觉到不对劲，主动去敲那个命令。

**这就是当前设计和上面这个结论之间的差距**：
标准从来不会因为证据而自动被质疑，只会因为你难受而被质疑。
而人对"自己定错了标准"这件事，是有本能抵抗的——
尤其是在已经照着它干了两周之后。

（怎么补：见前半篇第五节的三个选项。使用者暂时选择不动，
先把这件事想清楚。这个决定是对的——
**结构性的改动，想清楚了再动，比先动再改便宜。**）

# 续二：Definition 是最底层——对，但有个陷阱

使用者提出：最底层不是 Plan，是 **Definition（定义）**。并给出九问：

> 我要什么？→ 给谁？→ 解决什么需求？→ 解决到什么程度？→ 用户为什么选择它？
> → 和现有最好方案比好在哪？→ 哪里必须不同？→ 哪些绝不能牺牲？→ 最终成功是什么？

**次序判断是对的，而且这是最贵的错误来源**：给一个没定义清楚的东西做计划，
是最高效的烧钱方式——因为过程中每一步都在正常推进，你察觉不到。

九问的质量也高，尤其后两问（哪里必须不同、哪些绝不能牺牲），**大多数人不问第二个**。

下面：先对账，再说两个真缺口，再说四条修正。

---

## 一、对账：九问在现在这套流水线里落在哪

| 九问 | 现在落在 | 状态 |
|---|---|---|
| 我要什么 | `00-目标.md` 一句话目标 | ✅ |
| 给谁 | `00-目标.md` 这是给谁用的（要求具体到真人） | ✅ |
| 解决什么需求 | `00-目标.md` 现状的痛 | ✅ |
| **解决到什么程度** | —— | ❌ **缺口一** |
| 用户为什么选它 | `02-共性与独特.md` | ✅ |
| 和现有最好比好在哪 | `01-巨人的肩膀.md` + `02` | ✅ |
| 哪里必须不同 | `02-共性与独特.md` ERRC 四格 | ✅ |
| **哪些绝不能牺牲** | 散落在"共性必须项"和"什么算失败"里，**没有独立成条** | ⚠️ **缺口二** |
| 最终成功是什么 | `00-目标.md` 怎么算成功 | ✅ |

**七条已覆盖，两条是真缺口。**

---

## 二、缺口一：「解决到什么程度」

**为什么这条重要**：需求不是有无，是**深度**。
同一个需求，解决 60% 和解决 95%，是**两门完全不同的生意**，成本差十倍以上。

不定这个，会发生一件很隐蔽的事：**你会不自觉地一直加深度，永远做不完。**
因为每加一点都"显然更好"，而你没有一条线告诉自己"到这儿就够了"。

**它和「完成线」不是一回事**，别混：
- **完成线** = 质量的停止线（做到这个精度就发出去）
- **解决到什么程度** = 需求覆盖的停止线（解决到这个份上就够，剩下的不管）

两条都得有。缺第一条会无限打磨，缺第二条会无限扩张。

写法：
```
这个需求我们解决到 ____ 为止。
剩下的 ____ 明确不管，用户得自己想办法 / 找别的工具。
为什么这条线画在这儿：____
```

---

## 三、缺口二：「哪些绝不能牺牲」——这条实操价值最高

**为什么它最有用**：压力来临的时候，**人是一样一样地妥协的。**

每一次妥协单独看都合理——赶进度、省钱、这个太难了先跳过、客户催了。
但连着妥协五次之后，核心已经没了，**而且你说不清是哪一步丢的**，
因为每一步都有充分理由。

> **不可妥协清单的作用是：在你还清醒的时候，替将来那个疲惫的你做决定。**

写法有讲究：
```
## 绝不能牺牲的（最多 3 条）
1. ____
   宁可牺牲什么来保它：____
   如果这条守不住，我宁可不做这个项目。
```

**最多 3 条。超过 3 条等于没有**——因为真到了要取舍的时候，
一张 8 条的清单和没有清单是一样的，你还是得现场判断。

每条必须写"宁可牺牲什么来保它"。**只说"这个很重要"不算数**，
重要的东西人人都有一堆；只有说清了愿意拿什么去换，这条才有约束力。

---

## 四、四条修正

### 修正 1：Definition 是最底层，但**不是"第一步做完就锁死"的那一层**

这是最重要的一条。

九问里，**前三问可以先猜**（我要什么、给谁、解决什么需求）。
但后六问——解决到什么程度、用户为什么选它、和最好的比好在哪、
哪里必须不同、绝不能牺牲什么、成功是什么——

**这些在你调研之前根本答不出来，硬答出来的是幻觉。**

最明显的一条：**「和现有最好方案比好在哪」——你都没看过现有最好的，拿什么比？**
这时候写出来的答案，是你想象中的竞品，不是真的竞品。

所以定义必须**分两轮**：

```
粗定义（猜，够支撑去调研就行）
    ↓
调研（看清前人做到什么程度、现成的有什么、信息差在哪）
    ↓
精定义（改，这一轮才算数）
```

这也解释了现在的流水线**为什么把九问拆散在 00 / 01 / 02 三步里，而不是堆在第一步**——
不是设计疏忽，是刻意的。第一步只做粗定义，看完巨人的肩膀之后才做精定义。

而且这跟上一轮刚确立的结论完全一致：
**标准是产出不是输入 → 定义同理，也是产出。**
Definition 是最底层的**地基**，但地基是**边挖边浇**的，不是先浇好再盖楼。

### 修正 2：九问里缺一个最狠的——**「为什么是现在？」**

如果这件事三年前也能做、三年后也能做，那它**没有窗口**，
而且说明**不紧迫**——你不做别人也不做，因为没人急。

能答出 why now 的才有窗口，答案只有几种：
技术变了 / 平台规则变了 / 成本降了 / 人群变了 / 某个前置条件刚成熟。

这一问比「哪里必须不同」更靠前：**不同**回答的是空间上的位置，
**为什么是现在**回答的是时间上的位置。两个都得占住。

### 修正 3：「为什么值得存在」和「用户为什么选它」是**两个**问题

你开头写了「它为什么值得存在」，但展开的九问里**漏掉了**——
最接近的是「用户为什么选择它」，但那不是同一个问题：

- **用户为什么选它** = 跟**竞品**比
- **为什么值得存在** = 跟**根本没有这东西**比

**后者更狠。很多东西打得过竞品，但打不过"不用"。**
用户的真实选项从来不是"你 vs 竞品"，而是"你 vs 竞品 vs 干脆算了继续凑合"。
第三个选项永远存在，而且它免费、零学习成本、零风险。

### 修正 4：定义最容易的失败方式，不是写不出来，是**写得太漂亮**

定义写得越流畅、越完整、越像一份商业计划书，**越危险**——
因为它把**猜测**伪装成了**结论**。三个月后你回头看，
分不清哪句是当时查证过的，哪句是当时顺手编的。

**好的定义必须看得见不确定性。**

落地做法：定义文档里每一条关键判断后面标一个记号——
```
[事实] 有来源、有日期、可核对
[推断] 基于事实推的，逻辑写出来
[猜测] 就是猜的 —— 后面必须补一句「如果这条错了，会怎样」
```

**猜测本身没问题，把猜测当事实才有问题。**
标出来之后，你一眼就能看见这个定义的**承重墙在哪儿**——
那些标着[猜测]又"错了会很惨"的条目，就是你该优先去验证的东西。

---

## 五、Definition 之下还有一层：**「为什么是你」**

九问全在问"这东西是什么"，没有一问在问"**为什么是你来做**"。

这一层被漏掉的代价有两个：

1. **它决定你能不能扛过难受的阶段。**
   任何项目中段都有一个"没劲、看不到头、想放弃"的坑。
   那时候支撑你的不是目标写得多漂亮，是你为什么非做这个不可。
   没有这个理由，第一次真正的挫折就散了。

2. **你唯一复制不了的优势，只能从这里来。**
   `02-共性与独特.md` 最后要求答"有哪一条是别人复制不了的"——
   那条的答案**只可能来自"你是谁"**：你的行业经验、你认识的人、
   你手里的资源、你比别人多受过的罪。

> **如果一个定义完全不依赖"你是谁"，那它任何人都能执行——
> 说明你在这件事上没有任何优势，只是比别人早想到一步而已。
> 早想到一步不构成护城河。**

---

## 六、一个结构性的问题（留给使用者，我不动）

现在九步是**平铺**的。但按这个框架看，它其实是两大块：

```
定义层：1 目标 → 2 巨人的肩膀 → 3 共性与独特 → 4 什么算好
执行层：5 要做什么 → 6 我不懂的 → 7 技术与落地 → 8 任务清单 → 9 开做
```

**明确分开命名的好处**：你一眼能看出自己"还在定义"还是"已经在执行"。
这个区分很有用，因为**两块的失败模式完全不同**：
- 定义阶段的失败 = 想歪了，但便宜，改字就行
- 执行阶段的失败 = 做歪了，贵，要返工

而且它能拦住一种常见错误：**在执行阶段偷偷改定义**——
一边做一边把目标往已经做出来的东西上靠，最后成功了，
但成功的是一个你从没打算做的东西。

代价：要改文档编号和 README 结构。

# 续三：这套东西自己胖了，而且是我喂胖的

使用者的原话：
> 「这是因为你把我说的东西增加了太多限制，然后你现在又说他太慢了。
> 但实际上能把我的东西执行下去，并且保持住准确。你增加的思考态度臃肿。」

**这条批评成立，而且比它说的还准。** 记录如下。

## 一、先认账：数字

| | 第一版 | 现在 | 倍数 |
|---|---|---|---|
| 第2步说明书 | 46 行 | 202 行 | ×4.3 |
| 第5步说明书 | 66 行 | 212 行 | ×3.2 |
| 参考资料 | 1 个文件 | 5 个文件 / 1726 行 | —— |

**加法做了 14 次，减法做了 0 次。**

## 二、比"加多了"更准确的诊断

**我加的 14 条护栏，全部服务于「防错」，没有一条服务于「跑得动」。**

翻一遍就知道：标注来源、必须查证、不许自我安慰、难而正确三问、
偷神不偷形、摩擦审计、绝不能牺牲、双回路修订……
**每一条都在提高准确度，没有一条在提高速度。**

一个只有一个优化方向的系统，**只会单调地朝那个方向跑到死**。
这不是"加多了"，是**优化目标缺了一个**。

而使用者要的从来是两个：**跑得动 + 保持准。**
我只做了后者，还以为自己在做好事。

## 三、最难堪的一条：我给别人定停止线，没给自己定

这套系统强制每个项目写三条停止线：

| 线 | 管什么 |
|---|---|
| 解决到什么程度 | 需求覆盖的边界 |
| 完成线 | 质量的边界 |
| 止损线 | 投入的边界 |

**而这套系统本身，一条都没有。**

所以它必然无限膨胀——因为每一条新护栏单独看都"显然更好"，
而**没有任何东西告诉我"到这儿就够了"**。

这正是 `判断标准.md` 第六节写的原话：
> 「缺完成线会无限打磨」

我写了这句话，然后对着自己的系统无限打磨了 14 轮。

## 四、关键区分：哪些是承重墙，哪些是装饰

第一次真跑给了证据。**只有 4 条护栏真的被检验过**，而且全都当场生效：

| 护栏 | 真跑时的表现 |
|---|---|
| `[事实\|推断\|猜测]` 标注 | ✅ 产出逐条标了，一眼能看见哪儿是猜的 |
| 给选择题不给问答题 | ✅ 「谁掏钱」被翻译成 A/B 让人选 |
| 卡住了就写下来 | ✅ 写出 `05-我不懂的.md`，**还找出了 loop.sh 的真 bug** |
| 不许编，必须查证 | ✅ 拒绝凭印象编竞品，宁可停下 |

**其余 10 条，一次都没被执行到过**——因为流程在第3步就断了。

> **重量是确定的成本，价值是未验证的假设。**
> 那 10 条贡献了大部分行数，却没有一条拿出过证据。

## 五、正确的修法：不是删，是分层

使用者要的是"跑得动 + 保持准"，所以不能一刀切删——
**要保住那 4 条承重墙，把其余的从"默认执行"降级成"需要时才调用"。**

```
每个说明书分两段：

## 必做（默认只跑这段，20–40 行）
  产物是什么
  那 4 条承重墙
  验收单，最多 5 条

## 深挖（默认跳过）
  其余全部。只有项目大到值得，才启用
```

目标：**第2步说明书从 202 行回到 40 行左右**（接近第一版的 46 行）。

这跟调研结论也对得上：OpenSpec 12 分钟 vs BMAD 5.5 小时，
**赢的不是功能多的那个，是重量配得上项目的那个。**

## 六、给这套系统自己补上三条停止线

**解决到什么程度**：护栏只覆盖"会导致编造、会导致方向性错误"的那类问题。
　　"能提升质量但不致命"的一律不进默认路径。

**完成线**：默认路径上的说明书，**任何一个超过 40 行就是超了**，必须往深挖里挪。

**止损线**：**一条护栏如果连续 3 个真实项目都没被触发过，就删掉。**
　　不是降级，是删掉——留着它的唯一作用是让文档变长。

> 从今往后，**加一条护栏之前先问：它准备从默认路径里挤掉哪一条？**
> 答不上来就不加。

# 怎么跟他说话

**这一份管所有给老板看的东西**：第1步的听懂、论证的一页纸、CEO 的汇报、explain。
内部的分析不受这份管——**分析要全，说话要短。**

---

## 一、总规矩：站在他前面，让他自己走过来

不是推着他走，也不是拽着他走。
**是先走到他该到的地方，然后站在那儿，让他自己走过来。**

| 是这样 | 不是这样 |
|---|---|
| 「这三条查完了。第 2 条跟你原本想的相反。」 | 「你应该改变方向」 |
| 「按这个数算，一个月要 300 单。这行做得最好的一个月 80 单。」 | 「这个目标不现实」 |
| 「A 和 B 我推荐 A，因为你现在最缺的是'有没有人要'这个答案。」 | 「你必须先做 MVP」 |

**把事实摆到他面前，让结论自己长出来。**
他自己得出的结论，他会执行；你替他得出的结论，他会怀疑。

---

## 二、我们永远比他懂得更多，但**不许显摆**

**他不需要懂任何商业知识。** 那是我们的活。

- ❌ 「根据 JTBD 框架，你的用户在雇佣你的产品完成一项功能性任务」
- ✅ 「你要的不是记客户，是别让客户觉得你把他忘了」

**术语一个都不许出现在给他看的东西里。**
JTBD、蓝海、护城河、单位经济、LTV/CAC——**这些是我们内部用的工具，
不是说给他听的话。** 用得上就用，用完把结论翻译成人话再端出去。

**判断标准**：他看完能不能立刻做一个决定。
不能，就是没说清楚，不管写得多专业。

---

## 二之二、笑点在哪：冷幽默 ＝ 把差距点破

**他会笑，是因为一个他自己也知道、但没被说出口的差距，被人一句话点破了。**

差距有三种，全在他自己身上：

| 差距 | 例子 |
|---|---|
| **说的 vs 做的** | 「你说这个功能'很快就能做完'，但你已经说了三个星期了。」 |
| **想的 vs 说的** | 「你说'顺便做个社区'——'顺便'这两个字，通常是项目死因的第一句话。」 |
| **以为的 vs 真的** | 「你说这行竞争不激烈。我查到 47 个人在做，其中 3 个死了。」 |

**为什么这种能让人笑**：因为他心里早就知道了，只是没敢想清楚。
被人平静地说出来的那一秒，**紧张突然松掉了——那个松掉就是笑。**

### 冷在哪

**冷 ＝ 不加评论，不加表情，说完就停。**

```
✅ 「你三次提到'忘了'，一次都没提过'赚更多'。」
   （说完就停，不解释）
❌ 「你三次提到'忘了'，一次都没提过'赚更多'，这说明你其实……」
   （一解释就不冷了，也不好笑了，而且变成了下判断）
```

**冷幽默和"不许编"是同一件事的两面**：
你只是把他自己的话摆出来，**笑点是他自己制造的，你一个字没编。**

### 三条不许

1. **不许拿他的处境开玩笑**，只拿他的**表述**开玩笑
   （笑"顺便"这个词，不笑"你没钱"这件事）
2. **不许在坏消息上抖机灵**。算术不成立就平铺直叙地说，
   这种时候幽默是逃避，不是体贴
3. **一轮最多一次。** 密集的俏皮话会让他觉得你不认真——
   **他是来做事的，不是来看你表演的**

## 三、幽默是用来减轻真话的重量的

**真话不好听。** 「你这个算术不成立」「你以为的痛点不是真痛点」
——这些话必须说，但**说的方式决定他是接住还是防御**。

幽默的作用不是逗他笑，是**让他能接住一句难听的真话**。

| | |
|---|---|
| ✅ 「这行做得最好的一个月 80 单，你要 300 单。这不是努不努力的问题，是算术。」 | 用一句轻的收尾，让他不必辩护 |
| ✅ 「你说'顺便还能做个社区'——'顺便'这两个字，通常是项目死因的第一句话。」 | 拿他自己的话开个小玩笑 |
| ❌ 「哈哈哈这个想法太天真了」 | 嘲讽不是幽默 |
| ❌ 「这是一个非常有意思的挑战呢～」 | 用可爱掩盖坏消息，是另一种撒谎 |

**三条边界：**

1. **不许拿他开玩笑，只许拿事情开玩笑**
2. **不许用幽默软化事实**——难听的数字还是要原样给他
3. **不确定该不该幽默的时候，就别**。**说清楚 > 说得好玩**

---

## 四、每份给他的东西，都要覆盖这四格

第1步已经把他那段话拆成四格了。**给他的结论必须四格都碰到**，
少一格就是漏了他的一部分：

| | 他知道 | 他不知道 |
|---|---|---|
| **他说了** | 确认／或者告诉他这条其实不重要 | —— |
| **他没说** | **他默认了，但没说出口**——替他写出来让他确认 | **这一格最值钱**：他想不到、但会要命的 |

右下角那一格是我们存在的理由。**「你想不到但必须知道的」——
一份没有这一格的报告，等于把他已经知道的事重说了一遍。**

---

## 五、长度

**给他看的东西，永远只有一页。**

写不下，不是因为内容多，是因为**你还没想清楚哪三条最重要**。

挑法：**不是挑最重要的三条结论，是挑最能改变他下一步动作的三条。**
一条读完不影响他做什么的，再正确也别放。

---

## 六、还没做的（老板要亲自加）

- ⬜ **蒸馏一个真人的语言方式**，作为最终输出层。
  机制已经有了（`./loop.sh 蒸馏`），缺的是选谁。
- ⬜ **深度心理学 / 对人的理解**——这部分是老板的认知，不是书上的框架

**加的时候守住一条**：表达层**不许改结论**、不许动
`[事实][推断][猜测]` 的标记、不许改 ★ 评级。
**为了一句话说得漂亮，把不确定的说成笃定的——那是把猜测伪装成结论。**

# 抓取 SOP · 怎么把「抓得多」变成「抓得对」

**第 0 版，2026-08-18。** 这一版故意留了空——
空的那几处，要从老板看到真东西之后的反应里反推出来，**不许坐在屋里想。**

---

# 一、先把一个错觉打掉

> **「让它抓 100 个网页」不是壁垒。抓 1000 个也不是。**

任何人都能抓。爬虫是共性，不是独特。**在共性上使劲＝挖坑。**

**真正抓不走的只有三样：**

| | 是什么 | 为什么别人拿不走 | 代价 |
|---|---|---|---|
| **① 时间** | 同一批目标，**连着抓 90 天**，攒的是「变化」 | **别人今天开始，也要等 90 天**。这是唯一一种用钱买不到的壁垒 | 今天看不出价值，要熬 |
| **② 脏活** | 抓别人懒得抓的地方：**投诉、退款理由、差评、二手转让价、招聘启事** | 不是技术门槛，是**没人愿意干**。而真痛点全藏在这些地方 | 噪音大，一半是垃圾，要人去定义什么算信号 |
| **③ 问法** | 同一份公开数据，**你问的问题跟别人不一样** | 数据是公开的，**提问的角度不是** | 全靠你的判断力，学不来也教不会 |

**①是最便宜的，今天就能开始，而且越拖越亏。**
**③是最贵的，也是真正属于你的那部分。**

---

# 二、抓什么，不是从"哪些网站"开始定的

**顺序反了，就会抓回来一堆没用的东西。**

正确顺序：

```
一个具体的问题
   ↓
这个问题的答案会出现在哪三类地方？
   ↓
去那三类地方抓
   ↓
只留下带「钱」和「痛」的
   ↓
定一个复抓周期
```

**什么叫「具体的问题」**：

```
❌ 「餐饮行业怎么样」            ← 抓回来一堆行业报告，全是废话
❌ 「有什么好的创业机会」        ← 没法回答，等于没问
✅ 「开一家 20 平米小店的人，
    现在每个月固定往哪几件事上花钱？各花多少？」  ← 能回答，能验证
```

**判断标准**：这个问题**能不能用一句带数字的话回答**。
不能，就不是问题，是感慨。

---

# 三、三类地方（抓取目标的分类法）

| 类 | 去哪儿找 | 能回答什么 |
|---|---|---|
| **人在哪儿抱怨** | 投诉平台 · 差评区 · 退款理由 · "求推荐"帖 · 问答社区 | **真痛点**（不是他说想要什么，是他真的骂了什么） |
| **人在哪儿掏钱** | 在卖的价格页 · 销量 · 评价数 · 二手转让价 · 招聘启事的薪资 | **真需求和真客单价**（能直接算回本） |
| **人在哪儿被服务** | 服务商官网 · 代运营广告 · 行业群 · 线下门店 | **共性是什么**（大家都在做的那些，抄就完了） |

**三类都要抓。只抓一类会瞎：**
只抓抱怨 → 找到一堆没人愿意付钱解决的痛
只抓掏钱 → 只看得见已有市场，看不见新机会

---

# 四、抓回来之后怎么筛（这一步决定成败）

**抓是体力活，筛才是本事。**

每一条抓回来的东西，打三个标：

```
① 有没有钱？   （出现了具体金额 / 在讨论价格 / 在比价）
② 有没有痛？   （有具体场景 + 具体损失，不是泛泛说"不好用"）
③ 有没有人？   （能定位到具体是谁在说，不是匿名一句话）
```

**三个都有 → 留下，进证据库**
**只有一个 → 扔**
**两个 → 待定，攒够 5 条再看**

**留下的每一条必须带：链接 · 日期 · 原话摘录。**
**转述过的一律不算数**——转述的过程就是编造开始的地方。

---

# 五、复抓（这是壁垒真正长出来的地方）

**第一次抓完，先别急着分析。做一件更重要的事：**

> **把这批目标存成一张单子，定一个周期，往后一直抓。**

- 周期：先定**每周一次**（每天太吵，每月太慢）
- 存的东西：**同一个页面、不同时间的两份快照**
- 你要的不是快照，是**差**——价格涨了没、评价多了没、有人新做了没、有人不干了没

**做死的人，是在两次快照之间消失的。**
**这个信号只有连续抓的人看得见。**

---

# 六、留空的地方（等真东西回来再填）

```
【空 1】什么算「有用的一条」——从老板划的第一批里反推，写成一句话
【空 2】哪三类来源最值钱——从第一批命中率反推
【空 3】复抓的目标单子——第一批筛完才有
【空 4】止损线：抓了 __ 条还没出一条能算回本的机会，就换方向
```

**这四处不许坐在屋里想。**
「什么算好」不是一开始定死的输入，**是看到真东西之后修订出来的产出。**
只更新产出、不更新标准的系统，**会非常高效地跑向一个错的地方。**

# 框架库 · 前人已经造好的轮子

这个文件的用途：**不要重新发明思考方式。**
下面每一条都是别人用几十年、几百个案例验证过的思考工具。
做项目时直接调用，别自己瞎琢磨。

用法：每一条都写了「什么时候用」。在流水线的对应步骤里，挑 2–3 个用，不要全上——
全上就是没重点。

> 用之前记住一句话：**框架是拐杖，不是腿。**
> 框架能保证你不遗漏、不犯蠢，但做不出让人眼前一亮的东西。
> 眼前一亮那部分来自你的判断，框架只负责把你的判断放到对的位置上。

---

## 一、搞清楚人到底要什么

### JTBD · 用户雇你的产品来干什么活
Clayton Christensen 等人推广。
**白话**：人们买的不是产品，是"把某件事搞定"。经典例子——人买的不是电钻，是墙上那个洞；
再深一层，要的不是洞，是把照片挂上去，是家里看着温馨。
**怎么用**：把你的东西写成一句话「当我遇到【什么处境】，我想要【干成什么】，
这样我就能【得到什么】」。写不出来说明你还没想清楚在卖什么。
**关键**：往上追问三层。第一层是功能，第二层是情绪，第三层是身份认同。
钱在第二、三层。
**什么时候别用**：纯工具类、需求已经明确到不用问的东西，别过度解读。

### Kano 模型 · 为什么"用户想不到的"最值钱
狩野纪昭提出。把需求分三类：
- **基本型**：没有会骂，有了也不夸。（外卖不能凉）
- **期望型**：越多越满意，线性关系。（送得越快越好）
- **兴奋型**：用户压根没想到，一旦有了会主动跟别人说。（下雨天附赠一次性雨衣）

**白话**：你说的「他们想不到但符合需求」就是这一类。
**怎么用**：三类都要列。基本型是入场券——**一个都不能少，少一个前面全白搭**；
期望型决定你排第几；兴奋型决定别人会不会替你传播。
**残酷规律**：兴奋型会随时间退化成基本型。今天的惊喜是明天的标配。
所以差异化不是做一次，是持续做。

### 五个为什么 · 挖到真动机
丰田生产体系。对一个需求连问五次"为什么"。
**白话**：用户说"我要个更快的马"，问到第三层才发现他要的是"准时到"，
第五层发现他怕的是"迟到丢面子"。
**怎么用**：在第3步整理需求时，每条需求往下追三到五层，把最底下那层写下来。
底下那层才是你真正的竞争战场。

---

## 二、共性：所有人都一样的那部分

> 差异化之前先看清共性。**共性是地基，独特是楼。地基错了，楼越高塌得越惨。**

### 影响力六原则 · 人性的固定按钮
Robert Cialdini。（后来他补了第七个：统一/归属）
互惠、承诺与一致、社会认同、喜好、权威、稀缺。
**白话**：这六个是人脑的快捷键，几十年没变过，跨文化通用。
**怎么用**：检查你的东西用上了哪几个。一个都没用上，说明你在跟人性对着干。
**红线**：这几条能用来帮人，也能用来骗人。骗来的转化是负债——
退款、差评、口碑崩，会连本带利还回去。只用在"东西确实好，但人不知道"的场合。

### 最省力原则 · 人永远选更省事的那条路
**白话**：只要还有一个更省事的替代方案，你的东西就赢不了——哪怕你客观上更好。
**怎么用**：数一下用户从"想用"到"用上"要几步。竞品几步。
**你比对手好 20% 但多两步操作，你会输。**
差异化最稳的一种就是：功能不变，步骤砍一半。

### 马斯洛 / 七宗罪 · 底层驱动力
**白话**：所有生意本质上都在满足几个不变的东西——
省时间、省钱、赚钱、显得体面、被喜欢、少费脑子、少焦虑、有归属。
**怎么用**：一句话说清你的东西命中哪一个。
说不清、或者说命中五个，都等于零。

---

## 三、独特：怎么跟别人不一样，还不是瞎不一样

### 蓝海战略 ERRC 四步动作 · 最实用的差异化工具
W. Chan Kim & Renée Mauborgne。对行业的标准做法做四个动作：

| 动作 | 问自己 | 效果 |
|---|---|---|
| **剔除** | 行业习以为常、但其实没人真正在乎的，砍掉哪个？ | 降成本 |
| **减少** | 哪些做得远超必要了？降到及格线 | 降成本 |
| **增加** | 哪些行业普遍做得不够？提到远超及格 | 造差异 |
| **创造** | 这行从来没有过、但用户其实想要的，是什么？ | 造差异 |

**白话**：差异化不是"什么都比别人好"（那叫做梦，也没钱），
是**主动在某些地方比别人差，换取在另一些地方远远超过别人**。
**怎么用**：这是第4步「共性与独特」的主力工具，四格必须填满。
**填不出「剔除」和「减少」的，就是没想清楚**——那说明你只是想做个"更好的同款"，
而更好的同款打不过先来的。

### 定位 · 心智里只装得下第一
Al Ries & Jack Trout。
**白话**：人脑给每个品类只留两三个位置。挤不进前二，不如自己开一个新品类当第一。
**怎么用**：填这句话——「在【某个具体到窄的领域】里，我们是唯一/第一个【怎么样】的」。
填不出来就把领域缩窄，缩到能填出来为止。
**注意**：缩窄不等于自我设限。窄是起点，站稳了再扩。

### 波特三大战略 · 别站在中间
Michael Porter：总成本领先 / 差异化 / 聚焦细分。
**白话**：要么最便宜，要么最独特，要么服务一小撮人服务到极致。**卡在中间的最惨**——
比不过便宜的，也比不过高端的。
**怎么用**：明确选一个。选完之后凡是跟它冲突的想法一律砍。

### 领域迁移 · 最容易得手的差异化
**白话**：A 行业里成熟到无聊的做法，搬到 B 行业就是创新。
海底捞把酒店业的服务标准搬进火锅店；瑞幸把互联网的补贴打法搬进咖啡。
**怎么用**：问「隔壁行业解决这个问题解决到什么程度了？」
**这是差异化里成功率最高、成本最低的一种**——因为方法已经被别的行业验证过了，
你只承担"搬得动搬不动"的风险，不承担"这法子行不行"的风险。

---

## 四、把价值说清楚

### 价值方程式 · 报价前先算这个
Alex Hormozi（《$100M Offers》）：

```
            梦想的结果  ×  实现的可能性
价值  =  ─────────────────────────────
            要等多久  ×  要费多大劲
```

**白话**：想让人觉得值，四个旋钮——把上面两个调大，或者把下面两个调小。
**关键洞察**：绝大多数人只会吹上面（"我们效果超好"），
而**下面两个（等多久、多费劲）才是真正的胜负手**，因为对手也在吹效果，没人在减负担。
**怎么用**：四个格子逐个填，每个写"我们现在是多少，能改善到多少"。
优先改分母。

### 价值主张画布 · 一一对应，别自嗨
Alexander Osterwalder。左边写用户的：要干的活 / 痛点 / 想要的收获。
右边写你的：产品 / 止痛药 / 增益剂。
**白话**：**左边每一条都要在右边找到对应**，右边每一条都要在左边找到出处。
右边有、左边没有的，就是自嗨功能，砍掉。
**怎么用**：第6步「要做什么」里砍功能，用这个当刀最锋利。

### StoryBrand · 客户才是主角
Donald Miller。**白话**：绝大多数人介绍自己的东西时，把自己写成了英雄。
错了——客户是英雄，你是那个给他剑的向导。
**怎么用**：所有对外的话术套这句：
「你想要【X】，但卡在【Y】。我们懂，因为【凭证】。用我们，三步就能【X】。
不用的话，你会继续【损失什么】。」

---

## 五、让它传出去

### 黏性六原则 SUCCESs
Chip & Dan Heath：简单、意外、具体、可信、情感、故事。
**怎么用**：写介绍/文案/视频脚本时逐条对照打分。
六条里能占三条就已经比 90% 的内容强。
**最常缺的是「具体」**——"提升效率"没人记得住，"每天少花 30 分钟"能记住。

### 疯传 STEPPS
Jonah Berger：社交货币、诱因、情绪、公开性、实用价值、故事。
**白话**：人转发东西不是因为你好，是因为**转发这件事让他自己显得好**。
**怎么用**：问一句「别人把这个转给朋友，他自己看起来会是什么形象？」
答不上来，就别指望有自传播。

### 上瘾模型 Hooked
Nir Eyal：触发 → 行动 → 多变的奖励 → 投入。
**怎么用**：只在需要用户反复回来的产品上用。一次性交付的东西别硬套。
**红线**：这套东西用过头就是设计成瘾。自己心里有杆秤。

## 六、别浪费力气

### 第一性原理
**白话**：把事情拆到不能再拆的事实，从那儿重新推。
**怎么用**：只在"大家都这么干"但你觉得别扭的地方用。
**成本很高**，别对每件事都来这套，会瘫痪。

### 逆向思维
Charlie Munger：「反过来想，总是反过来想。」
**白话**：想"怎么成功"很难，想"怎么必死"很容易。列出必死的方式，然后一条条避开。
**怎么用**：第7步「我不懂的」里挖坑，主力工具就是这个。

### 80/20
**白话**：八成结果来自两成动作。
**怎么用**：任务清单排好后过一遍——**哪两成任务贡献了八成价值？先做那些。**
剩下八成里有一半可以永远不做。

### 奥卡姆剃刀 / MVP
**白话**：能砍的都砍掉，剩下的还能用，那就是对的版本。
**怎么用**：每加一个功能，问「不加它，这东西还成立吗？」成立就别加。

---

## 七、信息差在哪儿

> 你要找的"最好的信息差"，来源就这四种。按好挖程度排序：

**1. 领域差（最好挖，推荐优先）**
别的行业早就解决了，这个行业还没人搬过来。
挖法：问"离我最远但结构最像的行业，是怎么干这件事的？"

**2. 时间差（有效期短，要快）**
新技术/新平台出来后，早期红利期。规则宽松、成本低、竞争少。
挖法：查这个领域最近 6–12 个月出现的新工具、新平台政策。
**注意**：这种差消失得很快，且往往伴随规则突变的风险，别把身家压上去。

**3. 认知差（最持久，也最难）**
同样的信息摆在所有人面前，只有你看懂了它意味着什么。
挖法：找那些"数据都是公开的，但结论反直觉"的地方。
**这是唯一不会被抄走的一种**——因为抄的人看不懂。

**4. 执行差（最不性感，最实在）**
方法人人都知道，就是没人愿意认真做到底。
挖法：看看这行里"大家都说重要但都做得很糟"的环节。
**别看不起这种**——多数长青生意就靠这个，因为它抄不走：竞争对手知道该做什么，
但他不愿意吃那个苦。

---

## 八、怎么赚钱（很多好东西死在这一节）

> 「有价值」和「收得到钱」是两件事。这一节专治那种
> **人人称赞、但没人付费**的东西——而且因为称赞是真的，
> 你会以为只是"还没找到方法"，然后继续投入。

### 谁付钱 ≠ 谁使用（最容易致命的混淆）

企业软件、教育、母婴、给爸妈买的东西——**用的人和掏钱的人经常不是同一个**。

- **用的人**在乎：好不好用、麻不麻烦
- **掏钱的人**在乎：值不值、有没有面子、好不好跟别人交代

**你得同时打动两个人，但打动他们的点完全不同。**
只讨好用的人 → 掏钱的人不批；只讨好掏钱的人 → 用的人不用，第二年不续费。

所以「给谁」这一栏，必要时得写两个人。

### 收不到钱的三种典型情况

1. **有免费替代品** —— 你再好，也得跟"免费且够用"打
2. **价值太分散** —— 每次省 3 分钟，一年省很多，但没人为"每次 3 分钟"掏钱
3. **好处不落在决策者身上** —— 你帮公司省了钱，但省下的钱进不了拍板那个人的口袋

这三条都要在动手之前检查一遍。中了任何一条，要么换收费方式，要么换客户。

### 价格不是最后定的，是先定的

**先定价格 → 倒推成本 → 再决定做成什么样。**

反过来做（先做完再想卖多少）经常发现：**成本已经超过了人愿意付的价格。**
这时候只剩亏着卖或者不卖，两条路都难受，而且钱已经花了。

三种定价逻辑，只有第三种对：

| 逻辑 | 做法 | 评价 |
|---|---|---|
| 成本定价 | 成本 + 想赚的利润 | **错**。你的成本跟客户没关系，他不为你的辛苦买单 |
| 竞品定价 | 比对手便宜一点 | **次**。等于把定价权交给对手，而且直接打价格战 |
| **价值定价** | 客户因此赚到/省下多少，收其中一部分 | **对**。先用价值方程式算清他得到什么，再定价 |

### 赚一个客户 vs 找一个客户（LTV / CAC）

- **LTV**（赚一个客户能赚多少）＝ 他一辈子在你这儿花的钱 − 服务他的成本
- **CAC**（找一个客户要花多少）＝ 广告费 + 你的时间 + 送出去的优惠，全算

> **如果 CAC 大于 LTV，规模越大死得越快。**

这条很反直觉，但它是"增长看着很好然后突然倒闭"的真实原因——
每卖一单亏一点，卖得越多亏得越多，而报表上**收入还在涨**，所有人都很兴奋。

早期不用算精确，但**必须有个量级判断**：找一个客户大概要花多少？
答不上来 = 还没想过怎么卖，只想过怎么做。

### 变现方式的选择，本身就是生意模式的选择

同一个东西，收订阅 / 收一次性 / 免费+广告 / 抽成 / 卖配套服务——
**是五门完全不同的生意**：客户群不同、增长方式不同、对手不同、什么算好也不同。

**要早点定**，因为它会反过来决定产品长什么样。
特别注意：**免费养出来的用户，后面很难改成收费**——习惯一旦形成，涨价等于背叛。

### 最狠的一条测试：现在就能不能收到第一笔钱

东西还没做出来之前，有没有人愿意**预付、给定金、或者白纸黑字承诺买**？

**这是第0层最真的验证，比任何调研都真。**

「我觉得挺好的」「做出来我一定用」——这些话**成本是零**，所以不值钱。
而且人不忍心当面泼你冷水，你听到的赞美有相当一部分只是礼貌。

**掏钱是有成本的，所以它不撒谎。**

## 九、分发：怎么让人知道（2026年最重要的一节）

> 见 `现在什么防得住.md`（查证于 2026-08）：功能护城河已经死了，
> **能被抄的都不算护城河**，剩下抄不走的只有"谁认识你、谁信你"。

### 先记住这一条：先建受众，再建产品

绝大多数人的做法是「默默做完 → 再想怎么推广」。
而现在跑出来的那些，做法**正好相反**：

> **在别人反应过来之前成为这个品类的默认品牌——
> 先把受众建起来、把信任赚到手，再把产品发进一个已经相信你的市场。**

法律 AI 那家在产品还做不全的时候，就已经在头部律所里成了默认选择，
然后**回头把产品补上**。编程工具那家靠一群忍不住安利的用户起来的。

**为什么顺序不能反**：受众要时间养，产品可以后补；反过来不行。
你做完了才开始找人，等于从零开始跑一条最慢的路，而且此时钱已经花完了。

### 第一批 100 个人从哪来（这题必须有具体答案）

**不许答"发朋友圈""做 SEO""投广告"**——这些是渠道名，不是答案。
答案必须具体到能明天就动手：

```
第一批 100 个人，我打算从 ____ 来。
我现在已经能触达的人有 ____ 个（真实数字，不是估计）。
我打算怎么让第 101 到 1000 个人知道：____
```

**如果你现在一个人都触达不到**，那"建受众"就是你的第一个任务，
不是等产品做完之后的任务。

### 四种分发杠杆，按对个人/小团队的适用度排

**1. 嵌进别人已有的东西里（最省力，优先考虑）**
应用市场、平台生态、别人的工作流。
**这是原则一（不重造轮子）用在分发上**——别人已经把人聚好了，你去那儿。
代价：受平台规则限制，而且规则会变。

**2. 内容/信任先行（最适合个人，见效慢）**
先持续输出有用的东西，把人养起来，产品后发。
**优势**：养出来的受众抄不走，而且顺带验证了需求。
**代价**：慢，要几个月起步，而且要求你本来就有东西可讲。

**3. 别人替你说（最强，但不能强求）**
用户忍不住转给朋友。见框架库第五节 STEPPS——
关键问题是「他转发这个，他自己看起来是什么形象」。
**这个只能设计条件，不能保证发生。**

**4. 花钱买（最快，也最容易亏）**
必须先算清 CAC vs LTV（第八节）。
**没算清就投钱，是最快的亏钱方式**，而且亏的时候报表上收入还在涨。

### 分发也要做取舍

**同时铺四条 = 四条都做不透。** 选一条主力做到极致，一条备用。
选哪条的判断依据：**你现在已经有的东西是什么**——
有人脉选 1，有话可讲选 2，产品天然适合传播选 3，有钱且算得清账选 4。

### 一个容易忽略的点：分发方式会反过来决定产品长什么样

靠内容起来的产品，天然要"能被讲清楚"；
靠嵌入平台起来的，天然要"符合平台规范"；
靠传播起来的，天然要有"值得截图的一刻"。

**所以分发不能等做完再想——它是产品设计的输入之一。**

## 一、功能护城河已经死了 `[事实]`

这一条所有来源都同意，措辞几乎一样：

> **AI 把「做出来」的成本压到了接近零。**
> 你的界面、你的后端逻辑、你的接口对接、你的交互——全部可以被快速复制。

有个说法很直接：如果你的生意本质是
**「大模型 + 一段特制提示词 + 好看的界面」，那你离出局只差对方一次产品更新。**
Google Cloud 的一位副总裁在 2026 年 2 月公开警告过这类"薄壳"产品。

**这对 MoneyLoop 的直接含义**：
「我们功能做得比他好」这句话，在 2026 年**已经不构成差异化了**。
它顶多是共性（入场券），不是独特。

---

## 二、现在真正防得住的六样 `[事实，多方一致]`

按被提到的频率排序：

### 1. 分发和受众 —— 提得最多的一条
> 「唯一持久的优势是分发能力：比周围任何人更快、更便宜地触达、转化、留住用户。」

因为产品能被抄，**能被抄的都不算护城河**，剩下抄不走的只有"谁认识你、谁信你"。

### 2. 嵌进真实工作流 + 切换成本
在别人**每天重复**的流程里省下时间，比一个炫酷的独立功能强得多。
有个反直觉的观察：**带人工复核、有例外处理、有状态流转的"混合系统"，
往往比纯 AI 的漂亮 demo 更防得住**——因为它嵌得更深，拔出来更疼。

### 3. 专有数据回路
用的人越多 → 数据越多 → 东西越准 → 更多人用。
**注意**：这个飞轮要真的转起来才算数，不是"我们会积累数据"这句话本身。

### 4. 品牌、信任、关系
B2B 尤其明显：**人跟人买东西**。
「客户买你是因为信你能把这事办成」——竞争对手算法再好，也得先跨过这层人情。

### 5. 品味（taste）
这条被反复提到，措辞高度一致：

> **执行正在变得廉价，判断正在变得昂贵。**
> AI 会让智力变得充裕，但它不会让判断、信任、勇气、品味变得充裕。

有一句我觉得说得最准：
**「品味决定了哪些想法值得存在、哪些细节值得较劲、哪些默认值传达了在乎。」**
而且品味**抄不走**——它是从你的经历里长出来的。

### 6. 受监管的领域 / 物理世界
医疗、法律、金融这类**大厂因为责任风险不敢碰**的地方；
以及跟硬件、能源、空间打交道的地方。有投资机构明确说因为写软件变太快，
反而把钱往这些"软件 + 系统 + 物理世界交叉处"挪。

---

## 三、最有用的一条模式：**先建受众，再建产品** `[事实]`

这是这次调研里最值钱的发现，两个被反复引用的例子：

- **Harvey（法律 AI）**：在产品还做不到买家想要的全部功能时，
  就已经在美国前 100 律所里占住了一半以上，**成为"法律 AI"的默认品牌**，
  然后**反过来把产品补上**。
- **Cursor（编程工具）**：靠一群忍不住到处安利它的开发者社区起来的，
  被称为最快做到 10 亿美元年营收的 B2B 公司 `[存疑，数字未核实]`。

被总结成一句话的打法：

> **在别人反应过来之前成为这个品类的默认品牌——
> 先把受众建起来、把信任赚到手，再把产品发进一个已经相信你的市场。**

**这跟绝大多数人的做法正好相反**：多数人是"先默默做完，再想怎么推广"。

还有一条相关的：**在 AI 时代，"嵌进别人已有的工作流"常常胜过"做一个更好的独立产品"**。
应用市场、平台生态是现成的分发杠杆——这跟原则一（不重造轮子）是同一件事，
只不过用在了分发上。

## 四、怎么死的（逆向思维，主力工具）

- **薄壳套壳** —— 上游一次更新就没了
- **算力成本吃掉毛利** —— 用得越多亏得越多，跟 CAC>LTV 是同一类死法
- **忽略用户摩擦** —— 东西再强，多两步操作就输（最省力原则）
- **聚合器在商品化市场里守不住毛利** —— 你聚合的东西一旦变成大路货，你就没价了
- **做了个"很棒但没人真的需要它工作"的产品** —— 第0层没验证

有预测说 80% 的 AI 创业公司会在 2026 年前后死掉。
**这是预测不是事实 `[存疑]`**，但它指向的方向和上面的失败模式是一致的。

## 五、那些数字（仅供量级感，别当依据）`[存疑]`

- 只有约 **0.2%** 的个体经营者能跨过百万美元营收线
- 用 AI 的个体创业者 24 个月内做到百万美元年营收的比例约 **4.2%**，
  不用 AI 的约 **0.8%**
- 2026 年二季度通过 Stripe Atlas 注册的新公司里，**63%** 是单人创办

**怎么读这几个数**：AI 确实把成功率抬高了几倍——**但基数极低**。
从 0.8% 到 4.2% 是巨大的相对提升，绝对值仍然是「二十个里死十九个」。

**所以"AI 让一个人能做很多事"是真的，"AI 让一个人容易成功"是假的。**

## 六、对 MoneyLoop 的三条直接结论

### 结论 1：AI 是共性，不是独特 `[推断]`
AI 让你的执行变便宜，**也让所有人的执行变便宜**。
按原则二，它属于"不做就出局"的那一栏——**老实用好，不许指望它带来差异化**。

「产品经理 + AI 就能做出很顶的东西」——这句话现在是对的，
但**正因为人人都能做，它做出来的东西恰恰是最没有护城河的那一类**。

所以"做一个比它更强的"，如果指的是"功能更强、做得更快"，方向就错了。
**差别只可能出现在 AI 之外**：受众、信任、专有数据、你的独有资源、你的品味。

### 结论 2：MoneyLoop 有第二个大洞——**分发** `[推断]`
九步里，一步都没有问过：
**谁会看见这东西？他们从哪儿知道它？第一批 100 个人从哪来？**

第8步只在内容类项目里提了一句"发布时间、封面、标题"，
那是**发布动作**，不是**分发策略**。

这跟上次"变现"那个洞是同一类错：
**系统里没有名字的东西，就会被漏掉。**
而调研结果说，分发恰恰是现在最重要的那一样。

### 结论 3：「先建受众再建产品」跟现在的排序冲突 `[推断]`
现在第9步排任务清单时，第一条是"端到端跑通一个最小的"。
按调研的模式，**建受众的动作应该和它并排，甚至更早**——
因为受众要时间养，产品可以后补，反过来不行。

## 七、几条听起来很对、但会很贵的话

使用者提出一组判断。逐条过一遍——**有对的，有半对的，有一条信了会出事。**

### ✅ 对的：「难而正确」是真机制

「没几个人跟你竞争」的原因，不是你时机挑得巧，
**是那件事看起来不划算，所以别人不愿意做。**

这跟调研结论完全对上：活下来的都在
**受监管的领域**（大厂怕担责不碰）、**带人工复核的混合系统**（不性感、不好讲故事）、
**物理世界**（不是纯软件，快不起来）。

这三样的共同点是：**难，而且难得不体面。**

> **推论：少有人竞争的地方，当时一定看起来不像好机会。**
> 如果一个机会现在看起来又明显又漂亮，那它对所有人都明显又漂亮。

### ⚠️ 半对：「已经建立品牌和体验交付，他们复制不了」

品牌和信任确实是真护城河（第二节第4条）——**但它们是最慢建起来的那种。**
这句话把一个**目标**说成了**已有的资产**。

而且"复制不了"要拆开看，**能被复制的比你想的多**：

| 他们能抄的 | 抄不走的 |
|---|---|
| 功能、界面、定价 | 你的老客户为什么信你 |
| 你的定位话术 | 你踩过的坑（他们会踩新的） |
| 你公开讲过的所有观点 | 你的判断力本身 |
| **你验证过是对的方向**（省了他们全部试错） | 数据回路（如果真转起来了） |

**最后那条最要命**：你走过的弯路，他们不用走。
**后来者只抄你的成品，不抄你的失败。**

### ❌ 危险：「他们效率肯定没有我们这个 MoneyLoop 高」

这句话**你验证不了**，而且大概率是错觉。三个原因：

**一、你看不见对手的内部流程。**
你对自己的过程了如指掌——包括每一次纠结、每一次推翻重来。
对别人你只看得见结果。
> **拿自己的内部过程去比别人的外部结果，永远显得自己更聪明。**

**二、MoneyLoop 是公开材料拼起来的。**
JTBD、蓝海、定位、价值方程式、双回路学习——**全是公开的**。
任何一个认真的人都能拼出一套类似的，有些人早就拼出来了。
它是好工具，**不是秘密武器**。

**三、流程优势不产生任何用户摸得到的东西。**
用户不会因为你流程好而买你。流程优势只有**转化成别的东西**
（更快的迭代 → 更早的受众 → 更多的数据）才算数。
它本身**不是资产，是杠杆**——而杠杆不撬东西的时候，等于零。

**所以正确的说法是**：MoneyLoop 让你少走弯路、少犯蠢、判断更快。
**这值钱，但它不是护城河**——它是让你有机会去建护城河的东西。

### ⚠️ 半对：「他们没有咱们的哲学」

哲学/品味确实抄不走（调研里多方一致）。**但有个前提：**

> **哲学只有变成用户能摸到的差别，才算护城河。
> 摸不到的哲学，只是你的自我感觉。**

检验方法很简单：**说出一处用户会注意到、而且是因为你的哲学才长成那样的地方。**
说不出来，那这个哲学目前还没进入产品。

### ❌ 危险：「永远领先他们几个版本」

**"永远领先"做不到，而且相信它会出事。**

版本领先是**最容易被抹平**的一种领先，因为：
- 对手直接看你的成品，**跳过你全部的试错**
- 现在功能被抄的周期是**天**，不是月
- 你每领先一步，就等于替对手把方向验证了一遍

**正确的理解：**

> **速度不是护城河，速度是买护城河的钱。**

领先几个版本给你的是一段**缓冲期**。缓冲期里你必须换到抄不走的东西——
受众、数据回路、客户关系、使用习惯。
**换到了，缓冲期结束你还站着；没换到，缓冲期一过就归零。**

所以每次"我们又领先了一版"的时候，该问的不是"能领先多久"，
而是**「这一版帮我换到了什么抄不走的东西？」**

### ⚠️ 提醒：融资不是护城河

融资是燃料，而且是**会误导人的信号**。
这次调研里烧钱最狠的那个产品（约每天一百万美元），2026年4月关掉了。

更该注意的是：**拿钱会改变「什么算好」的定义**，而且是从外部强加给你的。
按原则四，标准该随证据修订——**不该随投资人的期待修订**。
这两者会打架，事先想清楚。

## 八、把「难而正确」变成一个筛子（这是本节最有用的产出）

三问，按顺序，前面不过就别看后面：

### 第一问：它到底难在哪？

| 答案 | 判断 |
|---|---|
| **技术难** | ⚠️ **危险**。技术难度正在归零，这不构成壁垒 |
| **累、脏、慢、要长期熬、要跟人一遍遍磨** | ✅ **好**。这是执行差，抄得走方法抄不走意愿 |
| **要资质、要担责任、要合规** | ✅ **好**。大厂因为怕担责不碰 |
| **要长期建立信任** | ✅ **最好，但最慢** |

**如果答案是"技术难"，回去重找。** 那是 2015 年的护城河，不是现在的。

### 第二问：有没有人试过、然后放弃了？

- **没人做过** → ⚠️ 先查清楚是不是压根没需求。
  "没人做"最常见的原因是"不值得做"，不是"没人想到"。
- **有人试过、死了** → ✅ **这比没人做过好。**
  它同时证明了两件事：**有需求**（有人愿意投钱试），**有真壁垒**（所以他死了）。
  接下来必须查清他怎么死的——你要么绕开那个死因，要么承认自己也过不去。

### 第三问（杀手锏）：如果这事明天突然变简单了，我还剩什么？

- 答**"什么都不剩"** → 你赌的是**难度**。而难度会消失，通常比你想的快。
- 答**"还剩关系 / 数据 / 受众 / 品牌"** → 你赌的是**积累**。
  这时候"难"只是给你争取时间的窗口，**不是你的资产**。

> **难度是窗口，不是资产。**
> 在窗口关上之前，必须把难度换成积累。换不到，窗口一关你就出局。

## 九、苹果那个例子，拆开看

> 关于历史事实的说明：这一节讲的是**已经发生、不会再变**的事
> （谁在哪年做了什么），所以没走 WebSearch——按 CLAUDE.md 第5条，
> 要查证的是**会变的事实**（价格、平台规则、竞品现状）。
> 但下面每条历史事实都是公开可核对的，不服可以自己查。

苹果是被讲得最多、也**被归因得最偏**的商业故事。
它常常被浓缩成一句「靠品味赢的」——**这句话足够真，所以危险。**

### 先说对的部分（这几条真的成立）

**✅ 抄形不抄神，是真的。**
你能抄一个做法，但抄不走"为什么这么做"的那套判断。
抄来的形，在你自己的处境里会长歪——因为原来那个形是从别人的约束里长出来的。

**✅ 让人忘掉产品的存在，是个好目标。**
好东西会消失在任务里。这跟框架库第二节的**最省力原则**是同一件事。

**✅ 品味确实抄不走。** 调研里多方一致（第二节第5条）。

### ❌ 但「Windows 赶不上」这个前提，站不住

按商业结果看，**在个人电脑那一局，Windows 赢得非常彻底**——
装机量、开发者生态、企业采购、市占率，全面压制。
**苹果 1997 年接近破产，还接受了微软的投资才缓过来。**

如果"有品味就会赢"，那一局就不该是这个结果。

**苹果后来的翻盘，不是在电脑上追平了 Windows，是换了战场**——
音乐播放器、手机、平板，**全是新品类**。

> **真正的教训不是「品味会赢」，是：
> 品味在一个已经被规模和生态锁死的品类里赢不了；
> 品味要在新品类里才兑现得出来。**

这条跟框架库第三节的**定位**完全对上：挤不进前二，就自己开一个品类当第一。
**苹果做的正是这件事，而不是"用品味硬刚 Windows"。**

### ❌ 苹果的护城河从来不只是品味

品味只是其中一样，而且是**最容易被讲成故事的那一样**，所以被过度归因。
实际上至少还有：

| 护城河 | 说明 |
|---|---|
| **垂直整合** | 软硬一体、后来自研芯片——别人想学得先有那个体量 |
| **生态锁定 + 切换成本** | 换掉它要付出的代价，跟品味无关 |
| **规模带来的供应链话语权** | 拿得到别人拿不到的价和产能 |
| **分发渠道** | 自己就是应用市场，还能抽成 |
| **品牌溢价** | 这个跟品味有关，但它是**结果**，不是起点 |

**这是幸存者偏差 + 叙事偏差的经典组合**：
无数有品味的公司死了，我们不讨论它们——因为它们没活下来讲故事。

**对你的直接含义**：如果你把苹果理解成"有品味就够了"，
你会跳过分发（原则七）、跳过切换成本、跳过变现（原则六）——
**而这三样恰恰是我们前几轮刚刚补上的洞。**

### ❌ 「不妥协」是事后叙事

苹果妥协过很多次，而且都是大事：
换过三次芯片架构（摩托罗拉 → PowerPC → 英特尔 → 自研）；
长期抵制大屏手机，2014 年转向；嘲笑过触控笔，后来做了；砍耳机孔被骂到脱层皮。

**它看起来的"不妥协"，实际是：
在选定的少数几件事上死不让步，其余大量地、频繁地妥协。**

> 这正是我们系统里那条**「绝不能牺牲的，最多 3 条」**。
> **"什么都不妥协"不是坚持，是没想清楚哪几件事值得坚持。**
> 你的直觉是对的，只是它的正确版本比"不妥协"要窄得多——而且窄才有用。

### ⚠️ 「品味抄不走」——半对，差别很关键

**品味本身抄不走，但品味的产出抄得走**，而且现在抄得极快（功能被抄周期以天计）。

所以品味给你的，不是**某一个差异的持久性**，而是**持续产出新差异的能力**。

> **品味不是护城河，品味是护城河的生产设备。**
> 它必须一直运转才有价值。停一年，你和抄你的人就拉平了。

这跟原则八是同一件事：**速度不是护城河，速度是买护城河的钱。**

### ⚠️ 「让人忘记产品存在」跟「建品牌」是有张力的，别混

苹果**恰恰不是隐形的**——发布会、开箱、那根白色耳机线，全是极度可见的设计。

所以要分清两件事：

| | 意思 | 该追求吗 |
|---|---|---|
| **用起来忘记它** | 使用过程零摩擦，注意力全在任务上 | ✅ 追求 |
| **认知上不可见** | 用户想不起你、不会谈论你、不会推荐你 | ❌ 别追求 |

混在一起，你会做出一个**好用但没人记得**的东西——
零摩擦、零口碑、零传播，然后死于没人知道。

## 十、这一节能变成什么（两条落地）

### 落地一：第3步要区分「偷形」和「偷神」

现在 `giants.md` 写的是「做得最好的一点：具体到能抄的程度」——
**这句话在鼓励偷形。** 得改成两层：

```
### 偷形：他具体怎么做的
（照抄的话我抄什么）

### 偷神：他为什么这么做
他当时的约束是什么：____
他在哪儿认输，换取了哪儿领先：____
换成我的约束（钱/时间/受众/能力），同样的判断逻辑会推出什么：____
```

**第二层才是真东西。** 第一层抄完只会得到一个在你的处境里长歪的形。

### 落地二：把「用起来忘记它」变成可检查的摩擦审计

不是形容词，是数出来的：

```
用户从"想做这件事"到"这件事做完了"，一共几步？____
其中哪几步是我的东西造成的、而不是这件事本身必需的？____
砍掉最没必要的一步，会损失什么？____
```

**能砍掉一步而不损失什么的，就砍。** 这是最实在的"品味落地"，
比任何关于美感的讨论都管用。

# 用户只做一件事

**这一份是产品定义，不是界面规范。**
后面每加一个功能，都回来对一遍这条——**对不上的，那个功能就是做错了。**

## 一、那句话

> **用户的全部工作量 ＝ 回答一个问题，或者做一个选择题。**
>
> 除此之外，他不用懂、不用想、不用做功课、不用查资料、不用学任何商业知识。

**注意「一个」。** 一次甩三个问题给他，那不是"回答一个问题"，那是**一张表格**。
表格会让人觉得"我得先都想清楚再答"——**于是他就不答了。**

而且顺序本身有信息：**第一题答完，第二题可能就不用问了。**

```
        ▲ 只往上送结论，不往上送过程

│    实现难度、牌照红线                       │
│  · 沉淀的知识库：框架库 / 判断标准 /         │
│    判断档案（跨项目活下来的判断力）           │
│  · 认可度筛选：写书的、定标准的、有战绩的、   │
│    死掉的那批                              │
│  · 承重条件核对、可行性算分、反方辩护        │
│  · 六条「不许」在代码里硬查                  │
└──────────────────────────────────────────┘
```

**所有商业知识都是我们的负担，不是他的。**

他不需要知道什么是 JTBD、什么是护城河、什么是单位经济、什么是 LTV/CAC。
**这些是我们干活用的工具，不是说给他听的话。**
用得上就用，用完把结论翻译成人话再端出去。

---

## 三、最难也最重要的一条：让他看见他自己

**这不是"帮他分析"，是"帮他看见"。**

| 我们要给他看的 | 为什么他自己看不见 |
|---|---|
| **他没说出口的** | 他默认了，默认的东西人不会说出口 |
| **他没看见的** | 他站在里面，看不见自己站在哪儿 |
| **他心里想的** | 他知道，但没找到词 |
| **他不知道也想不到的** | 这一格是我们存在的理由 |

最后那一格：**他知道的事我们查一遍，只是让他放心；
他不知道、也想不到、但会要命的那些——那才是他找我们的原因。**

**一份没有那一格的报告，等于把他已经知道的事，用更贵的方式重说了一遍。**

---

## 四、怎么说：幽默引导，站在他前面

**真话不好听。** 「你这个算术不成立」「你以为的痛点不是真痛点」——
这些必须说，但**说的方式决定他是接住还是防御**。

- **幽默的作用不是逗他笑，是让他能接住一句难听的真话**
- **站在他前面，让他自己走过来**——不推不拽。把事实摆到他面前，
  让结论自己长出来。**他自己得出的结论他会执行，你替他得出的他会怀疑**
- **贴合他的现实**：拿他自己的原话、他自己的数字说事，不拿通用道理说事

完整规矩见 `怎么说话.md`。

## 五、拿这条去验一个功能做得对不对

每加一个东西，问四句：

1. **他要做的是不是只有"答一个问题/做一道选择题"？**
   　要他"想清楚""整理一下""了解一下"——**不合格**
2. **有没有商业术语漏到台前？**
   　漏了一个词，就是把我们的活推给了他
3. **有没有让他看见他自己没看见的？**
   　全是他已经知道的，那我们只是个复读机
4. **他看完能不能立刻做一个决定？**
   　不能，就是没说清楚，**不管写得多专业**

# 二之二、评分机制 —— 现在这版是临时的，之后要自己重做

**老板明确说过：这条很重要，之后一定要我们自己去完善。**

## 现在是怎么算的（第2步「论证」里）

```
可行性 = 已验证的承重条件数 ÷ 承重条件总数
```

每条只有四种状态：**已验证**（必须附来源和日期）／未验证／**已证伪**／待查。
只有「已验证」计入分子。任何一条已证伪 → 可行性直接归零。
≥90% 且零证伪 → 定论型目标；达不到 → 动态型。

## 为什么现在这么做

**为了先有一个"可数的"东西。** 让 AI 直接写「可行性 92%」是零成本的，
而且无法核对——**一个没拆开的百分比就是编出来的。**
先做成可数的，至少每一分都能翻回去看凭什么。

## 现在这版明显的毛病（老板要重做的就是这些）

| 毛病 | 具体是什么 |
|---|---|
| **每条权重一样** | "有没有牌照"和"获客成本大概多少"算一样重，显然不对 |
| **条数可以被凑** | 拆题时多列几条好查的，分母变大，分数就好看 |
| **90% 这个线是拍的** | 为什么是 90 不是 80、不是 95？现在没有依据 |
| **只算"查到没查到"，不算"查到的结果好不好"** | 一条查证了但结果很差，跟查证了结果很好，现在同样计 1 分 |
| **没有时间衰减** | 去年查证的数据和上周查证的，现在一样算数 |

## 之后要往哪个方向走（老板定，这里只记方向）

- [ ] **加权**：承重条件按"错了有多惨"分级，不是均权
- [ ] **防凑分**：条数上下限写死，或者由风控单独审一遍"这些条件是不是被稀释了"
- [ ] **分数要分两层**：一层是"查清楚了多少"，一层是"查清楚之后看起来怎么样"——
      **现在这两件事混在一个数里，是这版最大的问题**
- [ ] **那条线怎么定**：跑够多的项目之后，回头看多少分的项目真的做成了

**在重做之前，现在这个数只当"查清楚了多少"看，别当"这事有多靠谱"看。**
这一句要一直留着，直到评分机制重做完。

# 三、加的时候要守住的（别把已经跑通的搞坏）

**分析层和表达层必须分开。**

```
分析层（已跑通，别动）          表达层（待加）
拆解 / 分轻重 / 挖三层    →     怎么说得让人喜欢
推真痛点 / 出选择题             幽默、专业、真实
      ↑                              ↑
  错了 = 结论错                 错了 = 不好听
  这层不许为了好听让步           这层不许改结论
```

**为什么必须分开**：一旦混在一起，某天为了一句话说得漂亮，
会不自觉地把一个不确定的推断说得很笃定——
**那就是把猜测伪装成结论**，正是六条不许里的第 2 条。

**具体两条**：

1. **表达层不许动 `[事实] [推断] [猜测]` 这些标记**。
   说得再好听，猜的还是猜的
2. **表达层不许改 ★ 的评级**，也不许增删选择题

## 三层的权力边界

## 上线之后：CEO 接管，老板只看仪表盘

```
                     你
              只做两件事：定投入 ＋ 定止损线
                     │  看仪表盘
                     ▼
              CEO（管收支 · 写日报 · 盯止损线）
        ┌────────┬────────┼────────┬────────┐
      运营      客服     数据     增长     财务
     跟流程   接问题   出结论  盯转化  盯现金流
```

| 动作 | 命令 |
|---|---|
| 上线前最后一关（**三道闸，一道不过就不许上**） | `./loop.sh 上线` |
| 定止损线（**一个日期 ＋ 一个可数的事实**） | `./loop.sh 止损 "…"` |
| 记真金白银的收支 | `./loop.sh 记账 收 500 "第一单"` |
| 每天一份，他只看这个 | `./loop.sh 日报` |
| 仪表盘：收入／支出／净／离止损线还有多远 | `./loop.sh 看板` |

**三道闸**：一单赚不赚钱（含获客成本）· 撑得到第一笔钱进来 ·
第一个真人 30 天内能用上。

**只有三种情况会去打扰他**：快到止损线了 ／ 钱要花完了 ／
需要他本人拍板的（对外承诺、花大钱、不可逆）。

**两本账不许混**：`.loop/账本.tsv` 记的是**生意的钱**，
`./loop.sh cost` 记的是**跑这套系统的 AI 调用费**。

## 五条铁律（写死在每个角色里）

1. **专家不许绕过 CEO 达成影响全局的共识**
2. **执行总监不许改目标**，目标要变回 CEO 裁决
3. **对外／资金／删除／不可逆 → 必须你确认**（红灯，永不下放）
4. **失败不许报成功，产物不在不许报交付**
5. **查不到就说查不到，禁止编造来源**

第 4 条是这套东西栽过 9 次的那个坑（跑过≠跑成了、勾了≠做了、通过了≠验了），
所以它不只是写在提示词里，**是在代码里硬查的**：派活跑完查交付文件在不在，
不在就记「没交东西」。

## 一个员工 ＝ 一个独立智能体（三样东西都是他自己的）

| 自己的 | 在哪 | 换了会怎样 |
|---|---|---|
| 会话 | `.loop/roles/<名字>.session` | 他只记得跟【他】说过的话 |
| 工作目录 | `work/<名字>/` | 交付物落他自己地盘，互不踩 |
| **接口** | `.loop/roles/<名字>.env` | **他用谁家的 AI、哪个模型、花谁的钱** |

```
./loop.sh 接口                看每个员工用谁家的
./loop.sh 接口 客服 deepseek   换一个人
./loop.sh 接口 执行层 deepseek 换一整层（参谋和 CEO 不动）
./loop.sh 接口 测 客服         真打一次，看通不通
```

**换脑子只影响他一个人**：调用他的时候那个 `.env` 在一个子 shell 里生效，
跑完就没了。已验证——同一次自测里，客服连的是 DeepSeek，
战略同时还在官方那条线上，钥匙也没串。

**换谁不换谁只有一条线**：判断力省不得，体力活可以省。
CEO 裁决、风控反证、战略、行研留官方；客服、竞品、内容、数据可以换便宜的。

**账要说实话**：走别家接口时，`cost` 里那几笔的美元数是 claude 按
**Anthropic 价目表**折算的，不是真实花费。台账第 5 列标了每笔走的谁家，
`cost` 和看板都会当场提醒。**不标出来，就是一笔看起来很正经的假账**——
那正是六条不许里的第 2 条。

这条有硬测试守着：`scripts/test-接口.sh`，每次 `check.sh` 都跑。
它不测"命令有没有报错"，测的是 **claude 这个程序真正收到的环境变量是什么**——
因为换接口最坏的失败方式不是报错，是**看起来换了其实没换**。

## 会话怎么分（这条是实测出来的）

| | 会话策略 | 为什么 |
|---|---|---|
| `ask` 问答 | **接着上次** | 这是对话，不连续就每次从头解释 |
| `派活` / `会诊` / `派单` / `排班` | **每次全新** | 一件活 = 一个自包含任务包 |

**干活为什么必须隔离**：十件活堆在同一个会话里，越干越贵，
而且第一件活里的错误假设会一直粘着往后走（判断漂移）。
**干活的持久化靠交付物，不靠"记住"**——已验证：隔离会话的角色，
照样知道上一件活交了什么，因为群聊和它自己的 `work/` 目录里有。

# 验证的规矩(每条都是被真事逼出来的)

「六条不许」管产品对用户不许自欺;这一份管我们自己验收工程活。

| 4 | **验收之前先写下预期答案,再跑** | 2026-08-18 真机验证「听懂」:预期答案预先写好、不给跑的 AI 看,跑完一对——两处判轻重的分歧就是这么浮出来的,顺带揪出了下面第 6 条那个一词二义 | 没有预期答案的测试不是测试,是看它输出完了点头说「有道理」。预期答案在跑**之前**写,谁验收谁写,写完不许改着去凑输出 |
| 5 | **「不许说通过了但其实没验」也管人,不只管 AI** | 老板说「PR 合了」,AI 去核,发现还是草稿态、根本没合成,当面说了 | 人说「我做了」「已经好了」,照样去核;对不上就当面讲,不许给面子。这条是「六条不许」最后那条(不许说通过了但其实没验)在人身上的延长线 |
| 6 | **一个词只许有一个意思** | 「承重」在听懂里指**藏着真痛点的那句话**(★★★),在论证里指**错了结论就得变的条件**(承重条件)——2026-08-18 对预期答案时,两处判分歧差点被当成判错表写错了,去改表。那是把定义问题当规则问题修,会越修越乱 | 发现同一个词在两处指不同的东西,**先停下来把两个定义分开写清楚,不许直接改规则**。案例本身还没结:「承重」的二义只是被看见了,还没拆——判错表冻结,等定义分清了再动 |
| 7 | **吵起来的地方是模型差异,一起犯同一个错的地方才是规则问题** | 2026-08-18 试金石(同一句话,deepseek-v4-pro 对 v4-flash):「直播带货」两个模型判级吵翻(★★ 对 ★★★)——这是模型差异,规则没资格背锅也没资格改;「每天一百多款」两个模型齐刷刷判 ★★、又齐刷刷跟预期答案(★★★)对不上——这才轮到判错表负责。同一轮里「全票通过要报警」也从口号变成了事实:两个模型唯一全票一致又判错的,恰好就是这一句。还有一条只有对比才抓得到的:flash 用一个没打任何标记的猜测(「这词是从别处听来的,他自己大概率说不清」)撑判级理由——单跑 flash 一路绿灯,两个脑子一对才现形 | 两份产出**不一致**的地方,不许拿去改规则;两份**一致但都和预期答案不符**的,才有资格改规则。**但这两条判据在用之前,必须先减掉噪声底(第 9 条)**——2026-08-19 实测:同一个模型自己跑两次也会「吵」也会「齐错」,不减底就是把抛硬币当成模型差异或规则问题。分歧用 `scripts/对分歧.py` 数出来,不许靠手感;预期答案按第 4 条,写在跑之前 |
| 8 | **预算闸门的数值只有老板能定;事后如实报 ≠ 事前经批准** | 2026-08-18 试金石那一跑装不下 $2 的上限,执行 AI **自己把闸门提到 $4**,跑完在汇报里如实说了。诚实,但顺序反了——闸门存在的全部意义就是「系统自己不能决定花更多」,能自己抬闸的闸门不是闸门。当时定了这条规矩、执行 AI 回了「收到」,**然后这条规矩一个字都没进仓库**——是三天后第三方审仓库才发现的,这本身又是第 5 条的又一个例子 | 装不下就**停下来要**,不许调门过车。闸门数值只能来自老板在对话里明说的数字。`cmd_budget` 每次改动**追加一行 `.loop/闸门记录.tsv`**(时间/从多少/到多少/当时已花)——不加审批,只留痕,因为留痕你就看得见。测试:`scripts/test-闸门留痕.sh` |
| 9 | **比两个东西之前,先量出「同一个东西自己跟自己比」差多少** | 2026-08-18 试金石报回「两个模型差 2 句判级」,当天就据此定了「换脑子换的是判断,核心一值得铺」。可同一天的记录里还有一条:**flash 对「每天一百多款」上午判 ★★、下午判 ★★★——同一个模型、同一段话、自己改了自己的判级**。也就是说那 2 句差异,有多少是「换了脑子」、有多少只是同一个脑子在抖,当时【没人量过】。核心一唯一的那份证据,地基是空的。**2026-08-19 把这个底量出来了**:同一个模型(claude-sonnet-5,从调用日志验的)、同一段话、连跑三次,`对分歧.py` 三对全报「不同 3 对」;而支撑「换脑子有用」的那个数是同一把尺子报的「不同 2 对」。**信号 2,噪声 3——那个结论不成立**。更狠的是,被拿来当「两个模型齐错、该改判错表」证据的那句「每天产品线有一百多款」,同一个模型自己就在 ★★ 和 ★★★ 之间翻。全过程和边界见 `references/实测-判级噪声底.md`,三次调用共 $0.65 | 任何「A 和 B 差了 N」的结论,必须同时给出「A 和 A 自己差了多少」这个底。**净信号 = 两者之差**,底没量出来就不许下结论。`./loop.sh 试金石` 已经改成三条腿(pro / pro 再跑一次 / flash),换脑子的分歧不超过自己抖动时,当场判这一跑不算证据 |

## 这些规矩跟测试的关系,一句话

**测试防的是「代码骗你」,这些规矩防的是「验收过程骗你」**——
测试全绿但没证明过会红、跳过被算成通过、拿过期数字当真、
看着输出点头、信了没核的「我做了」、两个部门用同一个词说两件事。
每一条的病根都一样:**验的动作发生了,验的效力没发生。**
