# 00 · 目标

> 原始想法（原话）：「给 MoneyLoop 做一个介绍页，让一个不懂技术的生意人五分钟看懂这是什么、对他有什么用」
> [事实] 来自 `.loop/原始想法.txt`

**先说清楚我在做什么，别搞混**：MoneyLoop 本身就是你正在用的这套九步流水线
（`loop.sh` + `references/` + `CLAUDE.md` 这一整套东西，已经跑了 14 次提交，
从「新增九步模板」一路做到「实地调研护城河、补分发」）。[事实，见 `git log`]
这次要做的，不是 MoneyLoop 这个大项目本身，而是**给它做一张对外的介绍页**——
一个独立的小交付物，目的是让别人（不是你自己）五分钟看懂它。

---

## 一句话目标

让**一个有生意直觉、但不懂技术的人**（比如「我自己有个点子但不会写代码、也不知道该找谁」的
个体老板/小团队负责人）能够**打开一个页面、不用问任何人、五分钟内看懂
"MoneyLoop 是一套把模糊想法自动带到能验证赚不赚钱的流程"，并且知道这东西对自己具体有什么用**，
从而**愿意迈出下一步**——加你、留联系方式，或者自己动手跑一次 `./loop.sh start`。

[推断] "下一步"具体是什么（加人/留联系方式/自己跑），现在还不确定，先按"愿意行动"这个粗颗粒度定，
第3/5步会收窄成一个具体的按钮/动作。

---

## 这是给谁用的

**主角**：一个和你很像的人——有生意判断力、手上有个模糊的赚钱点子，但不懂技术名词、
不会看代码，正在纠结"要不要花钱雇人做/自己硬学"。（猜的，不对就改我）

再具体一点，我猜大概是这三类里的一类：
1. 你认识的做实体生意的朋友（开店/贸易/工作室），40 岁上下，会用微信但没写过代码；
2. 小团队负责人，手下几个人，想让重复的事情自动化，但团队里没有懂技术的人；
3. 也可能不是熟人——是你以后想触达的陌生人，通过内容/口碑找到这张页面的。

**（猜的，不对就改我）**：如果这张页面第一批是发给**你已经认识的具体几个人**（不是陌生流量），
后面的文案基调、长度、语气都要按"写给熟人看"来做，会完全不一样——这条建议你先确认。

## 现在没有这东西的时候，这事怎么办

现状的痛：MoneyLoop 现在只存在于这个 git 仓库里，说明书是给"愿意读九步流程 + 十一条原则"
的人看的（`references/00-总纲.md` 那种写法）。一个不懂技术的生意人打开这个仓库，
看到 `loop.sh`、`CLAUDE.md`、`references/框架库.md` 这些文件名，大概率**直接关掉**——
不是内容不好，是**入口不对**：他不知道从哪儿看起，也不知道这跟他有什么关系。

[推断] 现状的痛不是"这东西不够好"，是"这东西没有一个五分钟能看懂的入口"，
所以介绍页要解决的是"入口"问题，不是"内容"问题——内容（方法论本身）已经有了。

**致命项自查**：你上一次想把 MoneyLoop 讲给一个不懂技术的朋友听、
但发现讲不清楚/对方没听懂，是什么时候？——这条需要你自己确认，
如果这个痛点其实没那么真实（你还没试过讲给人听），这一步的紧迫性要打个问号。

## 解决到什么程度

```
这个需求我们解决到：一个人打开这张页面，五分钟内能说出这三句话——
  ①MoneyLoop 是干嘛的（一句话）
  ②它跟自己随便找人做/自己瞎试比,好在哪
  ③如果我想用,下一步该干嘛（有一个具体能点的动作）
  ——为止。

剩下的明确不管：
  - 不做完整的产品文档/使用教程（那是"能不能用"，是第1层的事，现在还在第0层）
  - 不做技术细节展示（怎么部署、代码长什么样——生意人不关心，讲了也白讲）
  - 不做多语言/多版本（先做一个中文版本讲清楚）

  - 不追求说服"所有人"——只求让"和你原来设想的那个人像"的人看懂并有反应

为什么线画在这儿：
  [推断] 现在还没验证"讲清楚了之后，人到底会不会有反应"（第0层），
  在这之前投入去做教程/正式官网/多语言，全是给一个还没验证的东西加精装修，
  是 CLAUDE.md 里明说的"最贵的浪费"。
```

## 怎么算成功

**主指标**：拿这张页面给 3 个不懂技术的人看（不用你在旁边讲解），
**至少 2 个人能在看完后，不用你补充解释，自己说出"这是干嘛的"和"这跟我有什么关系"**。

**次指标**：这 3 个人里，**至少 1 个人主动问"那我能不能试试"或类似的话**
（对照 `判断标准.md` 的信号强弱表——"主动追问"是中高可信度信号，比口头夸奖值钱）。

[推断] 用"拿给真人看"而不是"我自己觉得写清楚了"作为标准，是因为
CLAUDE.md 明确说"口头夸奖不算数"，而"自己觉得清楚"比口头夸奖更不可靠——
写的人永远觉得自己写清楚了。

## 明确不做什么

1. 不做完整产品官网（导航栏、多页面、SEO）——只做一张页
2. 不做付费/注册/登录相关的任何功能——这一步只是"看懂"，不是"用起来"
3. 不写技术实现细节（不解释 Claude Code、API、部署这些）——生意人不需要,写了反而吓跑人
4. 不追求视觉/动效上的极致打磨——先讲清楚,好看是第2层的事,现在在第0层（见下）
5. 不同时做多个版本/多个受众画像——先给一类人讲清楚,别想着一次打动所有人
