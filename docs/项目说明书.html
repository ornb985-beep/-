MoneyLoop

任何一个想法输入，都能快速得到一个诚实的答案——要么变成赚钱闭环， 要么在你花大钱之前告诉你它不行。

〇 · 先说清楚这份文件怎么读

这里面没有一个数是估的

所有数字都从实际运行记录里数出来，标注方式沿用项目自己的规矩： 事实 有来源能核对 · 推断 从材料推的 · 猜测 就是猜的。

第四节是「还没验证的」，请先看那一节

把没做到的写在前面，是因为尽调最先查的就是没提的东西—— 被对方先发现，比自己说出来致命得多。

一 · 它解决什么

不是「帮你做东西」，是「不让你自欺」

一个有判断力的生意人，失败很少因为不会写代码。常见的死法是这五条：

真实死法MoneyLoop 在哪一步挡住
没查就做，建立在假设上第2步强制联网查证，带来源和日期，查不到就写查不到
分不清哪句是事实哪句是猜的全程强制标注，一份看不出哪句是猜的文档被判定为危险
说不清「什么算好」，于是无限打磨或草草交付第4步不问标准，给你看 A/B/C，从你的选择反推标准
只算成本没算收入第1步倒推算账，第7步收支两侧都要答
把「能用」当成「有人要」四层判断标准，只用当前层的尺子
全套最狠的一道闸，在第1步 
一单赚多少 → 每月要多少单 → 每单要接触多少人 → 每天要多少人看到
→ 这个数字，靠你现在能想到的渠道，拿得到吗？　[拿得到／拿不到／不知道]

大多数点子在这儿当场就死——不是想法不好，是算术不成立。 一分钱不花、一天不等就能知道。

二 · 怎么演示

五分钟能看到什么

./loop.sh budget 50                    # 设花钱上限
./loop.sh start "一句话想法"            # 开始
./loop.sh go                           # 一直敲，到该拍板的地方它会停
./loop.sh 看板                          # 生成可视化看板，双击打开

演示时最能说明问题的三个动作：

  1. 第1步的倒推算账 输入一个明显不成立的目标，看它当场把算术摊开、指出拿不到那么多人。
  2. 第4步的 A/B/C 它不问「你的标准是什么」，而是给三个能想象出画面的版本， 选完把标准反推成一句话给你确认。
  3. 外部专家链路 专家团 → 行业报告 → 蒸馏 → 专家群： CEO 先定缺哪几块判断，再去找真人（国家标准／教材作者／有战绩的操盘手）， 一人一份落盘带出处，能逐条回头核对。
一次真实运行的产出（可复现）

议题：中国电商直播运营。它交回 200 行报告、6 位单独落盘的专家， 其中挖到《互联网营销师国家职业技能标准（2021年版）》—— 人社部＋网信办＋广电总局联合颁布，把「直播销售员」拆成四工种五等级。

并且自评：「身份可核实的个人 A 类作者偏少，很多编著者查不到机构背景， 按诚实红线没敢算进正式名单。够不够支撑一次不可逆的决定：不够。」

它宁可承认缺口，也没有凑数。这是演示时最该展示的一幕。

开发过程中撞出并修复了 10 个「看着是 ✓ 其实什么都没发生」的缺陷—— 跑过≠跑成了、勾了≠做了、通过了≠验了、规矩写了≠规矩执行了。

这类缺陷最危险的地方不是它错，是它错得很好看： 每一步都显示成功，实际后面全建立在空气上。 所以第 6 条铁律不只写在提示词里，是在代码里硬查的： 每步跑完检查该产出的文件在不在，不在就判定「没做成」，不往下走。

四 · 还没验证的

这一节请先读

  • 能不能赚到钱：零验证 验证过的是「机器能转」，没验证过「转出来的东西有人要、有人付钱」。 收入至今为 0。
  • 样本量 = 1 唯一的使用者就是作者本人。没有第二个人完整用过。
  • 「他们愿不愿意付费」是承重墙，且是猜测 整个定位架在这条上。猜测 如果错了，整个方向要重来。这是现在最该先花钱验的一条。
  • 目前偏重 同类里最轻的工具做完一个任务 12 分钟，最重的 5.5 小时。 本项目目前属于重的那一派，而这个品类被记录在案的死法就是 「重到没人愿意天天用」。
  • 没有受众、没有分发 而按 2026 年的调研结论，受众与信任是唯一还算护城河的东西， 且必须用时间换、抢不回来。
五 · 竞争现实

它不是新品类，这一点必须先承认

所在领域叫规格驱动开发：先把「要做什么」写成文档，再让 AI 照做。 2026 年已主流化。

对手它是什么对我们意味着
GitHub Spec Kit定义了标准做法只管工程质量，不问这东西该不该做
BMAD多角色 ＋ 模板 ＋ 人工确认结构与本项目高度相似；被诟病重、慢、贵
OpenSpec最轻的一个用「12 分钟 vs 5.5 小时」证明了轻的价值
Grok Bot（SpaceXAI ＋ Cursor）2026-08-11 发布，每个 Bot 一台云电脑，能登录你的应用干活执行层面正面打不过；$200/月/席，背后 600 亿美元收购
及格线（必须比它更好，否则不该存在）

装一个现成的执行工具 ＋ 花约 $29 买个验证工具 ＋ 两边人工对接——今天下午就能搭好。

那凭什么是我们

只剩一条，而且它很窄：所有工具都在做「东西符不符合规格」， 没有一个在做「规格本身是不是定错了」。

推断 Grok Bot 的 Bot 只执行、不裁决。 但要诚实：这可能不是它做不到，是它不需要—— 它的用户已经知道自己要什么，卡在执行；我们的用户卡在「不知道自己要什么」。 这是两个市场，不是同一个市场的强弱。

猜测 如果它下一版加上判断层，我们的独特性会被削掉一大块。 这是这个方向最大的头顶风险，目前没有对策。

六 · 落到手机

怎么从「电脑上的工具」变成「手机上的 App」

先说清楚现状：MoneyLoop 现在是一个在你自己电脑上运行的命令行程序， 没有服务器、没有账号体系、没有客户端。要上手机，有三条路，代价差一个数量级。

路线 A · 我推荐先走这条

电脑跑，手机看

把 docs/ 和看板同步到网盘或 Git，手机上直接打开那个 HTML。 你在外面能看到：组织图、群聊、台账、花了多少钱、进度到哪。

要做什么
基本不用做——已经生成的是标准 HTML，同步一下就能看。
代价
接近 0，今天就能用。缺点是只能看，不能在手机上指挥。
路线 B

手机能看也能说话

加一个轻量服务：手机上打开网页看板 ＋ 能往群聊里发话， 电脑那端跑着的 loop 下次开口时就会看到。

要做什么
一个小服务 ＋ 一个能读写群聊文件的接口 ＋ 简单鉴权。
代价
推断 一到两周；多一个会挂的东西要维护。
路线 C

真正的手机 App

整套重写成托管服务：账号、云端执行、计费、客户端。用户不用装任何东西。

要做什么
后端 ＋ 执行沙箱 ＋ 计费 ＋ App 上架，是一个完整的产品工程。
代价
推断 数月起步，且每个用户的 AI 调用成本要真金白银垫付 （实测单次调用 $0.15–$8.20）。
为什么我不建议现在跳到 C

付费意愿还没验证。先花几个月做 App，等于在一个未经验证的假设上 压上全部成本——而这正是这套系统本身设计出来要拦住的那种决定。

更稳的顺序是：A 先用起来 → 找到真实付费用户 → 再决定 B 还是 C。

七 · 接下来

三件事，按顺序

  1. 验证付费意愿 整个定位架在这条猜测上。排在做任何新功能前面。 不需要写代码，需要的是把它给真实的「想不明白的人」看，看他们掏不掏钱。
  2. 砍重量 从可选项变成必答题——对手 12 分钟，我们还没数过自己要多久。
  3. 建受众 唯一成立的护城河，最慢、抢不回来，必须和产品并排推进而不是等做完。
这套系统对自己的判断

它的自我诊断工具（五个镜头互相打架）对自己跑过一遍，结论是： 「功能更好」「效率更高」「有方法论」这三条都不是护城河—— 功能能被抄且以天计；效率是内部过程，用户摸不到；方法论抄一遍就走。

唯一成立的是用户信任与受众，而那一条目前是 0。
