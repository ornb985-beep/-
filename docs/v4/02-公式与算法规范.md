# 02 · 公式与算法规范

本文档是 `oic/scoring/` 与 `oic/calibration/` 的数学契约。
**每条公式都必须跑在代码里，不得由 LLM 计算**（铁律 1）。

## 一、评分公式链

### 1.1 三级评分

```
资源匹配度 = 资金档位分 × 0.5 + 团队技能覆盖度 × 0.5
需求强度   = C × 0.5 + D × 0.5
可行性     = O × 0.4 + E × 0.4 + 资源匹配度 × 0.2
总分       = 需求强度 × 0.5 + 可行性 × 0.5
```

**为什么是这个结构**：
- 需求强度只看 C 和 D —— 趋势再热（C），没有活跃需求（D）也只是泡沫
- 资源匹配度占 0.2 且不可移除 —— 别人的好机会不等于你的好机会
- 总分对半开 —— 防止"趋势脑"压倒"务实脑"

**权重可学习性**：C/O/D/E 的系数 = 基准系数 × (权重/25)，权重上限 40。
**资源系数恒为 0.2，永不参与学习** —— 资源约束是物理事实，不因用户偏好改变。

| 资金 | 档位分 | 技能 | 覆盖度 |
|---|---|---|---|
| <10万 | 60 | 产品 | +33.3 |
| 10–50万 | 70 | 工程 | +33.3 |
| 50–200万 | 80 | 销售 | +33.3 |
| >200万 | 90 | | 封顶 100 |

> 团队缺哪个技能，资源匹配度掉 33 分，直接拖低可行性。

### 1.2 排序分

```
排序分 = 总分 × 变现系数 × M系数 × 风险系数 × 真实性系数 × 红线因子
```

红线因子 ∈ {0, 1}，**用乘法而非分支** —— 保证归零逻辑与公式一致，无法被绕过。

> 注意：排序分不是百分数，理论上界为 100×1.2×1.3 = 156。它只用于排序。

### 1.3 变现系数（pathCoeff）

| 档 | 系数 | 触发条件 |
|---|---|---|
| proven | 1.2 | **A/B 级来源**出现成交证据词（GMV/月销/年营收/万单/ARR…） |
| intent | 1.0 | A/B 级来源出现付费意愿词（付费/客单价/溢价/买单…） |
| buzz | 0.8 | 仅讨论热度 |

**关键修复**：v3 原实现对全部证据文本扫词，竞品自称"月销破万"就能骗到 1.2。
现在 **C 级来源永不参与判定**，其成交词被记入 `rejected_c_grade_terms` 并提示"疑似软文"。

### 1.4 真实性系数

```
真实性系数 = 1 − min(刷单风险分 / 100, 0.5)
```

下限 0.5：第三方拿不到平台级反作弊信号（设备指纹、关系网络），
这只是"真实性置信度"，不该由单一代理指标把商机直接打死（那是 R5 红线的职责）。

## 二、供给侧引擎

```
剪刀差 M = 需求增速% − 供给增速%
死亡率 X = 近12月注销吊销数 / 存续企业数      （存续数=0 时报错，不返回 1.0）
风险系数 = 1 − min(X × k, 0.5)                 k=1.0（PRIOR）
```

### M 系数分档（PRIOR，全部待校准）

| M | 判定 | 系数 |
|---|---|---|
| >30% | 强机会 | 1.3 |
| 10–30% | 窗口开着 | 1.1 |
| −10–10% | 平衡 | 1.0 |
| <−10% | 拥挤 | 0.7 |
| ≤−30% **且** X>15% | **绞肉机** | **0.0（红线）** |

绞肉机需**两个条件同时成立** —— 需求在退、供给还在涌入。
只有剪刀差差但死亡率低，不算绞肉机（可能只是行业整体降温）。

### Schwartz 成熟度自动定级

用同一批工商数据定级 L1–L5，从而自动给出文案策略。
**这个连接是本项目原创**：Schwartz 判定成熟度靠"此前有多少类似产品被宣传过",
而这正是供给侧数据能算的。

| 级 | 判定条件 | 文案策略 | 行动 |
|---|---|---|---|
| L1 | 同类 <10 家 | 直接说这东西是什么 | 最好做，直接上 |
| L2 | 10–50 家且供给增长 | 把效果说得更极致 | 好做，抢速度 |
| L3 | 50–200 家 | 讲独特机制 | 需真差异化 |
| L4 | >200 家且供给增长 | 讲更好的机制 | 需技术壁垒 |
| L5 | 饱和且注销率上升 | 只能靠身份认同 | 不做，除非有社群 |

> 证据强度：Schwartz 框架是营销经验总结，**无同行评议**，属判断辅助。
> 但"用供给侧数据自动定级"这个连接可被验证。

## 三、切换势能（JTBD 四力）

```
切换势能 = (推力 + 拉力) − (焦虑 + 惯性)
势能 ≤ 0 → 一票否决，降级为「观察」
```

**为什么必须有**：原 C/O/D/E 只测推力和拉力，完全不测焦虑和惯性，
导致系统持续推荐"痛点真实、市场够大、但用户就是不换"的商机 —— 这类项目最坑。

四力都可以从语料读出来：

| 力 | 语料来源 | 词典 |
|---|---|---|
| 推力 | 抱怨/忍受表达 | `TOLERANCE_LEXICON` |
| 拉力 | 现有方案缺口（≈O 维度） | — |
| 焦虑 | "问大家"里的顾虑 | `ANXIETY_LEXICON` |
| 惯性 | 转卖描述里的"还是用回原来那个" | `INERTIA_LEXICON` |

**忍受词优先级高于差评**：差评是愤怒（有人管了），忍受是绝望（没人管）。
最高信号是「**自己改了/自己动手**」（权重 1.0）—— 痛点真实到用户愿意付出劳动。

访谈数定为 **10** 而非 100：Moesta 的经验是 10 个精选近期购买者访谈
即可揭示 3–5 种购买模式、覆盖 90% 市场。

## 四、差异化

### Ulwick 机会分

```
机会分 = Importance + max(Importance − Satisfaction, 0)     量表 1–10，结果 0–20
```

`max()` 保证非负，等效给 Importance 双倍权重。

| 分值 | 判定 |
|---|---|
| ≥15 | 高吸引力，重点投入 |
| 10–15 | 部分市场有吸引力 |
| <10 | 过度服务 —— 放弃，或作颠覆式创新靶点 |

### Berger Better-Worse 系数

```
CS+ = (A + O) / (A + O + M + I)        范围 0→1
CS− = −(O + M) / (A + O + M + I)       范围 0→−1
```

| CS+ | CS− | 判定 |
|---|---|---|
| 高 | 强负 | 期望型 |
| **高** | **近 0** | **兴奋型（尖叫点，爆品应锁定此象限）** |
| 低 | 强负 | 必备型（做好只是不被骂） |
| 低 | 近 0 | 无差异 |

**可疑(Q)率 >10% 说明题目设计有误，需重写后重测** —— 不是把 Q 扔掉了事。

### 禀赋效应（为什么差异化必须可量化）

卖方普遍高估自身产品价值：普通私人商品 WTA/WTP 均值约 **2.9**
（Horowitz & McConnell 2002，45 项研究）；全样本几何均值约 **3.28**
（Tunçel & Hammitt 2014，76 项研究）。这就是"我觉得更好"自欺的经济学根源。

| HHI | 判定 |

| <1000 | 竞争充分 |

| >1800 | 高度集中 |

## 六、红线

任一触发即排序分归零，**不可被高分抵消**。红线是代码仲裁，不让 LLM 调和
（MAST 研究显示"输出冲突"是多智能体主要失败模式，解法是让确定性层裁决）。

| 码 | 条件 |
|---|---|
| R1 | 已确认的合规问题（监管/隐私/平台依赖/欺诈/现金断裂/声誉/IP） |
| R2 | 绞肉机：M ≤ −30% 且 X > 15% |
| R3 | 切换势能 ≤ 0 |
| R4 | HHI > 1800 **且** 机会分 < 15 |
| R5 | 刷单风险分 > 60（底层数据不可信，任何分析都是在错的数字上做的） |

## 七、概率聚合（F4.8）

```
z_i = logit(p_i)
z̄  = Σ w_i z_i / Σ w_i
p*  = inv_logit(a · z̄)          a = 1.5（PRIOR，需校准）
```

**为什么不用算术平均**：多个独立预测者各自基于**部分**信息作判断，
简单平均会把他们共有的不确定性重复计入，结果系统性"欠自信"（向 0.5 收缩）。
GJP 的做法是在 logit 空间平均后向外拉伸（extremization），
把"多个独立来源都指向同一方向"这件事的信息量还回来。

这是"团队比个人准约 23%"的**正确实现方式**。

### 分歧度

```
分歧度 = logit 空间的加权标准差
分歧度 > 1.0 → 强制人工终审
```

多 agent 分歧大本身就是**免费的不确定性估计**，应该推到人眼前，而不是被平均掉。

### 概率粒度

超预最常报 **1% 的倍数**，普通人报 10% 的倍数。允许 63% 而不是只能报 60%。
这是可直接编码的超预行为规则。

## 八、共形预测（F4.9）

Split conformal：取校准残差的第 `⌈(n+1)(1−α)⌉` 个经验分位数 `q`，
区间为 `[预测 − q, 预测 + q]`。

**保证**：只要校准集与测试点可交换，边际覆盖率 ≥ 1−α。
distribution-free、有限样本成立、纯排序实现（不需要 scipy）。

**所需最小样本**：`n ≥ ⌈1/α⌉ − 1`，本系统再叠加 `n ≥ 30`。

### 刻意的拒绝行为

样本不足时**返回 NaN 区间 + "校准未建立"**，而不是给一个没有保证的默认区间。
一个没有覆盖保证的"90% 区间"比没有区间更危险。

### Mondrian 变体

边际覆盖 ≠ 分组覆盖：整体 90% 可能由"A 品类 99% + B 品类 60%"构成。
做品类间比较时必须用 Mondrian。品类样本不足时可退回合并集，
但**必须明确告知"仅剩边际保证"**。

## 九、Kelly 仓位（F4.11）

```
Wilson 下界 p_lo = (p̂ + z²/2n − z√(p̂(1−p̂)/n + z²/4n²)) / (1 + z²/n)
全 Kelly    f* = (b·p_lo − (1−p_lo)) / b
建议仓位     f  = min(f* × 0.25, 0.25)
```

### 三重安全阀（不可关闭）

| # | 阀 | 理由 |
|---|---|---|
| 1 | 只用胜率区间**下界**，不用点估计 | 宁可少下注，不可高估胜率 |
| 2 | 硬上限 **¼ Kelly** | 全 Kelly 回撤实践中无法承受；¼ Kelly 保留约 3/4 增长率而大幅降方差 |
| 3 | 样本 **<30 直接拒绝输出** | Kelly 对 p 高估极度不对称敏感：真实 20% 误估为 40% → 长期增长率为负 |

**第 3 条意味着：在 Outcome 表为空的现在，这个函数永远返回"拒绝"。
这是正确行为，不是缺陷。**

¼ Kelly 上限同时写进数据库 CHECK 约束（`portfolio_position.kelly_fraction`）。

## 十、校准数学

### Brier 与 Murphy 三分解

```
BS  = (1/N) Σ(f_i − o_i)²
UNC = ō(1−ō)                        「只报基础率」这个笨办法的得分
REL = (1/N) Σ n_k(p_k − ō_k)²       校准误差，越小越好
RES = (1/N) Σ n_k(ō_k − ō)²         区分力，越大越好

恒等式：binnedBS = REL − RES + UNC   （精确成立）
有用性判据：RES > REL ⟺ BS < UNC
```

**关于恒等式的诚实说明**：该恒等式**只在"箱内预测取箱均值"的表示下精确成立**。
连续预测在箱内还有方差，这部分被分箱丢掉了。代码把它作为 `binning_loss`
**如实单列**，而不是藏进残差里假装恒等式成立。

这也是为什么报告首选 **RBS = √BS** 而非分箱 ECE：分箱数可以人为操纵，
箱越多 REL 越小，看起来越"校准"。

### 参照基准（ForecastBench, arXiv:2409.19839）

| 主体 | Brier |
|---|---|
| 超级预测者聚合 | **0.096** |
| 普通公众 | 0.121 |
| 最强 LLM | 0.122 |

**最后一行的含义很重要：LLM 单独做概率判断，天花板就是普通人水平。**
系统要超过它只能靠架构（强制基础率 + extremization + 确定性公式接管），不能靠换模型。

> 这条基准被钉进单元测试。系统若报出 0.05 这种远超超预的分数，
> 几乎一定是数据泄漏，不是真的强。

### 分层贝叶斯（Beta-Binomial partial pooling）

```
先验 Beta(α₀, β₀)，α₀ = τ·ō_global，β₀ = τ·(1−ō_global)，τ = 10（PRIOR）
后验 Beta(α₀+k, β₀+n−k)
收缩强度 = τ / (τ + n)
```

冷启动即可给**诚实的宽区间**，随数据自动收窄。零样本品类完全借全局，
并标记 `borrowed=True` —— 区间宽是诚实的，不要当作品类特有结论。

Beta 分位数用连分式展开（Lentz 算法）+ 二分求解，纯标准库，确定性。

### 代理结局与 Prentice 准则

代码只检验**可用观测数据检验**的部分：
(a) 代理与真值相关 r ≥ 0.5；(b) R² ≥ 0.5。

Prentice 完整准则还要求"给定代理后，处理对真值无残余效应"——
**那需要随机化实验才能识别，本系统不做随机化，因此永远无法完全验证。**

**含义：代理最多降到"可信排序信号"，不该被当作真值替代品。**

## 十一、证据层算法

### Span-grounding

```
接受 ⟺ 声称的数值 ∈ expand_numbers(原文[span_start:span_end])
```

- `expand_numbers` 展开中文单位：`"3万单"` → `{3.0, 30000.0}`
- NFKC 归一处理全角数字，**但只用于比对不用于定位**（NFKC 可能改变长度）
- 容差仅覆盖浮点误差，**不覆盖四舍五入**：原文 2.8 万不能匹配声称的 3 万
- 丢弃率 >30% 时提示"这不是数据问题，是抽取提示词或 schema 有问题，
  应改提示词而不是放宽校验"

### 时效衰减与双源锚定

```
w = e^(−λt)      λ = 0.0077（半衰期约 90 天，PRIOR）
```

四铁律：
1. 「实体×指标」指纹合并转载 —— 十篇转载同一通稿仍只算一条
2. ≥2 个 **A/B 级**独立来源才算锚定，否则标「待核实」
3. C 级只作线索不作证据 —— 十个自媒体也锚不住
4. 媒体数字与官方偏差 >30% → 权重 ×0.5，并提示"不要强行平均，
   应解释口径差异并提出最小验证动作"

### 真值发现

迭代求解「来源可信度 ↔ 真值」：

```
可信度_s = exp(−|值_s − 真值| / scale)
真值     = 加权中位数(值, 可信度)
```

- **加权中位数**而非加权均值：一个刷出来的数字不会拖走真值
- 固定 20 次迭代、固定初值 → 完全确定性，不破坏 `verify_scores`
- 来源 <3 时退回等级加权（样本太少，学出的权重是噪声）
- 同一来源多条取中位数 —— **刷条数无法提高影响力**

## 十二、Eval 指标

| 级 | 指标 | 说明 |
|---|---|---|
| 抽取级 | span P/R/F1 | IoU ≥0.5 匹配；一个 gold span 不能被两个预测重复认领 |
| 判断级 | Cohen's κ、容差一致率 | **参照：GoEmotions 27 类标注 κ≈0.27**，对细粒度任务别期待 0.8 |
| 系统级 | NDCG@10、Brier | 排序与概率是否有用 |

CI 门禁基线（PRIOR）：span F1 ≥0.70，容差一致率 ≥0.60，NDCG@10 ≥0.70。
**golden 集为空时门禁优雅跳过**，不让 CI 常红。
