## 2. 三条铁律（写进代码，不是写进文档）

### 铁律 1 · 确定性计算与 LLM 判断物理隔离

`oic/scoring/` 与 `oic/calibration/` **零网络、零时钟、零随机**。

- 一条 AST 静态检查测试确保它们不会 `import random / time / datetime`
- `verify_scores()` 双跑并断言逐字节一致
- 有**反向测试**证明这个断言真的会失败（不是永真的摆设）

LLM 在系统里只有一个角色：**给 C/O/D/E 四维打分**。其余全部是确定性计算。

### 铁律 2 · 没有实测基线，不准扩多智能体

```python
AgentGate.multi_agent_allowed()   # baseline_accuracy is None → 恒 False
```

依据：
- Google + MIT 的 **45% 规则**——单 agent 准确率超过约 45% 后，加 agent 收益递减甚至转负
- 可并行任务 **+80.8%**；顺序推理任务实测**倒退 39–70%**
- 5 个 agent 各 95% 准确率 → 系统可靠性 **77%**（0.95⁵）

所以「多智能体集群」不是默认开启的能力，是要先测基线才能解锁的能力。

### 铁律 3 · 挑战者必须有独立上下文

Chain-of-Verification 的**分解式**（factored）才有效：验证问题必须在
不看原答案的独立上下文里回答。同上下文自查等于让犯错者当裁判。

依据：FactScore 从 **55.9 → 71.4**。

## 5. 全部公式与参数

### 5.1 主排序公式

```
排序分 = 总分 × 变现系数 × M系数 × 风险系数 × 真实性系数 × 红线因子
```

任一红线触发 → **红线因子 = 0**，排序分归零，**不可被高分抵消**。

### 5.2 四维权重

| 项 | 值 | 说明 |
|---|---|---|
| C/O/D/E 基准权重 | 各 **25** | 公式系数 = 基准 × (权重/25) |
| 单维权重上限 | **40** | 防一次误否决把某维推到支配地位 |
| `RESOURCE_COEFF` | **0.2** | **硬编码，永不参与学习**——资源约束是物理事实 |

### 5.3 剪刀差 M（本系统最大差异化）

```
M = 需求增速 − 供给增速   （单位：百分点）
```

| 档 | 边界 | M 系数 |
|---|---|---|
| 强机会 | M ≥ **+30** | **1.3** |
| 窗口开着 | M ≥ **+10** | **1.1** |
| 均衡 | M ≥ **−10** | **1.0** |
| 拥挤 | M < −10 | **0.7** |
| **绞肉机（R2 红线）** | M ≤ **−30** 且死亡率 > **15%** | **归零** |

全部标注 **PRIOR**（拍定值，未经真实数据校准），界面必须显示「未校准」。

### 5.4 成熟度分级（Schwartz）

| 级 | 同类企业数 |
|---|---|
| L1 | ≤ **10** |
| L2 | ≤ **50** |
| L3 | ≤ **200** |
| L4 | > 200 |

### 5.5 红线 R1–R5（一票归零）

| 码 | 触发条件 |
|---|---|
| **R1** | 已确认的合规问题（按 `COMPLIANCE_CATEGORIES` 确定性遍历） |
| **R2** | 绞肉机：需求在退、供给还在涌入 |
| **R3** | 切换势能 ≤ 0 ——「痛点可能真实，但用户不会换」 |
| **R4** | HHI > **1800** 且机会分 < **15** ——高度集中且无差异化空间 |
| **R5** | 刷单风险分 > **60** ——底层数据不可信，任何分析都是在错的数字上做的 |

### 5.6 真实性系数

```
真实性系数 = 1 − min(刷单风险分/100 × k, 0.5)      k = 1.0
```

下限 **0.5** 是刻意的：第三方拿不到平台级反作弊信号（设备指纹、关系网络），
所以这只是「置信度」，不允许单一代理指标把商机直接打死——那是 R5 的职责。

### 5.7 Murphy 三分解

```
BS = REL − RES + UNC
```

**恒等式只在分箱表示下精确成立。** 实现里用箱内均值 `p_k` 计算 `binned_bs`，
并把 `binning_loss = actual_bs − binned_bs` **单独报出来**，不藏进残差。

G2 判据即 `BS < UNC`，等价于 `RES > REL`。

### 5.8 Kelly 三重安全阀

| 阀 | 值 | 防什么 |
|---|---|---|
| 用 **Wilson 下界**而非点估计 | z = **1.2816**（80%） | 小样本胜率高估 |
| **¼ Kelly** 上限 | **0.25** | 全 Kelly 的破产风险 |
| 样本 < **30** 直接拒绝 | — | Kelly 对胜率高估极度敏感：真实 20% 误估为 40% 会让长期增长率**转负** |

### 5.9 热度→供给证据封顶

```
NO_SUPPLY_EVIDENCE_CAP = 0.6
```

没有供给侧证据时，排序分封顶 0.6。**这个约束的依据是公式定义，不是数据拟合。**
刻意**不加**热度惩罚项——那会是在拟合 n=7 的噪声。

### 5.10 变化率评分

```
velocity_score = 趋势基分(UP=60) + 幅度分(≤20) + 形状分(≤20)
```

原本 UP 基分给 100，导致 +20% 和 +100% 都是满分，排序退化成指纹字母序。
现在留出了幅度与形状的空间。

### 5.11 信息饱和判据

```
连续 3 次查询边际产出 < 5%  →  判定饱和，可以停
```

某角度**零产出**则说明该字段大概率不存在于公开渠道，**不是查得不够**。

### 7.2 为什么招股书是最优源

**审计过 · 有法律责任 · 「行业竞争格局」是强制披露项。**

它恰好含公开渠道拿不到的字段：市占率、CR5、同业公司数、行业规模与增速、
客单价、毛利率、获客成本。登记为 `PUBLIC_DOWNLOAD` + A 级——
法定公开披露，不是爬取。

**已知偏差**：幸存者偏差（能 IPO 的都是成功者）+ 自利披露倾向，需在权重上体现。

### 7.3 八角度调查矩阵（`investigate.py`）


**实测有效**：同一品类（盲盒/潮玩），1 次查询 → 2 条事实；**7 次多角度 → 17 条**。

```

判据 |ρ| > 0.3   ❌ 未达；且 n=5 时纯随机 |ρ| 中位数约 0.4 —— 连运气基线都没打过
```

**这不构成「剪刀差有效」的证据。** 它只说明这条线值得继续扩样本去测——
而需求增速那条已经被扩样本否掉了。**两者现在有了区别。**

### 8.4 双标签打架 3/8（37.5%）

| 品类 | 需求侧 | 商机侧 | 实况 |
|---|:---:|:---:|---|
| 线下连锁咖啡 | ✅ +15.4% | ❌ | 价格战，星巴克降价 |
| 新茶饮 | ✅ 门店 48.6万→66.9万 | ❌ | 价格战，单店模型恶化 |
| 预制菜 | ✅ +27.3% | ❌ | 价格战，融资几乎归零，惠发净利 **−319%** |

**如果系统只用需求侧标签训练，它会把人精准地推进已经卷烂的赛道——
而且推荐理由看起来完全正当（「该品类 2025 年仍增长 27%」）。**

这条验证了双标签设计与绞肉机红线的必要性。

## 10. 合规内核

### 10.1 证券边界（`securities_guard.py`）

判据 = 是否触及**具体证券**。《证券法》第 160 条第 2 款。

| 码 | 命中 | 处理 |
|---|---|---|
| **S1** | 具体证券代码（A股6位/港股/NASDAQ:XXX） | **阻断** |
| **S2** | 推荐具体证券买卖 | **阻断** |
| **S3** | 给出买卖时机 | **阻断** |
| **S4** | 预测证券价格走势 | **阻断** |
| S5 | 高危措辞（「投资建议」等） | 自动改写为「商业机会评估」 |

**关键豁免**：仅有信息汇总或历史数据统计、不具备上述四功能的软件**不属于**荐股软件。
所以纯商业/市场/创业机会分析**不需要**证监会牌照。**「投资」二字本身不触发，证券关联才触发。**

罚则（第 213 条）：责令改正、没收违法所得、并处 **1–10 倍**罚款；
无/不足 50 万违法所得的处 **50万–500万**，责任人 **20万–200万**；
可升级为刑法 225 条非法经营罪。

### 10.2 AI 双标识（GB 45438-2025）

导出必须同时有**显式**（正文提示）与**隐式**（元数据）标识。
`assert_labeled()` 任一缺失都不许导出。

`provider_code` 缺省带 `UNFILED-` 前缀并写进元数据——
**一个看起来像真编码的默认值会被原样带上线，带 `UNFILED-` 的不会。**

### 10.3 爬取（`provenance.py` + `http_fetch.py`）

**`SCRAPING` 类源无论法务是否放行，`scraping_never_cleared` 都不放行**——
DB CHECK 约束 + 代码闸双保险。

依据：
- 《反不正当竞争法》(2025) 第 13 条第 3 款：禁止「以避开或者破坏技术管理措施等方式获取他人合法持有的数据」
- 2011–2022 年 12 起「爬虫 + 不正当竞争」案，**爬取方胜诉率 < 16.67%**

**反爬不是待修的 bug，是停止信号。** 你的抓取记录里微博/知乎标注「反爬，待修」——
在这个法条下，正确的动作是从源清单里移除或走授权渠道。

通用取数器代码层做不到的三件事（**没有开关，不是默认关闭**）：

| 做不到 | 拦在哪 |
|---|---|
| 伪装浏览器 UA | 构造 `FetchPolicy` 时抛 `DishonestUserAgent` |
| 无视 robots.txt | 没有 `ignore_robots` 字段，**有测试断言它不存在** |
| 403/429 后重试换身份 | `NO_RETRY_STATUSES`，测试断言只发 1 次请求 |

robots.txt 按 **RFC 9309 §2.3.1.4**：4xx → 可抓；5xx / 网络错误 → **视为完全禁止**。

## 11. 防自欺统计层（`oic/stats/`）

这一层的价值**不是让结果变好，是让「结果好」这件事变得可信**。

| 工具 | 解决什么 |
|---|---|
| **精确置换检验**（小 n 可穷举） | n=8 时正态近似失效，置换检验无分布假设 |
| **Bootstrap CI** | 给出区间而非点值 |
| **`expected_max_correlation`** 运气基线 | 测 20 个特征，最好的那个必然好看——纯属偶然 |
| **Benjamini-Hochberg** | 多重检验校正 |
| **PBO（CSCV）** | 回测过拟合概率 |
| **Purged / LOO 交叉验证** | 防止用同一批数据既选特征又报成绩 |

**关键测试**：`test_pbo_high_when_many_features_few_samples`——
20 特征 × n=8 必须报出高过拟合概率。
