## 一、数据源白名单（F0.1）

实现：`oic/compliance/provenance.py` + `db/schema.sql::source_registry`

### 强制入口

```python
registry.assert_source_allowed("qcc_open")   # Collector 取数前必须过这里
```

绕过它就是绕过合规。未登记 → `SourceNotRegistered`；未放行 → `SourceNotAllowed`。

### 放行条件（全部满足才可用）

| 条件 | 不满足时 |
|---|---|
| 已登记 | `SourceNotRegistered` |
| `access_method ≠ scraping` | 一律不放行，**法务说 OK 也不行** |
| `legal_status == cleared` | 不放行 |
| `tos_url` 非空 | 不放行 |
| `reviewed_on` 非空 | 不放行 |
| 涉敏感 PI 时 `pipia_completed == true` | 不放行 |

### 为什么爬取一律不放行

德恒统计 2011–2022 的 12 起"爬虫 + 不正当竞争"案，
**爬取方胜诉率不到 16.67%**。2025 年《反不正当竞争法》新增数据专款
第 13 条第 3 款：不得以避开或破坏技术管理措施等方式获取他人合法持有的数据。

同一条约束同时写进数据库：

```sql
CONSTRAINT scraping_never_cleared
    CHECK (NOT (access_method = 'scraping' AND legal_status = 'cleared'))
```

### 当前登记表状态

**没有任何一个源是 `cleared`。`registry.allowed_keys()` 返回空。**

这是正确的起点 —— 法务过完之前，采集层根本不该能跑起来。

| 源 | 取数方式 | 状态 | 备注 |
|---|---|---|---|

## 二、证券边界拦截器（F0.2）

实现：`oic/compliance/securities_guard.py`

### 核心判据 = 是否触及**具体证券**

《证券法》第 160 条第 2 款：从事证券投资咨询服务业务须经证监会核准。

"荐股软件"认定标准（**任一功能即算**）：

| # | 功能 | 拦截码 |
|---|---|---|
| ① | 对具体证券做投资分析意见或预测价格走势 | S4 |
| ② | 推荐具体证券 | S2 |
| ③ | 推荐具体证券的买卖时机 | S3 |
| ④ | 其他证券投资分析/预测/建议 | S1（证券代码） |

**关键豁免**：仅有证券信息汇总或历史数据统计、不具备上述四功能的软件
**不属于**荐股软件。

### 对本系统的含义

纯商业/市场/创业机会分析（行业趋势、商业模式、市场规模）
**不需要**证监会牌照。

但 **"投资级决策建议"是高危措辞**，必须改为"商业/市场机会分析"。

**注意边界**：`"投资"二字本身不触发，证券关联才触发。**
`"这个项目值得投资 50 万元做验证"` 必须放行 —— 这是已测的用例。

### 两类处理

| 类 | 码 | 处理 |
|---|---|---|
| 硬违规 | S1–S4 | **阻断，不做自动改写** —— 改写会掩盖问题，这类内容根本不该生成 |
| 高危措辞 | S5 | 自动改写后放行 |

改写表：

| 原 | 改为 |
|---|---|
| 投资级决策建议 | 商业/市场机会分析 |
| 投资建议 | 商业机会评估 |
| 投顾服务 | 商业研究服务 |

### 自检结果

```
必须拦截：7/7 ✅   （证券代码、荐股、买卖时机、目标价、港美股标注）
必须放行：7/7 ✅   （剪刀差、访谈成本、TAM 计算、止损线、资源匹配度…）
```

**0 误杀是硬要求**：误杀会逼团队关掉这道闸，那比没有闸更危险。

### 罚则（为什么值得写代码）

《证券法》第 213 条：责令改正、没收违法所得、并处 1–10 倍罚款；
无违法所得或不足 50 万的处 **50 万–500 万**，责任人 **20 万–200 万**；
可升级为刑法第 225 条**非法经营罪**。

## 三、AI 双标识（F0.3）

实现：`oic/compliance/ai_labeling.py`

依据：《AI 生成合成内容标识办法》（网信办+工信部+公安部+广电总局，
2025-3-14 发布，**2025-9-1 施行**）+ 强制国标 **GB 45438-2025**。

| 标识 | 要求 | 实现 |
|---|---|---|
| **显式** | 用户可明显感知：文本起始/末尾/中间加文字提示 | 正文首尾加 `【本内容由AI生成，仅供参考】`，幂等 |
| **隐式** | 文件元数据含：生成合成内容属性、服务提供者名称或编码、内容编号 | `AIGC-Attribute` / `AIGC-Provider-Name` / `AIGC-Provider-Code` / `AIGC-Content-ID` |

### 内容编号必须确定性

```python
content_id(body, provider)   # SHA256(provider.code + \0 + body)[:32]
```

同一份报告重新导出必须得到同一编号，否则审计时无法把线上内容与存档对上。

### 导出闸门

```python
ai_labeling.assert_labeled(content)   # 显式或隐式任一缺失 → LabelingError
```

**导出/下载的报告文件必须保留合规显式标识** —— 不是只在网页上显示。

## 四、PIPL（F0.4）

| 场景 | 要求 |
|---|---|
| 简历字段 | 简历**非整体敏感**，但身份证号/金融账户/健康字段属敏感 PI |
| 敏感 PI | **单独同意** + 事前 PIPIA + **记录保存 ≥3 年**（第 55/56 条） |
| 数据源层 | `handles_sensitive_pi=true` 且 `pipia_completed=false` → 源不放行 |

数据库同步约束：

```sql
CONSTRAINT sensitive_pi_requires_pipia
    CHECK (NOT (handles_sensitive_pi AND legal_status = 'cleared' AND NOT pipia_completed))
```

## 五、不可变审计日志（F0.6）

```sql
CREATE TRIGGER audit_log_no_update BEFORE UPDATE OR DELETE ON audit_log ...
    RAISE EXCEPTION '审计日志只可追加，不可 % —— 可篡改的日志不是审计', TG_OP;
```

记录内容：每次评分、每次终审、每次权重修正、每次模型版本变更。

配套：`forecast` 表触发器禁止事后修改预测（只允许回填结局）。

## 七、输出路径上的三道闸

任何面向用户的文本导出前依次通过：

```python
text = securities_guard.assert_safe(text)              # ① 证券边界
content = ai_labeling.label(text, provider, now_iso)   # ② 双标识注入
ai_labeling.assert_labeled(content)                    # ③ 标识完整性
```

**任一失败即阻断导出，不做降级放行。**
