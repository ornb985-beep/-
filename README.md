# 从一个想法，到一个能用的东西

一条自动化流水线。你给它一句话，它带着你走完九步，做出东西来。

**它假设你不懂代码**——全程大白话，遇到术语当场解释，
只在真正需要你判断的地方停下来问你。

---

## 怎么用

```bash
./loop.sh start "我想做一个帮我记录客户跟进的小工具"
```

一句话就行，不用想得多完整——**想不清楚正是它要帮你解决的问题。**

然后：

```bash
./loop.sh go        # 继续
./loop.sh status    # 看到哪一步了
./loop.sh explain   # 忘了在干嘛？让它用大白话讲一遍
./loop.sh judge     # 它给了个东西，我不知道好不好
./loop.sh correct   # 感觉哪儿不对，但说不清哪儿
./loop.sh back      # 上一步不满意，退回去重做
```

---

## 它怎么想问题

两条原则贯穿全程：

**一、站在前人最好的基础上。**
这世上大概率已经有人把这件事做得很好了。第 2 步会把最强的几个全扒出来、
把能直接用的现成东西列清楚、把信息差挖出来。
**不重造轮子**——包括不重新发明思考方式（`references/框架库.md` 里是几十年验证过的现成框架）。

**二、共性做扎实，独特下重注。**
- 共性 = 所有人都要、不做就出局的。老实照做，不许在这儿创新。
- 独特 = 我们凭什么不一样，以及**用户自己想不到、但一用就对**的那一击。
- 差异化的本质是**取舍**，不是叠加。为了某处极致，其他地方要主动认输。

## 它怎么帮你判断好坏

**你不用能说出标准，你只需要能认出好坏。** 这两件事完全不同——
让你凭空描述"什么是好"，谁都答不上来；但把三个东西摆在你面前问"哪个顺眼"，你一秒就能答。

所以这条流水线**从不问你标准是什么**，而是给你具体的东西看，从你的选择里把标准提取出来。

配套的三件工具：

- **五分钟验收单**：每一步交付时，闸门会直接把清单打在屏幕上，每条都能答"是/否"，
  并标明哪条是**致命项**（这条不过，其他全过也没用）
- **`./loop.sh judge`**：不知道好不好的时候用。它会逼问自己五个问题
  （这方案怎么死、哪些是假设、预算砍一半砍哪儿…），最后给你 A/B/C 选择题，不给你结论
- **`./loop.sh correct`**：感觉不对的时候用。**先归因错在哪一层**再动手——
  执行错、标准错、需求错、目标错，四层的修法和成本差一百倍，
  在错的层上使劲是最常见的烧钱方式

判断的完整方法写在 `references/判断标准.md`，包括**标准分层**（第0层有没有人要 →
第3层撑不撑得住，拿错层的标准判断是最贵的浪费）、**「最好的」和「最适合我的」怎么选**、
以及**完成线和止损线**（大多数项目烂在半路，就是因为只有"什么算好"，没有"什么算够"和"什么算该放弃"）。

## 九步

| | 步骤 | 干什么 | 停不停 |
|---|---|---|---|
| 1 | 目标 | 把一句话想法变成能验证的目标 | 自动 |
| 2 | 巨人的肩膀 | 扒出前人最好的、找现成轮子、挖信息差 | 自动 |
| 3 | 共性与独特 | 共性守什么、独特赌什么 | **你拍板** |
| 4 | 什么算好 | 定义质量标准和取舍 | **你拍板** |
| 5 | 要做什么 | 拆成具体功能 + 验收标准 | **你拍板** |
| 6 | 我不懂的 | 挖出你不知道的坑、名词、法规、真实花销 | 自动 |
| 7 | 技术与落地 | 什么形态、用什么做、**花多少 / 赚多少** | **你拍板** |
| 8 | 任务清单 | 排成可勾选的清单 | 自动 |
| 9 | 开做 | 做→检查→修，自动循环到全部通过 | 自动 |

**只有四步会停下来等你，而且都是选择题**——它给选项、给推荐、给代价，你只做判断。
这四步全是生意问题（赌什么、什么算好、做不做、花多少钱），只有你能定。
其余全自动。

> 为什么不全自动？
> 因为"什么算好"是你的审美。AI 替你定，做出来就是个哪儿都见过的平庸货。
> 这四个停顿，是这条流水线唯一不肯省的地方。

---

## 不一定是软件

产出可以是**软件、视频/内容、服务流程**，或者混合。
第 7 步会先判断属于哪一类，再决定"做"和"检查"分别指什么。
不是软件的项目，它会写一个 `check.local.sh` 把"怎么算做对了"变成能自动检查的东西。

---

## 卡住了怎么办

```bash
./loop.sh explain
```

它会告诉你：现在有什么、走到哪了、下一步是什么、有什么在等你、该担心什么、钱花哪了。
**不贴代码，全是人话。**

自动循环修不好的时候会自己停下来，把选择题摆给你，不会闷头烧钱。

## 目录

```
loop.sh                  主程序
docs/                    每一步的结论都落在这里（你的项目记忆）
references/00-总纲.md    整套东西的门口：是什么、六条原则、该翻哪个文件
references/框架库.md     前人造好的思考工具，直接调用（含「怎么赚钱」）
references/判断标准.md   怎么判断好坏、怎么纠错（标准分层、止损线）
references/现在什么防得住.md 现在什么还算护城河（带查证日期，会过期）
.claude/commands/        每一步的说明书（想改流水线就改这里）
scripts/check.sh         自动检查「东西还正常吗」
.loop/                   进度状态和日志
```

`docs/` 里的文件**你可以随便改**——改字、划掉、补充。
你改过的地方，后面每一步都会当成最高优先级。**那才是你的判断，比它写的重要。**

## 可调的开关

```bash
MAX_BUILD_ROUNDS=30   # 第9步最多循环几轮（防止无限烧钱）
MAX_FIX_TRIES=3       # 一个任务最多自动修几次
```
