读 `docs/00-听到的.md`。**那才是你的输入**——
第0步已经把我随口那段话拆开、分过轻重、挖出真痛点，还问过我几个问题。
`.loop/原始想法.txt` 是原话，只在需要核对原文时看。

产物：`docs/00-目标.md`。

你的任务：**把「他要什么」变成「这笔账成不成立」。**

第0步管听懂，你管算账。**不要再重新推断一遍他要什么**——
那一步已经做完了，而且是他本人确认过的。你从那份文档的
「真实痛点」「真实需求」直接往下接。

不要问我一堆问题。先自己推断，把推断出来的东西摆出来让我否定——
**让我改比让我从头想容易得多。**

## 两条硬规矩，先说在前面

**规矩一：这一步只做「粗定义」，不追求准。**
有几个问题（解决到什么程度、为什么是现在、跟最好的比好在哪）
**在没做调研之前根本答不准**——你都没看过现有最好的，拿什么比？
所以这一步大胆猜，够支撑第2步去调研就行。**第3步会回来精修。**

**规矩二：每条关键判断必须标记来源，不许把猜测伪装成结论。**

```
[事实] 有来源、有日期、能核对的
[推断] 基于事实推的，把推的逻辑写出来
[猜测] 就是猜的 —— 后面必须补一句「如果这条错了，会怎样」
```

**猜测本身没问题，把猜测当事实才有问题。**
标出来之后，我一眼就能看见这份定义的**承重墙在哪儿**——
那些标着 [猜测] 又"错了很惨"的，就是最该优先去验证的东西。

一份读起来完美流畅、看不出哪句是猜的定义，是**危险**的，不是专业的。

---

`docs/00-目标.md` 要包含：

## 一句话目标
「让【谁】能够【做什么】，从而【得到什么好处】」——填满这个句式。

## 这是给谁用的
具体到人。不要写「用户」，写「我自己」「我手下 3 个销售」「我的老客户，大概 50 个，
年纪偏大不太会用手机」。人不一样，东西完全不一样。

**先看 `00-听到的.md` 里我已经确认过的**。那儿有的就直接用，别再猜一遍。
那儿没有的才轮到你猜，标上「（猜的，不对就改我）」。

## 谁掏钱（跟上一条可能不是同一个人）

**这条不许跳过。** 见 `references/框架库.md` 第八节。

```
掏钱的人是：____（跟"用的人"是不是同一个？不是的话，他在乎什么？）
凭什么掏：____（他因此赚到什么 / 省下什么 / 避免了什么）
大概愿意掏多少：____（数量级就行，标"（猜的）"）
如果这东西永远收不到钱，我还做吗：____
```

**最后那一问必须答。** 答"做"——那这就是个爱好或者投资，
后面所有关于成本的判断都要按这个来，不许自欺。
答"不做"——那"能不能收到钱"就是这个项目的**头号风险**，
比功能做得好不好重要得多，后面每一步都要盯着它。

## 你要多少钱、什么时候要（不答这题，后面全是空谈）

**「谁掏钱」答的是有没有钱。这一节答的是够不够。**
大多数点子不是死在"没人付钱"，是死在**结构上根本到不了他想要的那个数**——
而他从头到尾没算过那个数。

### 第一问：钱的形状。给他三选一，不许选"都要"

> **A · 最快见到钱**
> 　 三个月内有人真掏钱，哪怕金额很小。
> 　 会选它的人：手上现金紧、或者需要一个真实成交来验证方向的人——**他是对的**。
> 　 代价：能快速收钱的东西通常门槛低、容易被抄、天花板矮。
>
> **B · 赚最多的钱**
> 　 前一两年可能一分不赚，赌的是做深之后别人进不来。
> 　 会选它的人：有别的收入撑着、能熬、而且这行确实有深水区的人——**他是对的**。
> 　 代价：熬不到那天就归零，而且中途没有任何反馈告诉你走对没有。
>
> **C · 先快后多**
> 　 用快的那个养活自己，同时攒抠不走的东西（受众、数据、关系、习惯）。
> 　 会选它的人：大多数人——**这通常是对的答案，但也是最难执行的。**
> 　 代价：**快的那件事会吃掉你全部时间**，然后你会告诉自己"等忙完这阵再攒"，
> 　 　 　 然后就没有然后了。选 C 必须当场定死：每周分给"慢的那件事"几个小时。

**别把 C 当成"两个都要"的安全牌。** 见原则八：
**速度不是护城河，速度是买护城河的钱。** 选 C 就是明说"我先挣钱，
然后拿挣到的时间去买抠不走的东西"——**买不到，快就白快了。**

### 第二问：具体数字

```
每个月要净赚 ____ 元（净赚，不是流水）
____ 个月内做到
到不了这个数的话，我会 ____（继续做／停掉／改方向）
```

**最后那行就是止损线的雏形**，第4步会把它写死。

### 第三问：倒推算账（这是纯算术，不是预测）

**我们不预测这个方向未来会怎样——那是编。
我们只算「要成立必须满足什么」，然后去查那些条件现在成不成立。**

```
一单赚 ____ 元（毛利，扣掉成本，不是售价）
→ 每月需要 ____ 单        = 目标 ÷ 单笔毛利
→ 每单需要接触 ____ 个人   （成交率取 __%，这个数必须标：
                            [查证，来源__] 还是 [猜的]）
→ 每月需要 ____ 个人看到
→ 每天需要 ____ 个人看到

最后一问，必须直答：
这个数字，靠你现在能想到的渠道，拿得到吗？
　[拿得到，因为____ ／ 拿不到 ／ 不知道]
```

**最后那一问是这一整步最狠的地方。**
大多数点子在这儿当场就死了，而且死得很干净——
**不是因为想法不好，是因为算术不成立。**

三种答案三种走法：
- **拿不到** → 要么改数字，要么改单价（提高客单价，需要的人数就少了），
  要么换方向。**别硬着头皮往下走，后面八步都会白干。**
- **不知道** → 这是最诚实也最危险的答案。
  **把它写进 `05-我不懂的.md`，标成头号待验证项。**
- **拿得到** → 那个"因为"必须具体到能核对，不许写"做内容就能来"。

**这一节算出来的所有数字，第2步要拿去和这行真实的量级对照。**
你算出来每月要 300 单，而这行做得最好的人一个月 80 单——那就是算术层面的死刑。

## 他们从哪儿知道这东西（第一批 100 个人从哪来）

**这条和「谁掏钱」一样，不许跳过。** 见 `references/框架库.md` 第九节。

理由：AI 把「做出来」的成本压到了接近零，**能被抄的都不算护城河**，
所以现在最防得住的是"谁认识你、谁信你"。做完了才开始找人，是最慢也最贵的路。

```
第一批 100 个人从哪来：____（具体到能明天动手，不许答"发朋友圈""投广告"）
我现在已经能触达多少人：____（真实数字，不是估计。是 0 就写 0）
主力分发方式：____（嵌进别人的平台 / 内容先行 / 靠人传人 / 花钱买）
  为什么选这条，不选另外三条：____
```

**如果"现在能触达的人"是 0**——那"建受众"就是你的第一个任务，
不是等产品做完之后的任务。这一点后面排任务清单时会用到。

（这条现在只能粗答，标 [猜测]。第2步调研完，第3步回来精修。）

## 现在没有这东西的时候，这事怎么办
描述现状的痛。如果现状其实没那么痛，请直说——
有可能这东西不值得做，早知道比晚知道好。

## 解决到什么程度（不是解决不解决，是解决多深）

**需求不是有无，是深度。** 同一个需求，解决 60% 和解决 95%，
是**两门成本差十倍的生意**。不划这条线，你会不自觉地一直加深度，永远做不完——
因为每加一点都"显然更好"。

```
这个需求我们解决到 ____ 为止。
剩下的 ____ 明确不管，用户得自己想办法 / 找别的工具。
为什么线画在这儿：____
```

**注意别跟「完成线」搞混**（那条在 `docs/03-什么算好.md`）：
- **这一条** = 需求覆盖的停止线（解决到这个份上就够，剩下的不管）
- **完成线** = 质量的停止线（做到这个精度就发出去，不许再打磨）

**缺前者会无限扩张，缺后者会无限打磨。两条都得有。**

（这条现在只能粗答，标 [猜测]。第2步看完别人解决到什么程度，第3步回来改。）

## 为什么是现在

如果这件事**三年前也能做、三年后也能做**，那它没有窗口，
而且说明**不紧迫**——你不做别人也不做，因为没人急。

能答出来的答案只有几种，选一个并说清楚：
- 技术变了（以前做不到，现在能了）
- 平台/规则变了
- 成本降了（以前不划算，现在划算了）
- 人群/习惯变了
- 某个前置条件刚成熟

```
为什么是现在：____
这个窗口大概还有多久：____
如果我晚一年做，会怎样：____
```

答不出来也要写：「暂时想不到为什么非得是现在 [猜测]」——
**这不是致命伤，但它意味着你没有时间压力，也没有时间红利，纯拼执行。**
知道这一点，比自欺一个理由强。

（这条要查证，第2步会验。）

## 为什么是我

这一条问的不是"这东西是什么"，是"**凭什么是你来做**"。

漏掉它的代价有两个，都很实：

1. **它决定你能不能扛过中间那段。** 任何项目中段都有一个
   "没劲、看不到头、想放弃"的坑。那时候撑住你的不是目标写得多漂亮，
   是你为什么非做这个不可。
2. **你唯一复制不了的优势，只能从这儿来。** 第3步会问
   「有哪一条是别人复制不了的」——那题的答案只可能来自这里。

```
我的什么经验/资源/关系，让我做这个比别人有优势：____
我为什么非做这个不可（不做会怎样）：____
换个完全不认识这行的人来做，他会缺什么：____
```

**如果最后那一问的答案是"他什么都不缺"**——那说明这个定义
任何人都能执行，你只是比别人早想到一步。
**早想到一步不构成护城河。** 这时候要么找到你独有的东西，要么就得靠跑得比别人快。
两条都行，但你得知道自己在靠哪条。

## 怎么算成功
一条可以量化或者至少能明确判断的标准。
- ✅「每天录客户信息的时间从 40 分钟降到 10 分钟以内」
- ❌「提升效率」

## 明确不做什么
列 3–5 条。这是防止越做越大的刹车。

## 时间和预算的大致边界
如果我没说，你给个建议数字，标明「（建议值，不对就改我）」。

## 现在在第几层（很重要，后面每次判断都要看这个）
读 `references/判断标准.md` 第一节，判断这个项目现在处在哪一层，写明：

```
现在在第 X 层：____
这一层要看的：____
这一层【不许看】的：____
```

绝大多数新项目都在**第0层（有没有人要）**。
如果你判断在更高层，必须说明凭什么——是已经有人在用了，还是只是我觉得肯定有人要？
**"我觉得肯定有人要"不算证据。**

写完之后，用大白话跟我说三句话。
**「我理解你想要的是…」不用再说了**——第0步已经说过，我也确认过了。
这一步要说的是账：

1. 这笔账要成立，必须满足的是 ____
2. 这里面最靠不住的一个数是 ____
3. 我看到的最大风险是 ____

然后停。不要继续往下做。

- [ ] 钱的形状选了（最快／最多／先快后多），选 C 的话每周留给"慢的那件事"
