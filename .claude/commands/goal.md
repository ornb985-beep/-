读 `.loop/原始想法.txt`，那是我随口说的一句话，肯定不完整。

产物：`docs/00-目标.md`。

你的任务：把那句话变成一个**能验证成没成**的目标。

不要问我一堆问题。先自己推断，把推断出来的东西摆出来让我否定——
**让我改比让我从头想容易得多。**

## 两条硬规矩，先说在前面

**规矩一：这一步只做「粗定义」，不追求准。**
有几个问题（解决到什么程度、为什么是现在、跟最好的比好在哪）
**在没做调研之前根本答不准**——你都没看过现有最好的，拿什么比？
所以这一步大胆猜，够支撑第2步去调研就行。**第3步会回来精修。**

**规矩二：每条关键判断必须标记来源，不许把猜测伪装成结论。**

```
[事实] 有来源、有日期、能核对的
[推断] 基于事实推的，把推的逻辑写出来
[猜测] 就是猜的 —— 后面必须补一句「如果这条错了，会怎样」
```

**猜测本身没问题，把猜测当事实才有问题。**
标出来之后，我一眼就能看见这份定义的**承重墙在哪儿**——
那些标着 [猜测] 又"错了很惨"的，就是最该优先去验证的东西。

一份读起来完美流畅、看不出哪句是猜的定义，是**危险**的，不是专业的。

---

`docs/00-目标.md` 要包含：

## 一句话目标
「让【谁】能够【做什么】，从而【得到什么好处】」——填满这个句式。

## 这是给谁用的
具体到人。不要写「用户」，写「我自己」「我手下 3 个销售」「我的老客户，大概 50 个，
年纪偏大不太会用手机」。人不一样，东西完全不一样。
你不确定就写你的猜测，标上「（猜的，不对就改我）」。

## 谁掏钱（跟上一条可能不是同一个人）

**这条不许跳过。** 见 `references/框架库.md` 第八节。

```
掏钱的人是：____（跟"用的人"是不是同一个？不是的话，他在乎什么？）
凭什么掏：____（他因此赚到什么 / 省下什么 / 避免了什么）
大概愿意掏多少：____（数量级就行，标"（猜的）"）
如果这东西永远收不到钱，我还做吗：____
```

**最后那一问必须答。** 答"做"——那这就是个爱好或者投资，
后面所有关于成本的判断都要按这个来，不许自欺。
答"不做"——那"能不能收到钱"就是这个项目的**头号风险**，
比功能做得好不好重要得多，后面每一步都要盯着它。

## 现在没有这东西的时候，这事怎么办
描述现状的痛。如果现状其实没那么痛，请直说——
有可能这东西不值得做，早知道比晚知道好。

## 解决到什么程度（不是解决不解决，是解决多深）

**需求不是有无，是深度。** 同一个需求，解决 60% 和解决 95%，
是**两门成本差十倍的生意**。不划这条线，你会不自觉地一直加深度，永远做不完——
因为每加一点都"显然更好"。

```
这个需求我们解决到 ____ 为止。
剩下的 ____ 明确不管，用户得自己想办法 / 找别的工具。
为什么线画在这儿：____
```

**注意别跟「完成线」搞混**（那条在 `docs/03-什么算好.md`）：
- **这一条** = 需求覆盖的停止线（解决到这个份上就够，剩下的不管）
- **完成线** = 质量的停止线（做到这个精度就发出去，不许再打磨）

**缺前者会无限扩张，缺后者会无限打磨。两条都得有。**

（这条现在只能粗答，标 [猜测]。第2步看完别人解决到什么程度，第3步回来改。）

## 为什么是现在

如果这件事**三年前也能做、三年后也能做**，那它没有窗口，
而且说明**不紧迫**——你不做别人也不做，因为没人急。

能答出来的答案只有几种，选一个并说清楚：
- 技术变了（以前做不到，现在能了）
- 平台/规则变了
- 成本降了（以前不划算，现在划算了）
- 人群/习惯变了
- 某个前置条件刚成熟

```
为什么是现在：____
这个窗口大概还有多久：____
如果我晚一年做，会怎样：____
```

答不出来也要写：「暂时想不到为什么非得是现在 [猜测]」——
**这不是致命伤，但它意味着你没有时间压力，也没有时间红利，纯拼执行。**
知道这一点，比自欺一个理由强。

（这条要查证，第2步会验。）

## 为什么是我

这一条问的不是"这东西是什么"，是"**凭什么是你来做**"。

漏掉它的代价有两个，都很实：

1. **它决定你能不能扛过中间那段。** 任何项目中段都有一个
   "没劲、看不到头、想放弃"的坑。那时候撑住你的不是目标写得多漂亮，
   是你为什么非做这个不可。
2. **你唯一复制不了的优势，只能从这儿来。** 第3步会问
   「有哪一条是别人复制不了的」——那题的答案只可能来自这里。

```
我的什么经验/资源/关系，让我做这个比别人有优势：____
我为什么非做这个不可（不做会怎样）：____
换个完全不认识这行的人来做，他会缺什么：____
```

**如果最后那一问的答案是"他什么都不缺"**——那说明这个定义
任何人都能执行，你只是比别人早想到一步。
**早想到一步不构成护城河。** 这时候要么找到你独有的东西，要么就得靠跑得比别人快。
两条都行，但你得知道自己在靠哪条。

## 怎么算成功
一条可以量化或者至少能明确判断的标准。
- ✅「每天录客户信息的时间从 40 分钟降到 10 分钟以内」
- ❌「提升效率」

## 明确不做什么
列 3–5 条。这是防止越做越大的刹车。

## 时间和预算的大致边界
如果我没说，你给个建议数字，标明「（建议值，不对就改我）」。

## 现在在第几层（很重要，后面每次判断都要看这个）
读 `references/判断标准.md` 第一节，判断这个项目现在处在哪一层，写明：

```
现在在第 X 层：____
这一层要看的：____
这一层【不许看】的：____
```

绝大多数新项目都在**第0层（有没有人要）**。
如果你判断在更高层，必须说明凭什么——是已经有人在用了，还是只是我觉得肯定有人要？
**"我觉得肯定有人要"不算证据。**

---

写完之后，用大白话跟我说三句话：
1. 我理解你想要的是 ____
2. 我猜的、可能猜错的地方是 ____
3. 我看到的最大风险是 ____

然后停。不要继续往下做。

## 文档末尾必须有验收单

在 `docs/00-目标.md` 末尾加上这一段，条目要具体到我不用懂技术就能判断真假：

```
## 怎么验收这一步
- [ ] 那句话目标里的「谁」，具体到我能立刻想起某个真人
- [ ] 「谁掏钱」答了，包括「收不到钱还做吗」
- [ ] 「解决到什么程度」划了线，而且写清了剩下的明确不管
- [ ] 「为什么是现在」有个说法，答不出来也明写了
- [ ] 「为什么是我」里，至少有一条是换个人来做会缺的
- [ ] 「怎么算成功」带数字，不是形容词
- [ ] 「不做什么」至少 3 条，而且我确实舍得不做
- [ ] 每条关键判断都标了 [事实|推断|猜测]，看得出哪儿是猜的
- [ ] 【致命项】现状的痛是真的，不是我脑补的——我能说出上次为这事烦躁是什么时候
```
