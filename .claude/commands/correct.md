我觉得哪儿不对劲，但说不清是哪儿。**先别急着改东西，先搞清楚错在哪一层。**

读 `references/判断标准.md` 第四节，然后按下面做。

## 第一步：归因（这一步最重要，做错了后面全白费）

按顺序问，**第一个答"是"就停下**，不要继续往下猜：

1. 做出来的东西，符合 `docs/04-要做什么.md` 里写的验收标准吗？
   → 不符合 = **执行错**
2. 符合标准，但我还是不满意？
   → **标准错**（`docs/03-什么算好.md` 定歪了）
3. 标准也没问题，但这东西根本没人用？
   → **需求错**（`docs/04-要做什么.md` 做错了东西）
4. 有人用，但对生意没帮助？
   → **目标错**（`docs/00-目标.md` 方向不对）

**明确告诉我结论**：「这是【X 错】，因为 ____ 。」
不确定的话，把两种可能都摆出来，各自给一个"怎么快速确认"的办法。

## 第二步：算清代价，让我选

不同层的修法成本差一百倍，我得知道我在买什么：

```
## 修这个要付出什么

错误层级：____
修法：____
需要重做的：____（具体到哪些文件、哪些已完成的任务）
作废的工作量：约 ____
需要重新拍板的步骤：____

## 不修会怎样
____（如果代价能接受，"不修"也是个正当选项，说清楚）
```

**「先不修，带着这个问题往下走」永远是选项之一。**
不是所有的错都值得当场修——有些错要等更多信息才看得清。
如果你建议先不修，说明什么时候再回头看它。

## 第三步：给出纠错动作

按错误层级给具体命令：

- **执行错** → 哪个任务要重做。把 `docs/07-任务清单.md` 里对应的 `[x]` 改回 `[ ]`，
  在任务后面注明「重做原因：____」，然后 `./loop.sh go`
- **标准错** → `./loop.sh back` 退到什么算好那一步，说清该改哪一条标准
- **需求错** → 退到要做什么那一步，说清该砍/该加什么
- **目标错** → 停下来。这一层我必须亲自想，你只负责把「如果改成 ____ ，
  前面哪些工作还能用、哪些作废」摆清楚给我看

## 第四步：铁律自查

改之前确认三条（`references/判断标准.md` 第四节）：

- [ ] **没有在错的层上使劲**——目标错了就别打磨执行
- [ ] **这次只改一层**——同时改两层，下次还会错，因为你不知道是哪个起的作用
- [ ] **想清楚了这个错是怎么发生的**

第三条展开写一句：

```
这个错是怎么来的：
□ 信息不够——当时查不到 ____
□ 判断失误——当时看到了但想错了
□ 明知有风险，赌了——赌的是 ____，没赌中

（第三种要记进 docs/学习笔记.md：判断本身没错，只是运气不好，
  下次同样情况还该这么赌。这条以后能救你。）
```

## 第五步：防复发

一句话：**「下次怎么早点发现这个问题？」**
如果答案是某个能自动检查的东西，就加进 `check.local.sh`。
如果是需要人看的，就加进对应步骤文档末尾的「怎么验收这一步」。

---

## 不许做的事

- **不许一上来就改代码。** 没归因就动手，八成改错地方，而且会把问题掩盖掉。
- **不许因为"已经做了很多了"就避重就轻。** 已经花掉的钱和时间是拿不回来的，
  它不该影响现在的判断。往前看，别往回看。
