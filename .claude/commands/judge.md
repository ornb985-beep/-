我拿到了一份东西（方案、文档、或者做出来的成品），但我不知道该怎么判断它好不好。
**别问我"你觉得怎么样"——我要是知道就不问你了。**

读 `references/判断标准.md`，然后按下面做。

## 第一步：先确认现在该用哪一层的标准

看 `docs/00-目标.md` 里写的当前层级（第0/1/2/3层）。没写就自己判断并告诉我。

明确说一句：**「现在该看的是 ____，不该看的是 ____ 。」**

这句话是这一步最重要的输出。
大多数误判都来自这里——用"好不好看"去判断一个还没验证"有没有人要"的东西。

## 第二步：逼问五题（自问自答，不许含糊）

对着这份东西，你自己回答，答案要具体：

1. **这东西最可能怎么死？** 说不出来就是没想清楚，直说。
2. **哪些是假设，不是事实？** 逐条列，每条标「错了会损失多大」。
3. **最贵的那一步，能不能先花小钱验证？** 能就说怎么验；不能就明说这是在赌。
4. **如果预算/时间砍一半，砍哪儿？** 砍不动 = 没有优先级。
5. **跟「什么都不做」比，好在哪？**

再闻两个味道：
- 有没有"全都要"的痕迹？（好方案一定看得见取舍）
- 有没有具体数字？（全是形容词 = 空的）

## 第三步：给我一个五分钟能用的验收单

这是给我用的，所以**必须满足三个条件**：
- 每条我不用懂技术就能判断
- 每条能明确答"是"或"否"，不许出现"比较好""基本满足"
- 总共不超过 7 条，五分钟能过完

```
## 五分钟验收单
- [ ] （具体到能一眼看出真假的描述）
- [ ] ...

其中【第 X 条】是致命项——这条不过，其他全过也没用。
```

**必须指出哪条是致命项。** 没有致命项的验收单是摆设。

## 第四步：给我选择题，不要给我结论

不要说"我觉得这个方案不错"。给我这个：

```
## 你现在有三条路

A. 就这么定，往下做
   适合：____（什么情况下选它）
   风险：____
   
B. 改一处再往下：改 ____
   适合：____
   代价：多花 ____

C. 这个方向不对，退回第 ____ 步重来
   适合：____
   损失：已经花掉的 ____

我推荐：____，因为 ____
```

## 第五步：告诉我你自己最不确定的地方

一句话：**「这份东西里，我最没把握的是 ____，因为 ____ 。」**

这句话比前面所有分析都值钱。你要是全都很有把握，那多半是你没想深。

---

## 不许做的事

- 不许通读一遍然后说"整体不错，建议优化以下几点"——这是废话
- 不许用"最佳实践""行业标准"当理由，除非你查证过并给出来源
- 不许因为这东西是你自己刚做的就手下留情。**你现在的角色是挑刺的人，不是作者。**
