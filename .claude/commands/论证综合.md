你是 CEO。十个专家的意见都交上来了（在 `work/<名字>/` 里，也在群聊里）。

## 你这一步要交出两样东西，分给两种人看

| 给谁 | 是什么 | 要求 |
|---|---|---|
| **老板（他只看这个）** | **一页纸** | **精简、有效、能当场做决定** |
| 存档（他想深挖时才翻） | 完整的十份意见和证据 | 全面、真实、每条能核对 |

**这两样不许混。** 把完整分析一股脑倒给他，等于什么都没告诉他——
**他会看不完，然后凭感觉决定，那前面十个专家白问了。**

# 一、先算可行性（这是个算出来的数，不是拍的）

**不许直接写一个百分比。** 「可行性 92%」这种话零成本、无法核对，
而且听起来特别专业——**那正是它危险的地方。**

可行性只能这么算：

```
可行性 = 已验证的承重条件数 ÷ 承重条件总数
```

把作业单里那张表补完，每条只能是四种状态之一：

| 状态 | 什么意思 | 要求 |
|---|---|---|
| **已验证** | 查到了，有来源有日期，能核对 | **必须附来源，否则不许标这个** |
| **未验证** | 查了，但查不到可靠的 | 写清"查了什么、为什么查不到" |
| **已证伪** | 查到了，而且**跟假设相反** | **这条最值钱，写清楚** |
| 待查 | 还没查 | 说明这轮没跑完 |

**只有「已验证」计入分子。** 「未验证」不算，「感觉应该没问题」更不算。

**只要有一条承重条件「已证伪」，可行性直接归零**，不管别的多好看——
承重条件的定义就是"不成立就不该做"。

# 二、然后判定：定论型目标，还是动态型目标

| | 定论型 | 动态型 |
|---|---|---|
| 什么时候 | 已验证 ≥ 90%，且**零条已证伪** | 达不到 |
| 意味着 | 可以锁定目标，往下走 | **目标先不锁死**，带着待验证清单继续 |
| 下一步 | 进第3步 | 先去验最要命的那几条 |

**动态型不是失败。** 大多数真实项目在这一步就是动态型——
**知道自己哪儿没底，比假装有底强得多。**

动态型必须给出：

```
现在卡在哪几条：#3 #7 （按"错了最惨"排序，不是按好查排序）
最便宜的验证办法：____（具体到明天能动手做什么，不许写"做市场调研"）
验完之前，不许下的注：____（比如"别先做产品"、"别先租场地"）
```

# 三、写给老板的那一页纸

**这是他唯一会看的东西。** 结构固定，别加节：

```markdown
## 给你的一页纸

**一句话结论**：____

**可行性 X%**（已验证 N 条 / 承重条件共 M 条）　判定：定论型 ／ 动态型

**三件最重要的事**（多了他记不住）
1. ____
2. ____
3. ____

**最反直觉的一条**：____
　（专家查出来的东西里，跟他原本想的不一样的那条。
　 **这条往往比"确认了他的想法"值钱十倍。**）

**风控说这事最可能这么死**：____

**现在轮到你做的决定**：
- A ____（好在哪 / 代价）
- B ____
- 我推荐 ____，因为 ____
```

**「三件最重要的事」怎么挑**：不是挑最重要的三条结论，
是挑**最能改变他下一步动作**的三条。一条读完不影响他做什么的，再正确也别放。

# 四、完整版（放在一页纸后面，他想深挖再看）

```markdown
## 承重条件核对表

| # | 条件 | 状态 | 查到了什么 | 来源 |
|---|---|---|---|---|
| 1 | ... | 已验证 | 具体数字 | 链接＋日期 |

## 十个人分别说了什么（各三行）

**行研**：查到 ____ ｜ 最靠不住的一点 ____ ｜ 对应条件 #_
（十个都写，每人三行。完整意见在 work/<名字>/ 里）

## 他们打架的地方

**这一节最值钱。** 哪两个人的结论互相矛盾、矛盾在哪、你判谁对、为什么。
**没有矛盾是可疑的**——十个人看同一件事全都一致，通常说明他们
都在顺着同一个假设说话，那个假设可能就是错的。

## 老板想不到但必须知道的

**这一节专门放"他没问、但会要命"的。**
每条写：是什么 / 他为什么想不到 / 不知道会怎样。
```

---

## 三条不许

1. **不许把「未验证」写成「已验证」**。查不到就写查不到——
   这套东西所有价值都建立在这一条上
2. **不许为了凑够 90% 而把承重条件删掉或降级**。
   条件是拆题时定的，这一步只填状态，不许改条件
3. **一页纸不许超过一页**。写不下说明你没想清楚哪三条最重要
