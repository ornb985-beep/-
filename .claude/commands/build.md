description: 第9步 · 做任务清单里的下一个任务
---

打开 `docs/07-任务清单.md`，找到**从上往下第一个** `- [ ]` 的任务。就做这一个，做完就停。

## 做的规矩

1. **只做这一个任务。** 顺手看到别的问题，记到 `docs/07-任务清单.md` 末尾当新任务，不要顺手改。
   一次改一件事，出问题才知道是谁干的。

2. **照着 `docs/06-技术与落地.md` 定好的技术做。** 想换技术，停下来问我，不许自作主张。

3. **对照 `docs/03-什么算好.md` 做取舍。** 每次遇到「A 方案还是 B 方案」，
   回去看我在那个文件里选了什么。那是我的审美，不是可选参考。

4. **每次想妥协之前，先看「绝不能牺牲的」那三条。**
   凡是你打算说「这个先简化一下」「这块暂时跳过」「这样也够用了」的时候——
   **先回 `docs/03-什么算好.md` 看那三条，确认没碰到。**

   碰到了就不许自己决定，停下来告诉我，写清楚：
   要动的是哪一条、为什么不得不动、有没有别的办法。

   理由：妥协是一次一点、每次都合理地发生的，
   等我察觉的时候东西已经变味了，而且谁也说不清是哪一步丢的。

5. **写完自己跑 `bash scripts/check.sh`。** 不过就自己修，别丢给我。

6. **任务里带「【停下来给我看】」的**，就把东西跑起来，
   告诉我具体怎么打开（精确到"在浏览器地址栏输入 localhost:3000"这种程度），
   我该看什么、什么样算对。然后停下。

   **停下来之前必须多问我一句**：

   > 「看完这个实物，`docs/03-什么算好.md` 里有没有哪一条你想改？」

   这一问不许省。原因：我当初定标准的时候还没见过实物，
   见到实物之后我的判断会变——**那个变化才是真的，纸上写的是猜的**。
   我说要改，你就去改那个文件，并且在末尾的「标准修订记录」里记一笔。
   我说不用改，也记一笔「看过，没改」。

## 做完之后必须做的三件事

1. 把 `docs/07-任务清单.md` 里这条的 `- [ ]` 改成 `- [x]`。
   **忘了这步，自动循环会以为没进展，然后卡住。**

2. 如果这个任务里用到了我可能不懂的东西，在 `docs/学习笔记.md` 末尾追加一小段：

   ```
   ## （日期）今天用到了 XXX
   它是干什么的：一句白话
   为什么这儿需要它：一句话
   你需要记住的：一句话（大多数时候是"不用记，知道有这么个东西就行"）
   ```

   这个文件是我的技术扫盲课，一点点攒。别写长，每次三五行。

3. 用两句话跟我汇报：做完了什么、下一个是什么。不要贴代码，我看不懂。

## 卡住了怎么办

试两次还不行，就别硬试。在 `docs/05-我不懂的.md` 末尾追加：

```
## 卡住了：（任务名）
卡在哪：白话描述
我试了什么：1... 2...
需要你决定：（选择题 A/B，附推荐）
```

然后停下来告诉我。**卡住不丢人，闷头瞎试才是浪费钱。**
