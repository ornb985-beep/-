读 `docs/00-目标.md` 和 `docs/01-巨人的肩膀.md`，以及 `references/框架库.md`。

产物：`docs/02-共性与独特.md`。

这一步回答一个问题：**已经有人做得很好了，凭什么是我们？**
答不上来就别做——这不是打击，是省钱。

## 一、共性：所有人都必须做到的（地基）

从 `docs/01-巨人的肩膀.md` 的「标准做法」里，提炼出**不做就出局**的清单。

```
- [必须] ____ ｜ 不做的后果：____
```

**规矩：这一栏里的东西，一条都不许"创新"。**
地基上搞创意是自杀。这些老老实实做到行业平均水平就行，不用超越。

再往下挖一层——用 `references/框架库.md` 里的 Kano 模型和影响力六原则：
**用户真正在乎的、不变的东西是什么？**（省时间？少操心？显得专业？被认可？）
写成一句话。这句话是整个项目的锚，后面所有取舍都回来看它。

## 二、独特：我们在哪儿不一样（楼）

用 ERRC 四步动作框架，四格必须填满：

```
### 剔除 —— 行业都在做，但用户其实不在乎的，我们不做
- ____ ｜ 省下的成本/精力：____ ｜ 风险：____

### 减少 —— 做到及格就行，不追求超越
- ____ ｜ 降到什么程度：____

### 增加 —— 远远超过行业水平
- ____ ｜ 超到什么程度：____ ｜ 为什么用户会在乎：____

### 创造 —— 这行从来没有过的
- ____ ｜ 为什么以前没人做：____（这条很重要，认真答）
```

**「剔除」和「减少」填不出来的，退回去重填。**
差异化的本质是**取舍**，不是叠加。什么都做的结果是什么都平庸，而且钱不够。

「为什么以前没人做」这题必须认真答，只有三种答案：
- **以前做不到，现在技术/平台变了** → 这是真机会，抓紧
- **以前不划算，现在成本降了** → 也是真机会
- **有人做过，死了** → 回去查它怎么死的，别当第二个

答不出来第四种。如果你觉得"就是没人想到"，八成是你没查够，回去查。

## 三、「他们想不到，但一用就对」的那一击

这是整个项目最值钱的部分，认真做。

用 Kano 模型的「兴奋型需求」+ JTBD 的第三层动机（身份认同层）：
找出 **用户说不出口、但戳中了会立刻叫好** 的点。

挖的方法（至少试三种）：
1. 去看竞品的**差评和客服记录**，找那种"用户在抱怨，但抱怨的其实不是它说的那件事"
2. 找用户为了绕开某个问题，**自己发明的土办法**——土办法出现的地方就是需求的信号弹
3. 问：用完我们的东西之后，用户会**怎么跟别人形容自己**？（"我是那种用XX的人"）
4. 问：这件事里，用户觉得**理所当然要忍受**的麻烦是什么？（麻烦忍久了会变得看不见，而它可以被消灭）

给出 2–3 个候选，每个写：
```
### 候选：____
用户表面的说法：____
底下真正的需求：____
戳中之后他的反应会是：____
实现难度：低/中/高
竞品为什么没做：____
```

## 四、一句话立不立得住

把结论压缩成一句话（`references/框架库.md` 里的定位公式）：

> 在【具体到窄的领域】里，我们是唯一/第一个【怎么样】的，
> 因为我们【剔除了什么】换来【增加了什么】，
> 这戳中的是【什么不变的人性需求】。

**这句话说给一个完全不了解的人听，他能不能立刻明白、并且觉得"有点意思"？**
不能，就回去改。这一句话立不住，后面做什么都是白费。

## 五、自检：会不会只是"标准答案"

问一遍：**换一个人用同样的框架、查同样的资料，会不会得出跟我一模一样的结论？**

如果会——说明这里面还没有你的东西。
把我（使用者）的行业经验、见过的人、独有的资源列出来，
问：**有哪一条是别人复制不了的？** 把它加进差异化里。

---

写完用大白话跟我说：
1. 我们跟最强的那个对手，最大的区别是哪一条（一句话）
2. 你最没把握的是哪个假设，怎么花最少的钱验证它
3. 如果这个差异化被大厂看到并且抄走，我们还剩什么

然后停下。**这一步定的是这东西的命，我不点头你不许往下做。**
