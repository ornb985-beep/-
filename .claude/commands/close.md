## 这份东西写给谁看

**写给半年后的他。** 那时候他已经忘了细节，只会记得一个模糊的印象
——而模糊的印象几乎总是错的（成了的会被记成"我早就知道"，
败了的会被记成"运气不好"）。

**所以这份复盘的唯一价值，是把当时真实的判断和真实的数字钉住。**

## 硬规矩

1. **不许写得好看。** 这不是对外的总结，是给自己的账。
2. **所有数字从记录里来，不许估。** 没有记录就写「没有记录」——
   **那本身就是一条教训。**
3. **不许把运气说成本事，也不许把本事说成运气。**
   分不清的就老实写「分不清」。

# `docs/99-结项.md` 要包含这些

## 一、结论先行：这个项目怎么了

三选一，必须明说，不许含糊：

```
[做成了]   达到了 00-目标.md 里定的那个数
[没做成]   没达到，到止损线了，停
[改方向了] 中途变成了另一件事（那就写清楚变成了什么，为什么）
```

## 二、账（全部从记录里抄，不许估）

```
从 ____ 开始，到 ____ 结束，一共 ____ 天

目标是：____（抄 00-目标.md 的原话，不要转述）
实际做到：____

花出去：
  AI 调用 $____（来自 .loop/cost.tsv，一共 ___ 次）
  其他   ____（订阅、工具、外包，有多少写多少）
收回来：____（一分没有就写 0，不许美化成"积累了经验"）

任务清单：做完 __ / 共 __
```

## 三、真正的死因（或者成因）

**只写一条。** 写不出一条，说明还没想清楚。

```
最关键的那一下是：____

它发生在什么时候：____
当时能不能看出来：[能，我们看到了但没当回事 ／ 能，但我们没看 ／ 看不出来]
```

**「看到了但没当回事」是最贵的一种**，如果是这种，写清楚当时为什么没当回事。

## 四、当初的判断，事后看对了几条

去 `docs/00-目标.md` 和 `docs/03-什么算好.md` 里把标着 `[猜测]` 的
挑出来，逐条对账：

```
| 当初猜的 | 后来实际是 | 对/错 | 如果当时验了，会省多少 |
```

**这一栏是整份复盘最值钱的地方**——它告诉他下次该先验哪种猜测。

## 五、标准改过几次

看 `docs/03-什么算好.md` 末尾的「标准修订记录」：

```
一共改过 __ 次标准
```

- **改过 3 次以上** → 好，说明真的在碰现实
- **一次没改** → 危险信号。**要么全程没碰到真东西，
  要么在护着当初的判断。** 老实写是哪一种。

## 六、下次不再犯的，最多三条

**最多三条。** 写十条等于没写，他一条都记不住。

每条必须是**下次能当场执行的动作**，不是感悟：

```
❌ 要更重视验证    ← 这是感悟，下次照样不做
✅ 花钱超过 ¥500 之前，必须先找 3 个真人问过愿不愿意付钱
```

## 七、留给下一个项目的东西

```
可以直接复用的：____（做好的模板、跑通的流程、认识的人）
绝对不要再用的：____（哪个方案、哪条路、哪种做法）
```

## 最后，跟他说三句话

1. **一句话说清这个项目怎么了**（不带情绪，就是事实）
2. **最该早点做的那一件事是什么**
3. **有没有哪条教训，其实在 `references/` 里早就写着，但我们没照做**
   ——如果有，**那才是真正要认的账**：不是不知道，是知道了没做。

写完提醒他：
**这份东西过半年再看一遍。教训的保质期，比结论长得多。**
