读 `docs/` 下已有的全部文档。

这一步专门对付一件事：**我不知道自己不知道什么。**
你见过一万个类似项目是怎么翻车的，我没见过。把那些坑提前挖出来。
主力工具是 `references/框架库.md` 里的「逆向思维」——
先想清楚怎么必死，再一条条避开。

产物：`docs/05-我不懂的.md`。

## 分四类写

### 一、你必须知道的名词（不然后面听不懂）
挑出这个项目里绕不开的 5–8 个词。每个这样写：

> **API**
> 一句话：两个软件之间说话的接口。
> 打个比方：像餐厅的服务员——你不用进厨房，跟服务员说要什么，他给你端出来。
> 在你这个项目里：我们要用微信的 API 来发通知，意思是我们不自己做通知功能，
> 让微信替我们发。
> 你需要为它做的决定：无 / 有（有的话写清是什么）

判断标准：如果这个词后面会出现在给我看的文档里，就必须在这儿解释。

### 二、别人做这类东西，通常栽在哪
**必须用 WebSearch 查证**，不要凭印象写。找 5 条真实的坑，每条写：
坑是什么 → 为什么会踩 → 我们怎么绕开 → 绕开的代价。

### 三、有没有什么规矩会卡我（重点查）
- 这类东西有没有法规限制（比如存客户手机号涉不涉及个人信息保护）
- 用到的平台有没有规则限制（比如微信不让干什么、App Store 会不会拒审）
- 有没有资质门槛（备案、执照、支付牌照）

**这一类必须查证**，写清查证日期和来源链接。查不到就明写「查不到，上线前需要找人确认」——
不许猜。这一类猜错，是会真的赔钱的。

### 四、钱和时间的真实数字
把后面会花的钱列出来（服务器、域名、各种服务的订阅费），
分「一次性」和「每个月」。同样必须查证当前价格，标注日期。
免费额度写清楚：免费到什么程度、超了之后按什么收费。

## 最后一段固定写这个

```
## 需要你现在就决定的事
1. （选择题，A/B/C，附推荐和理由）
2. ...

## 不着急但早晚要决定的事
1. ...

## 我查不到、需要你去问人的事
1. （具体到该问谁、问什么）
```

---

写完之后，用大白话跟我说：
- 这里面**最贵的一个坑**是哪个（踩了要赔多少钱或者浪费多少时间）
- 有没有什么发现，严重到应该回头改 `docs/02-共性与独特.md` 或 `docs/04-要做什么.md`？
  有就直说——**现在改是改字，做完再改是赔钱。**

## 文档末尾必须有验收单

```
## 怎么验收这一步
- [ ] 名词解释我真的看懂了，每个都能用自己的话复述
- [ ] 法规/平台规则那部分带查证日期和来源，查不到的明写了「需要验证」
- [ ] 钱的数字分了「一次性」和「每月」，免费额度写清了超了怎么收费
- [ ] 【致命项】「最贵的一个坑」我看了觉得后背发凉——
      如果看完毫无感觉，说明没挖到真东西，退回去重挖
```
