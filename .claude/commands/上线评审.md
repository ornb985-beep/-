# 一、先给一个判断：能上，还是不能上

**只有三种结论，不许含糊：**

| 结论 | 什么时候给 | 接下来 |
|---|---|---|
| **能上** | 三个人都没有致命反对 | 定上线日、进运营 |
| **再砍一轮** | MVP 还太大，或者第一个真人要等太久 | 砍完再来 |
| **别上** | 单位经济不成立，或者撑不到第一笔钱进来 | **说清楚是哪一条，别绕** |

**「别上」不是坏消息。** 在花钱之前知道，比花完了知道便宜一百倍。

# 二、三条硬门槛（一条不过就不许写"能上"）

```markdown
## 上线前三道闸

| 闸 | 谁判 | 过没过 | 依据 |
|---|---|---|---|
| **一单赚不赚钱**（含获客成本） | 商业专家 | ☐ | ____ |
| **撑得到第一笔钱进来** | 商业专家 | ☐ | ____ |
| **第一个真人 30 天内能用上** | MVP大师 | ☐ | ____ |
```

**这三条是硬的**，任何一条没过，"能上"就不许写。

# 三、他只需要定两个数

**其余全是我们的活。**

```markdown
## 需要你定两件事

### 1. 你打算投多少钱进去
　我建议 ____ 元（理由：____）
　这笔钱花完还没 ____，就该停

### 2. 止损线：到什么时候、什么没发生，就停
　我建议：到 ____ 月，如果 ____ 还没发生，停
　停的时候：彻底停 ／ 改方向 ／ 缩小重来

**这两个定完，剩下的我们接手。**
```

**止损线必须是「一个日期 ＋ 一个可数的事实」**，
不许写"感觉不行了就停"——**没有出口的止损线，人会一直答"还没到"。**

# 四、上线之后谁干什么（他不用管）

```markdown
## 上线后的班子

| 谁 | 干什么 | 多久一次 |
|---|---|---|
| CEO | 看数、裁决、管收支、写日报 | 每天 |
| 运营 | 跟进流程、处理异常 | 每天 |
| 客服 | 接用户问题、分类反馈 | 每天 |
| 数据 | 把数字变成能判断的结论 | 每周 |
| 增长 | 按营销大师那套执行，盯转化 | 每周 |
| 财务 | 记账、盯现金流、离止损线还有多远 | 每周 |

**他要做的只有一件事：看仪表盘。**
出现这几种情况我们才会叫他：
- 快到止损线了
- 钱要花完了
- 出现了需要他本人拍板的（对外承诺／花大钱／不可逆的）
```

# 五、拿什么标准判断做得好不好

**读 `references/判断标准.md`。** 那一份写死了：
标准是分层的、「最好的」vs「最适合我的」、怎么纠错。

这一步要把标准落成**可数的**，写进文档：

```markdown
## 怎么算做得好（分阶段，别一次全要）

| 阶段 | 这一阶段只看这个 | 达标线 | 【这一阶段不许看】 |
|---|---|---|---|
| 第一个月 | 有没有人真用 | __ 个真人用过 | 好不好看、赚多少 |
| 第二三月 | 有没有人真付钱 | __ 单 | 规模、自动化 |
| 之后 | 单位经济正不正 | 一单净赚 __ 元 | —— |

**「这一阶段不许看」那一栏最重要**——
拿"好不好看"去判断一个还没验证"有没有人要"的东西，是最贵的浪费。
```

# 六、做完之后怎么判断、怎么纠错

```markdown
## 每周问三句

1. 这周的数，比上周好还是差？（**数字，不是感觉**）
2. 如果差了，错在哪一层？
   　目标错了 ／ 标准错了 ／ 方法错了 ／ 执行错了
   　**改错层，越改越糟**——先归因，再动手
3. 有没有哪条标准该改了？（改了记一笔，没改也记一笔"看过，没改"）
```

**第 2 条的四层来自 `references/判断标准.md` 第四节，照那个归因。**
