读 `docs/00-目标.md`。

这一步的信条：**这世上大概率已经有人把这件事做得很好了。找到他，看懂他，然后从他停下的地方开始。**
从零开始想是最贵的做法。

产物：`docs/01-巨人的肩膀.md`。

**这一步必须大量使用 WebSearch，不许凭印象写。** 每条结论标注来源和查证日期。
凭训练记忆写出来的"业内普遍认为"，在这一步等于零分。

## 一、谁做得最好（找 5 个，不是 3 个）

不要只找最有名的，按这四类各找一到两个：
- **规模最大的那个**：它定义了行业标准做法
- **口碑最好的那个**：用户为什么爱它
- **最新冒出来的那个**：它凭什么后来居上，抓住了什么变化
- **一个隔壁行业的**：结构类似但不同领域的（这一条最容易挖到金子）
- **一个失败的**：做过但死了的，死因是什么

每个写：
```
### 名字
一句话它是什么
做得最好的一点：____（具体到能抄的程度，不要写"体验好"这种废话）
最烂的一点：____（这是你的机会）
用户真实评价里出现最多的抱怨：____（必须去查真实评价，不要编）
我们要偷的：____
我们要躲的：____
```

## 二、这个领域已经沉淀下来的"标准做法"是什么

列出这行里所有人都在做、被反复验证有效的做法。这些是**共性**，是入场券。
每条注明：为什么它成了标准（是真有效，还是只是路径依赖没人质疑过）。

**区分这两种很关键**：
- 真有效的 → 老实照做，别创新，创新了就是给自己挖坑
- 只是没人质疑的 → 这就是 `references/框架库.md` 里「蓝海 ERRC」的「剔除/减少」入口，是机会

## 三、已经造好的轮子（别重造）

**这一段直接决定项目省多少钱、少多少时间。** 分四类查：

1. **现成的产品/服务**：能直接买或订阅的，能替代我们自己做多少工作？
2. **现成的工具/技术**：开源的、免费的、有免费额度的
3. **现成的模板/素材**：设计模板、脚本模板、话术库、素材站
4. **现成的方法论**：见 `references/框架库.md`，哪几个框架适用于这个项目

每条写：叫什么、能替我们省掉什么、多少钱、有什么限制/坑。

写完给一句结论：**「这个项目里，X% 的工作可以用现成的东西解决，
只有 ____ 这部分必须我们自己做。」**
那个"必须自己做"的部分，就是你真正的产品。

## 四、这个领域的高手都在用什么思考框架

读 `references/框架库.md`，从里面挑出**最适合这个项目的 3–5 个**，
每个写清：为什么适合、在哪一步用、怎么用。
框架库里没有但这行特有的，去查，查到了补充进 `references/框架库.md`。

## 五、信息差在哪儿（重点，慢慢想）

按 `references/框架库.md` 第七节的四种信息差，逐个挖：

```
### 领域差
隔壁哪个行业早就解决了这个问题？他们怎么解决的？搬过来的障碍是什么？

### 时间差
最近 6–12 个月，这个领域出现了什么新工具/新平台/新规则？
谁还没反应过来？这个窗口大概还有多久？

### 认知差
有什么是数据公开、但大多数人理解错了的？

### 执行差
这行里"大家都说重要、但普遍做得很烂"的环节是哪个？为什么没人做好？
（如果答案是"因为很累"，那这就是最扎实的机会）
```

每种至少给一条具体的，给不出就写「这个方向没找到，查了____」——诚实比编强。

## 最后必须回答三个问题

1. **如果我们什么都不创新，纯粹把现有最好的做法抄一遍，做出来是什么样？**
   （这是你的**及格线**，也是差异化的起跳板）
2. **现有所有玩家共同的盲区是什么？**（所有人都没做、或都做得很差的那件事）
3. **我们最不该碰的是什么？**（前人踩过、验证过是死路的）

写完用大白话跟我说：
- 最值得抄的一个东西是什么
- 你找到的最大的一个信息差是什么，为什么它还没被人吃掉
- 有没有发现让你觉得「这事可能不值得做」？有就直说，**现在说比做完再说便宜一万倍**。
