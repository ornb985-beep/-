# 一、现在有什么（已完成，真跑过）

**文件**：`.claude/commands/听懂.md`（提示词）· `scripts/test-听懂.sh`（自测，测什么以它的输出为准）

```
用户说一段话
   ↓
拆解每一句 → 标轻重（★★★承重 / ★★有用 / ★现在不重要）
   ↓
承重的往下挖三层（字面要什么 → 为了什么 → 到底怕什么）
   ↓
推出真实痛点（必须能指回原话里的具体某句）
   ↓
问最多 3 个选择题 → 用户答 → 再听一遍（最多 3 轮）
   ↓
它自己写下「状态：听懂了」，才准往下走
```

**真机实测**（2026-08-13，测试句故意埋了三个坑）：

> 「我想弄个**小程序**，管我那些老客户，**老是**忘了谁该回访，最好**像微信那样**打开就能用」

| 埋的坑 | 它判成 | 它的理由 |
|---|---|---|
| 小程序 | ★ 不重要 | 形态是第8步的事，现在定死会跳过论证 |
| **老是**忘了 | ★★★ 承重 | 频次词后面藏着真痛点 |
| 像微信那样 | ★★★ 承重 | 那个参照物解决的问题才是重点 |

挖到第三层：「他怕做了个新工具但自己嫌麻烦不去用」——
**要的不是长得像微信，是"用起来零门槛"**。

## 待加 2 · 语言表达模式：幽默、让人喜爱、专业、真实

**目的**：现在的输出**准，但冷**。像一份结构清晰的分析报告。

老板要的是：**幽默的、让人非常喜爱的、专业真实的、最顶级的语言表达。**

**为什么这件事不是锦上添花**：这一步的产物是给用户看的**第一印象**。
准确但冷冰冰，用户会觉得"这是个工具"；
准确又让人会心一笑，用户会觉得"这东西懂我"。
**第一句话就决定了他要不要继续。**

## 待加 3 · 蒸馏一个人，模仿他的语言，作为最终输出层

**目的**：把待加 2 落地的方式——**不是描述风格，是蒸馏一个真人**。

**这套东西已经有蒸馏的机制**（`./loop.sh 蒸馏`，现在用来蒸馏行业专家），

**顺着风格编内容，是这件事最像模像样的一种编造。**

# 二之二、评分机制 —— 现在这版是临时的，之后要自己重做

**老板明确说过：这条很重要，之后一定要我们自己去完善。**

## 现在是怎么算的（第2步「论证」里）

```
可行性 = 已验证的承重条件数 ÷ 承重条件总数
```

每条只有四种状态：**已验证**（必须附来源和日期）／未验证／**已证伪**／待查。
只有「已验证」计入分子。任何一条已证伪 → 可行性直接归零。
≥90% 且零证伪 → 定论型目标；达不到 → 动态型。

## 为什么现在这么做

**为了先有一个"可数的"东西。** 让 AI 直接写「可行性 92%」是零成本的，
而且无法核对——**一个没拆开的百分比就是编出来的。**
先做成可数的，至少每一分都能翻回去看凭什么。

## 现在这版明显的毛病（老板要重做的就是这些）

| 毛病 | 具体是什么 |
|---|---|
| **每条权重一样** | "有没有牌照"和"获客成本大概多少"算一样重，显然不对 |
| **条数可以被凑** | 拆题时多列几条好查的，分母变大，分数就好看 |
| **90% 这个线是拍的** | 为什么是 90 不是 80、不是 95？现在没有依据 |
| **只算"查到没查到"，不算"查到的结果好不好"** | 一条查证了但结果很差，跟查证了结果很好，现在同样计 1 分 |
| **没有时间衰减** | 去年查证的数据和上周查证的，现在一样算数 |

## 之后要往哪个方向走（老板定，这里只记方向）

- [ ] **加权**：承重条件按"错了有多惨"分级，不是均权
- [ ] **防凑分**：条数上下限写死，或者由风控单独审一遍"这些条件是不是被稀释了"
- [ ] **分数要分两层**：一层是"查清楚了多少"，一层是"查清楚之后看起来怎么样"——
      **现在这两件事混在一个数里，是这版最大的问题**
- [ ] **那条线怎么定**：跑够多的项目之后，回头看多少分的项目真的做成了

**在重做之前，现在这个数只当"查清楚了多少"看，别当"这事有多靠谱"看。**
这一句要一直留着，直到评分机制重做完。

# 三、加的时候要守住的（别把已经跑通的搞坏）

**分析层和表达层必须分开。**

```
分析层（已跑通，别动）          表达层（待加）
拆解 / 分轻重 / 挖三层    →     怎么说得让人喜欢
推真痛点 / 出选择题             幽默、专业、真实
      ↑                              ↑
  错了 = 结论错                 错了 = 不好听
  这层不许为了好听让步           这层不许改结论
```

**为什么必须分开**：一旦混在一起，某天为了一句话说得漂亮，
会不自觉地把一个不确定的推断说得很笃定——
**那就是把猜测伪装成结论**，正是六条不许里的第 2 条。

**具体两条**：

1. **表达层不许动 `[事实] [推断] [猜测]` 这些标记**。
   说得再好听，猜的还是猜的
2. **表达层不许改 ★ 的评级**，也不许增删选择题

# 待加 1 · 接上了（2026-08-18）

**接的方式**：`.claude/commands/听懂.md` 里加了「第四样：读状态」一节，
产物里加了「零、你说这段话的时候」。原料是 `references/人性档案.md`
（公理 ＋ 信号翻译表），**压缩进提示词，不让它去读 references/**——
第1步那三条省钱硬规矩没破。

**接进去的时候钉了三条铁律**，因为"判断他是什么样的人"是 AI 最容易编、
而且编得最像的一件事：

1. **读「状态」，不读「人格」。** 状态会变，标签不会；
   标签一旦写下会传染后面每一步的分析，**所以标签比状态危险十倍**
2. **每句心理判断必须指回原话 ＋ 带标记。** 指不回具体某句话的就是编的
3. **状态只许改「怎么问」，不许改「判什么级」。**
   轻重和 `[事实]/[推断]/[猜测]` 一个都不许被状态读数改动

**为什么第 3 条最重要**：这是分析层和表达层之间那道墙。
**顺着情绪说话可以，顺着情绪改结论不行**——这条一破，
后面所有"更好听"的改动都会顺着这个口子把结论一起改了。

**留了个坑没填**：`人性档案.md` 的公理还在草稿区（支撑档案满 3 条才转正），
现在只有档案 001 一条。**公理的支撑还很薄，用的时候记着这件事。**
