# 一、现在有什么（已完成，真跑过）

**文件**：`.claude/commands/听懂.md`（提示词）· `scripts/test-听懂.sh`（10 项自测）

```
用户说一段话
   ↓
拆解每一句 → 标轻重（★★★承重 / ★★有用 / ★现在不重要）
   ↓
承重的往下挖三层（字面要什么 → 为了什么 → 到底怕什么）
   ↓
推出真实痛点（必须能指回原话里的具体某句）
   ↓
问最多 3 个选择题 → 用户答 → 再听一遍（最多 3 轮）
   ↓
它自己写下「状态：听懂了」，才准往下走
```

**真机实测**（2026-08-13，测试句故意埋了三个坑）：

> 「我想弄个**小程序**，管我那些老客户，**老是**忘了谁该回访，最好**像微信那样**打开就能用」

| 埋的坑 | 它判成 | 它的理由 |
|---|---|---|
| 小程序 | ★ 不重要 | 形态是第8步的事，现在定死会跳过论证 |
| **老是**忘了 | ★★★ 承重 | 频次词后面藏着真痛点 |
| 像微信那样 | ★★★ 承重 | 那个参照物解决的问题才是重点 |

挖到第三层：「他怕做了个新工具但自己嫌麻烦不去用」——
**要的不是长得像微信，是"用起来零门槛"**。

**两轮共 $0.62。**

# 二、要加的三样（老板亲自加，现在别动）

这三样都属于**「怎么说」**，不属于「分析得准不准」。
分析框架已经跑通了，接下来是让输出**像一个真正懂人的人在说话**。

## 待加 1 · 深度心理学 ＋ 对人的认知

**目的**：现在挖到第三层靠的是「五个为什么 + JTBD 三层」——
这是**通用方法**，能挖到"他怕不专业"这一层，但再往下就到顶了。

老板要加进去的是**他自己对人的理解**：人为什么这么说、
说这句话的时候他在回避什么、他嘴上的理由和真实动机差在哪。

**这部分只有老板能写**，因为它是他的认知，不是从书上抄的框架。

- [ ] 由老板提供
- [ ] 加进 `.claude/commands/听懂.md` 的「往下挖」那一节

## 待加 2 · 语言表达模式：幽默、让人喜爱、专业、真实

**目的**：现在的输出**准，但冷**。像一份结构清晰的分析报告。

老板要的是：**幽默的、让人非常喜爱的、专业真实的、最顶级的语言表达。**

**为什么这件事不是锦上添花**：这一步的产物是给用户看的**第一印象**。
准确但冷冰冰，用户会觉得"这是个工具"；
准确又让人会心一笑，用户会觉得"这东西懂我"。
**第一句话就决定了他要不要继续。**

- [ ] 由老板定义"什么算好的表达"（**给例子，不是给形容词**）
- [ ] 提取成一句话的标准，加进提示词

## 待加 3 · 蒸馏一个人，模仿他的语言，作为最终输出层

**目的**：把待加 2 落地的方式——**不是描述风格，是蒸馏一个真人**。

选定一个人 → 蒸馏他的语言方式 → 分析结果过一遍他的嘴 → 那才是最终输出。

**这套东西已经有蒸馏的机制**（`./loop.sh 蒸馏`，现在用来蒸馏行业专家），
可以直接复用，不用新造。

**一条诚实红线，跟专家蒸馏那条一样**：
它读不到那个人的全部作品，只有公开材料。
**顺着风格编内容，是这件事最像模像样的一种编造。**
所以蒸馏出来的那一层**只负责怎么说，不许改分析的结论**。

- [ ] 老板定：蒸馏谁
- [ ] 蒸馏出「表达层」智能体
- [ ] 接在分析之后：分析照旧 → 表达层重写一遍 → 输出

# 三、加的时候要守住的（别把已经跑通的搞坏）

**分析层和表达层必须分开。**

```
分析层（已跑通，别动）          表达层（待加）
拆解 / 分轻重 / 挖三层    →     怎么说得让人喜欢
推真痛点 / 出选择题             幽默、专业、真实
      ↑                              ↑
  错了 = 结论错                 错了 = 不好听
  这层不许为了好听让步           这层不许改结论
```

**为什么必须分开**：一旦混在一起，某天为了一句话说得漂亮，
会不自觉地把一个不确定的推断说得很笃定——
**那就是把猜测伪装成结论**，正是六条不许里的第 2 条。

**具体两条**：

1. **表达层不许动 `[事实] [推断] [猜测]` 这些标记**。
   说得再好听，猜的还是猜的
2. **表达层不许改 ★ 的评级**，也不许增删选择题

# 四、暂时不动的两件事（知道，但先不改）

听懂是第1步、目标是第2步，但文档还叫 `00-听到的.md` 和 `00-目标.md`。
按顺序本该是 `01-` `02-`……但那要改所有文档名，
而每个提示词里都写着旧名字，**牵一发动全身**。
**文件名不影响任何功能**，等真到了要整理的时候一起改。

**2. 「第几步」的编号现在是算出来的**

`scripts/lib.sh` 的 `stage_num()` 按 `STAGES` 数组的位置算，不再手写。
以后再插步骤，编号自动跟着变。

**这个改动本身就是被一个真 bug 逼出来的**：
`references/框架库.md` 里一直写着「第4步『要做什么』」，
可那时候「要做什么」早就是第5步了——**写错了半年没人发现，
因为没人会去核对编号。**
