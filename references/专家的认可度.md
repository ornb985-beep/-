# 什么样的人才算专家（认可度）

**这一份是唯一的真身。** `专家团.md` / `蒸馏.md` / `行业专家.md` 都指向这里，
不许各自再抄一遍——抄一遍就会有一天三处对不上，而你不知道哪个是真的。

---

## 一、认可度 ＝ 可核对的凭证，不是名气

**判断一个人算不算专家，只有一条：他凭什么被信，能不能核对。**

| 算 | 不算 |
|---|---|
| 出过书、参与过国家/行业标准、写过教材 | 粉丝多 |
| 有可查的战绩（公司、销量、融资、任职） | 自称"操盘过上亿" |
| 公开演讲、访谈、判决书、财报里能查到 | 二手转述、"业内都知道" |
| **失败的当事人**（有公开复盘） | 别人替他总结的失败 |

**没有凭证的一律不收。** 不是因为他不厉害，是因为**你没法核对，
而没法核对的东西一旦错了，你永远不知道错在哪。**

## 二、配比写死：A≥3　B≥3　C 0–2　失败方≥1

| | 至少几位 | 他给你什么 | 他给不了什么 |
|---|---|---|---|
| **A 体系**（写书的、国家标准、教材、行业规范） | **3，不许缺** | **知识骨架**：这行分几块、每块的标准做法、行业黑话 | 当下的具体打法 |
| **B 操盘**（有可核对战绩的一线） | 3 | 什么条件下会失效、真实的数字量级 | 体系（他只有他那条路） |
| **C 标杆**（乔布斯、马斯克这类跨行的） | 0–2 | **判断范式**——他怎么想事情 | **你这行的任何细节**（别问，问了就是编） |
| **失败方**（死掉的那批） | 1 | 怎么死的、死在哪一步 | —— |

### 为什么 A 类不许缺

**只按"有战绩"去找，会找回一堆网红。**
有故事没体系，而且他的成功高度依赖那个年代的红利——
**拿到手你没法用，因为你不知道哪部分是方法、哪部分是运气。**

A 类给的是**骨架**：这个行业由哪些环节构成、每个环节的标准做法是什么。
有骨架，B 类的故事才挂得上去。

**A 类是骨架，B 类是血肉，C 类是眼光。**
只有 B 类，你就只有一堆故事。

### 为什么必须有失败方

九个人告诉你怎么成，一个人告诉你怎么死。
**"怎么死的"比"怎么成的"可复用得多**——成功高度依赖时机，
失败的原因却反复出现。

## 三、诚实红线（这条最要紧）

**它读不到那些书的全文。** 它有的只是目录、摘要、书评、演讲、访谈。

所以每一位都必须标明**掌握到什么程度**：

```
读过全文 ／ 只有目录和摘要 ／ 只有二手转述 ／ 只有一次演讲
```

**顺着目录编内容，是这件事最像模像样的一种编造。**
一份读起来充实流畅、看不出哪句是编的专家意见，**是危险，不是专业**。

### 每次开口必须分层

```
【他说过的】 ——  有出处，能核对到原话
【据此推断】 ——  基于他的公开判断推的，逻辑写出来
【我的补充】 ——  他没说过，是我加的
```

**混在一起说，等于借他的嘴说你的话。** 借方法可以，借嘴不行。

---

## 四、还要问一句：他说那话的时候，条件是什么

一个专家的判断永远绑着他当时的条件——那年的平台规则、流量成本、
竞争格局。**条件变了，判断可能整个反过来。**

所以蒸馏一个人的时候，除了"他说过什么"，必须记：

```
他说这话是哪一年、在什么环境下：____
那时候成立的前提，现在还成立吗：____
如果不成立，他的结论要怎么改：____
```

**不问这一句，你请回来的是一个活在过去的顾问。**

## 五、用完可以封存，不用删

```
./loop.sh 封存 专家-X      换行业了，收起来
./loop.sh 起复 专家-X      需要了再叫回来
```

蒸馏出来的专家绑着具体行业。换项目的时候封存，
**别让上一个行业的专家在新项目里发言**——他会很自信地说错话。
