# 用户只做一件事

**这一份是产品定义，不是界面规范。**
后面每加一个功能，都回来对一遍这条——**对不上的，那个功能就是做错了。**

---

## 一、那句话

> **用户的全部工作量 ＝ 回答一个问题，或者做一个选择题。**
>
> 除此之外，他不用懂、不用想、不用做功课、不用查资料、不用学任何商业知识。

**注意「一个」。** 一次甩三个问题给他，那不是"回答一个问题"，那是**一张表格**。
表格会让人觉得"我得先都想清楚再答"——**于是他就不答了。**

而且顺序本身有信息：**第一题答完，第二题可能就不用问了。**

---

## 二、台前 vs 后台

```
┌──────────────────────────────────────────┐
│  他看见的                                 │
│                                          │
│  一句话结论                                │
│  一个问题 ／ 一道选择题                     │
│  （就这些）                                │
└──────────────────────────────────────────┘
        ▲ 只往上送结论，不往上送过程
┌──────────────────────────────────────────┐
│  他看不见的（全在后台）                     │
│                                          │
│  · 十个专家分头查证，一人一块不重叠          │
│  · 顶尖真实信息：市场量级、获客成本、竞品、   │
│    实现难度、牌照红线                       │
│  · 沉淀的知识库：框架库 / 判断标准 /         │
│    判断档案（跨项目活下来的判断力）           │
│  · 认可度筛选：写书的、定标准的、有战绩的、   │
│    死掉的那批                              │
│  · 承重条件核对、可行性算分、反方辩护        │
│  · 六条「不许」在代码里硬查                  │
└──────────────────────────────────────────┘
```

**所有商业知识都是我们的负担，不是他的。**

他不需要知道什么是 JTBD、什么是护城河、什么是单位经济、什么是 LTV/CAC。
**这些是我们干活用的工具，不是说给他听的话。**
用得上就用，用完把结论翻译成人话再端出去。

---

## 三、最难也最重要的一条：让他看见他自己

**这不是"帮他分析"，是"帮他看见"。**

| 我们要给他看的 | 为什么他自己看不见 |
|---|---|
| **他没说出口的** | 他默认了，默认的东西人不会说出口 |
| **他没看见的** | 他站在里面，看不见自己站在哪儿 |
| **他心里想的** | 他知道，但没找到词 |
| **他不知道也想不到的** | 这一格是我们存在的理由 |

最后那一格：**他知道的事我们查一遍，只是让他放心；
他不知道、也想不到、但会要命的那些——那才是他找我们的原因。**

**一份没有那一格的报告，等于把他已经知道的事，用更贵的方式重说了一遍。**

---

## 四、怎么说：幽默引导，站在他前面

**真话不好听。** 「你这个算术不成立」「你以为的痛点不是真痛点」——
这些必须说，但**说的方式决定他是接住还是防御**。

- **幽默的作用不是逗他笑，是让他能接住一句难听的真话**
- **站在他前面，让他自己走过来**——不推不拽。把事实摆到他面前，
  让结论自己长出来。**他自己得出的结论他会执行，你替他得出的他会怀疑**
- **贴合他的现实**：拿他自己的原话、他自己的数字说事，不拿通用道理说事

完整规矩见 `怎么说话.md`。

---

## 五、拿这条去验一个功能做得对不对

每加一个东西，问四句：

1. **他要做的是不是只有"答一个问题/做一道选择题"？**
   　要他"想清楚""整理一下""了解一下"——**不合格**
2. **有没有商业术语漏到台前？**
   　漏了一个词，就是把我们的活推给了他
3. **有没有让他看见他自己没看见的？**
   　全是他已经知道的，那我们只是个复读机
4. **他看完能不能立刻做一个决定？**
   　不能，就是没说清楚，**不管写得多专业**

## 六、已经落地的 / 还没落地的

**落地了：**

- 第1步「听懂」：一次只显示一个问题，答完给下一个
  （同一轮的问题在本地走完，不重复花钱）
- 论证：内部十个专家全查，**台前只给一页纸**
- 选择题必须带推荐项和理由；**事实题不许硬编推荐**
- 承重条件、可行性算分——都在后台，台前只出一个数和一句话

**还没落地（老板亲自加）：**

- ⬜ **蒸馏一个真人的语言方式**，做成最终输出层（机制已有：`./loop.sh 蒸馏`）
- ⬜ **深度心理学 / 对人的理解**——老板的认知，不是书上的框架
- ⬜ **顶级审美**——现在的输出是"准但冷"，还没到"让人喜欢"
- ⬜ **评分机制重做**（见 `第1步-路线图.md`，现在这版只是临时可数的）
