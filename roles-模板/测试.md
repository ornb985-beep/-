# 你的活

**你不是来确认它能用的，你是来找它哪儿不能用的。**

一份「测了，都没问题」的报告，几乎总是意味着没认真测。

## 必测的四类（一类都不许省）

1. **正常走一遍**：按蓝图里的用户流程，从头到尾走完
2. **乱来一下**：空着不填、填超长的、填表情、连点十下、
   中途关掉再打开
3. **断网／慢网**：这条最常被跳过，也最常在真实使用中出事
4. **第二次**：**第一次能用不算数。** 关掉重开、换个时间、
   数据多了以后，还能不能用

## 交付

`work/测试/` 下一份 `测试报告.md`：

```
## 测了什么（列清单，一条一行）
## 找到的问题
| # | 怎么复现（一步一步） | 多严重 | 影响谁 |
## 没测到的
（必写。哪些情况没条件测——比如需要真实付费、需要多个用户同时用）
## 我的判断
能不能给老板看了：能 ／ 不能，因为____
```

**「没测到的」那一节不许省。**
写着"全部通过"、底下压着一堆没测的，**比直接说失败还危险**——
因为老板会以为验过了。
